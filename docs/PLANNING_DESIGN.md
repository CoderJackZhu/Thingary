## 1. 定位与设计决定

物谱已经按低频方式记录账户余额。规划模块在这些盘点之上增加一个独立的「规划」入口：用实测储蓄代替拍脑袋，据此估算养老金、退休／FIRE（财务自由、提前退休）时间，以及近期大额支出对退休时间的影响。它不是记账功能：不记逐笔流水，不要求用户分类支出。

| 决定 | 原因与取舍 |
|---|---|
| 规划是独立模块，可在「功能模块」中开关，不进时间轴与全局搜索 | 它是推算与假设，不是已发生的记录；关闭只隐藏入口，不删除资料 |
| 记录月度收入，不记支出 | 收入每月到账、来源统一、容易记；支出分散，由收入与净资产变化推出 |
| 公积金提取不记录 | 提取是公积金账户到现金账户的内部转移，在净资产里自动抵消；推算提取额 = 缴存 − 公积金账户余额变化 |
| 储蓄 = 净资产变化 − 公积金账户余额变化（2026-10 由「− 缴存」修正） | 储蓄是现金与投资的增长；锁在公积金里的部分不算，但已经提取进现金的算现金（原口径把提取后花掉的公积金记成花了工资，使储蓄偏低）。没有计入的公积金账户时缴存不进净资产，不扣 |
| 不使用 4% 法则，用「未来缺口折现」 | 社保到法定年龄才开始发，提前退休要经历「先靠存款、后有养老金」两段；4% 来自美国股债组合，不适用现金为主的配置 |
| 规划输出是估算，不是事实 | 估算用浮点数计算，必须与整数分的已记录事实隔开并标注 |
| 近期大额支出读取心愿，不建目标表 | 沿用已取消攒钱模式的原则：不存「已划拨金额」，不再造一份进度 |

**不做**：逐笔记账、月度预算、支出与收入来源分类、独立的目标与划拨、交易流水、行情与持仓同步、银行券商接入、投资收益归因、蒙特卡洛与压力测试、买房与组合贷测算、年度持有成本、盘点里的「本期转入」字段、1996 年前视同缴费的过渡性养老金、税务桶。其中买房、持有成本与「本期转入」是推迟而非否决，有实际需求时另行设计；本设计的数据结构不阻碍它们日后加入。

借鉴 Wealthfolio 退休引擎的结构与算法思路（逐年账本、所需资金、FIRE／传统两种模式、敏感性矩阵），在物谱里自行实现，不复制其代码；其许可证为 AGPL-3.0，物谱为 GPL-3.0-or-later，不引入其源码。

## 3. 月度收入记录

每月一行，记录实际到账：

| 字段 | 约束 |
|---|---|
| 到账日期 | `YYYY-MM-DD` 本地自然日，必填；同一天可有多行（工资与奖金分开发放） |
| 税后到账 | 整数分，必填，允许 0（明确没有到账）；年终奖等并入到账当月 |
| 公积金缴存 | 整数分，必填，允许 0；个人与单位合计，随工资、单位、比例变化时按实际逐月记录，不建分段模型 |
| 备注 | 可空，最多 500 字 |

这是按月汇总的事实，不是流水，也不按来源分类。可补记从工作以来的历史。逐月编辑使用修订号，删除进入「最近删除」并可恢复，与其他资料一致；批量补录历史不是首版内容。未来预测取最近一行的公积金缴存额。

## 4. 储蓄分析

### 4.1 区间与可比性

储蓄按**相邻两次未删除的完整盘点**形成的区间计算，而不是假设每月盘点一次。区间可比须同时满足：

- 两端都是完整盘点，起点早于终点；
- 两端共同账户的「是否计入」没有变化（与现有盘点比较的账户范围判定一致）；
- 区间内至少有一条月度收入记录。

不满足时该区间不参与储蓄统计，并显示原因：「旧版不完整盘点」「账户范围变化」「收入未记录」。区间新增账户的起点按零处理，与盘点比较一致。

### 4.2 口径

设区间两端的金融净资产（计入账户资产 − 负债欠款）之差为 ΔNW；区间内（起点日期之后至终点日期，含终点）按到账日期汇总的税后到账为 I，公积金缴存为 H；区间月数 m = 区间天数 ÷ 30.4375。

- 储蓄 S = ΔNW − H
- 支出 E = I + H − ΔNW（即 I − S）
- 月储蓄 = S ÷ m；储蓄率 = S ÷ I（仅 I > 0 时计算）

储蓄、支出可以为负，不截断成零。余利宝与活期利息、公积金年度利息、投资账户的涨跌首版直接计入储蓄，界面注明；净资产变化不等于投资收益。区间内记录的月数少于区间整月数时，提示「可能有收入漏记」，仍计算但标注。

### 4.3 滚动统计与异常提示

以最新完整盘点为终点，向前取终点落在 12 个月内的可比区间：

- **常态储蓄**：各区间月储蓄的中位数（每个区间一票）；另给按区间月数加权的平均（ΣS ÷ Σm）。年终奖、大件支出会拉偏单个区间，规划使用中位数。可比区间少于 3 个时标注「样本少」。
- **异常提示**：某区间月储蓄与中位数之差超过 3 × max(|中位数|, 月均收入 × 10%) 时，提示为这次盘点补一条备注。区间少于 3 个不提示。
- **不计入常态**：用户可把一个区间标记为一次性变动，使其不进入中位数与平均，只作展示。标记是独立的事实，随盘点稳定 ID 引用，不改变盘点金额、备注与完整性，只更正标记不要求重新盘点。

### 4.4 三段式复盘

1. **现状**：净资产与对应盘点日期、距今天数；本区间的储蓄、支出、储蓄率。
2. **变化**：本区间月储蓄与常态中位数对比，一句话结论，例如「本期储蓄比常态少 40%」。
3. **原因**：该区间终点盘点的备注，区间内已知购入日期与实付价的物品，以及对应模块开启时的重要支出与周期付款，按日期列出。这些只用于解释，**不自动调整**储蓄数字，物品购入也不另行加回。

没有任何可比区间时显示空状态并说明需要什么（至少两次完整盘点与区间内的收入记录），不画零值。

## 5. 中国养老金估算

养老金计算器是独立纯函数：输入个人资料、地区参数与退休年龄，输出起领年龄、退休首月养老金，以及到退休时的个人账户与公积金余额。不处理 1996 年前视同缴费的过渡性养老金。

### 5.1 输入

个人资料（出生年月、性别与职工类型：男职工／女干部／女工人）、参保地、当前缴费基数、已缴月数、个人账户余额、个人养老金年缴额（0 表示未开户）、公积金余额及月缴存额（余额取自最近盘点中公积金类账户，月缴存取自最近一条收入记录）、边际税率、通胀与工资增长等假设。缺少必需项显示「需要补填」，不当零。

### 5.2 法定退休年龄

按国务院渐进式延迟办法：男职工自 1965 年 1 月出生起、女干部自 1970 年 1 月起，每 4 个月延 1 个月，分别至 63、58 岁；女工人自 1975 年 1 月起，每 2 个月延 1 个月，至 55 岁。延迟月数 = min(上限, ⌊m ÷ 步长⌋ + 1)，m 为出生月与起算月之差，m < 0 不延迟。可另设最多 ±3 年的弹性提前或延后。按月领取的最低缴费年限从 2030 年起每年加 6 个月，由 15 年升到 20 年，不满时提示。**以上数字实施前对照官方文件核对并记录来源与日期。**

### 5.3 基础养老金与个人账户养老金

基础养老金 = (W + W × k̄) ÷ 2 × N × 1%：W 为退休时上年度当地社平工资（今天的社平工资按工资增长假设外推），k̄ 为平均缴费指数（缴费基数 ÷ 当年社平，限定在 0.6 至 3），N 为累计缴费年限。个人账户养老金 = 退休时个人账户余额 ÷ 计发月数。账户余额 = 当前余额按记账利率增值，加每年 8% 的缴费基数按记账利率累积。计发月数按国发〔2005〕38 号附表；延迟退休会出现非整岁，官方修订表出台前按月线性插值，并在界面标明这是近似。

### 5.4 随退休年龄重算

退休起领年龄是法定年龄，**与是否提前辞职无关**；但提前辞职后缴费停止，累计缴费年限 N、个人账户余额和公积金余额都随辞职年龄 a 变小。因此基础养老金 P、个人账户养老金与可解锁金额 D 都是 a 的函数，计算器对每个候选 a 重算，而不是固定一个数。

### 5.5 个人养老金与公积金

- **个人养老金**：每年最多缴 12000 元，税前扣除；领取时单独按 3% 缴个税，到法定领取条件才能取。建模为锁定到起领年龄的资金池，缴存期按自设收益增长，到期余额 × 97% 并入可支配资产；另算「按你的边际税率，每年省多少税」。
- **公积金**：建模为锁定资金池，按公积金利率与缴存增长，缴存在辞职后停止；到法定退休年龄一次性可取并并入可支配资产。若长期按月提取，预测会偏高，提供可选的「每月提取额」，默认 0。

### 5.6 输出与参数表

输出：起领年龄（年＋月）、基础养老金、个人账户养老金、合计，名义值与折成今天的钱两套口径，替代率（养老金 ÷ 退休前工资），个人账户与公积金到起领年龄的余额。**养老金内部按名义计算，出口按通胀折现；后续账本全程用实际口径。**

地方社平工资、缴费基数上下限、记账利率、公积金利率是可编辑的地区参数表，先只填北京。每项带来源与生效日期；内置默认值随应用版本更新，用户修改的值优先并保留。默认值不写在本设计中，实施时对照官方文件取得。

## 6. 退休与 FIRE 估算

全部用实际口径（扣除通胀）。

**所需资产**（在年龄 a 辞职）：

F(a) = max_{k} Σ_{y=a}^{k} [E_y − I_y − P(a)·1(y ≥ R) − D(a)·1(y = R)] ÷ (1+r)^{y−a}

E 为年支出，I 为用户添加的收入，P(a) 为养老金年额，k 取遍 a 到 H（资产在任何一个月都不能为负，取前缀最大值；解锁额大于其后净支出时，解锁前的缺口不会被掩盖），R 为养老金起领年龄，D(a) 为公积金与个人养老金在 R 年的一次性解锁额，H 为规划终点（默认 90），r 为退休后实际收益率。收益率恒定时是闭式；以后引入变动收益再换成二分查找。辞职之后才发生的大额一次性支出（首付、换车、心愿）与月支出一样计入 F(a)，按发生月折现；辞职之前的已经从资产里扣掉。逐月推演、所需资金与市场路径共用同一份一次性支出和同一个退休后单月步进，成功判据也相同（必须真的开始了退休）。退休后某月付不起的大额支出留作欠款：资产为负、不增值、不清零，先由收入与解锁额偿还，期间记为资金耗尽。

缴费年限不足最低要求时（R05），退休账本不计月养老金，个人账户余额近似为一次性领回并入解锁额；养老金页仍按公式显示并提示。续缴、补缴与转入居民保险不建模。

**支出假设**：退休后月支出（今天的钱）由用户明确填写日常月预算；留空暂不估算退休时间。最近 12 个月推出的支出中位数只显示为历史参考，不能默认套用一次性消费。日常生活是第一个、必需的支出桶；医疗、住房、旅行等其他桶见 §6.1。

**起点资产**：当前可支配资产 = 最近完整盘点中计入账户的净资产 − 锁定资金（公积金类账户、个人养老金账户）。个人养老金账户的识别方式在阶段 2 确定。

**达成年限**：从起点逐月推演——每月加常态储蓄中位数（扣除个人养老金年缴额的月均部分）并按退休前实际收益率增长，第一个满足可支配资产 ≥ F(当时年龄) 的月份就是 FI 月份。计划类型由用户选择（§6.1）：FIRE（年龄 ≥ 期望年龄且资产够才开始退休）与传统（到期望年龄强制开始，看资产够不够）。无法在规划终点前达成时显示「不可达」，不给一个假日期。

**假设与默认值**：退休前、退休后实际收益率与通胀、工资增长由用户填写，界面标明「这是假设」。退休前收益率不从盘点推导：没有「本期转入」，余额变化无法区分利息与存入。以货基为主时扣除通胀后接近 0，年限主要取决于储蓄率。出厂预填值在实施时与用户确认，写入参数表，不在本设计中固化。

**应急金线**：逐月推演中可支配资产低于 6 个月支出时标出；它只是提示线，不作为目标存储，也不划拨。

**敏感性**：由「假设分析」里的两张 5×5 矩阵取代原来的月储蓄 × 收益率表（§6.1），每格都按该年龄重算 P(a)、D(a)。

### 6.1 对标 Wealthfolio 的扩展（2026-10）

借鉴 Wealthfolio 3.9 的退休规划结构（只借鉴布局、算法思路与文案结构；其许可为 AGPL-3.0，物谱自行实现，不复制代码）。

- **计划类型**：FIRE 与传统是**同一个引擎**，只有「何时开始退休」不同；FIRE 在年龄 ≥ 期望年龄且资产 ≥ 当月所需时开始，传统到期望年龄就开始（资金不足也开始，记为「强制」）。两者都记录 FI 月份。成功 = 必需支出全程有资金（缺口超过 max(1 元, 当月支出的 0.1%) 才算）、没有资金耗尽、FIRE 另需达成 FI。
- **存储**：个人资料 JSON 的 `retire` 段新增 `mode`、`target_age`（默认 50）、`volatility_hundredths`（默认 500）、`spend_items`、`income_items`（各最多 20 项，标识唯一）、`saving_phases`（最多 30 段，起始年龄月数严格递增，金额分可为负，|金额| ≤ 100 万元）、`gap_share_hundredths`（平均空窗比例，0–50%）、`life_events`；缺省字段读取为默认值，旧资料照常读。**写入新字段后，旧版应用因 `deny_unknown_fields` 读不了该资料**：回退到旧安装包前须先备份并知晓。无 schema 变化。
- **引擎分层**：`plan-ledger.ts`（逐月账本、所需资金、下滑曲线、Coast、覆盖与逐年行）、`plan-risk.ts`（市场路径、压力测试、矩阵、崩盘路径）、`plan-view.ts`（判词、进度、里程碑、轨迹与覆盖展示模型）；旧单预算引擎只留在 `tests/legacy-fire.ts` 作对照基准：单桶、无收入时两者的所需资产、FIRE 月份与传统盈亏必须一致。
- **收入与养老金**：国家养老金对每个辞职月龄重算（沿用 §5.4），不手填；用户收入项为 DB 型（月金额、起止、是否随通胀）；不引入 DC 基金型收入（个人账户、公积金、个人养老金已由养老金计算器覆盖）。
- **不引入**：提取税、账户占比、提前提取罚金、债券下滑曲线、年度投资费用（已含在实际收益率中）、通胀的随机性与它和收益的相关性。
- **压力测试**：收益率 −2 个百分点；通胀 +1.5 个百分点（名义收益与名义工资增长不变，实际收益、实际储蓄增长按比例下降）；支出 +10%；期望年龄提前 2 年（不早于现在起一年）；缴款 −25%；退休第一年实际收益 −30%。严重程度：出现资金耗尽或支出缺口、FIRE 由可达变为不可达、FI 推迟 ≥ 36 个月或缺口增加 ≥ 基准所需的 15% 为高；FI 推迟 ≥ 12 个月或缺口增加 ≥ 5% 为中；其余为低。
- **市场路径**：每年抽一次对数正态实际收益，中位数等于假设收益、年内按月摊开，固定种子（计划数值的 FNV 指纹）；`volatility = 0` 时与确定性推演逐点一致（测试覆盖）。
- **矩阵**：缴款（基准 ×0.6/0.8/1/1.2/1.4，取整到 100 元）× 实际收益率（−2…+2 个百分点，退休前后同移）；支出（×0.8…1.2）× 期望年龄（−3、−1、0、+2、+4 岁，夹在现在 +1 与终点 −1 之间）。
- **崩盘路径**：从退休当月起，基准、第 1 年 −30%、第 5 年 −30%、第 1 年 −25% 与第 5 年 −20%、前 10 年 0% 五条退休期收益序列，其余年份取假设收益；退休未发生或退休时没有资产则不可用。
- **收入不确定性**：不预测收入，改为让用户分段设储蓄（高收入期、空窗期、清闲期），并用压力测试与区间并排显示结论会摇摆多大；Coast 检查点回答「前期要存到多少，之后不依赖高收入」。空窗月份（储蓄为负的阶段、有收入阶段的平均空窗比例、选了路线时路线的比例）默认停缴：缴费年限、个人账户、公积金与缴费指数都只按实际缴费的份额计（`project()` 的 `idle`）；可勾选「空窗期也续缴」改为照常计缴。
- **离职之后**：存为 `retire.keep_paying_until_age`、`keep_paying_monthly_cents`、`keep_paying_base_cents`、`gap_keeps_paying`、`rent_cents`，缺省读为「没有」，旧资料照常读（无 schema 变化；写入后旧版应用读不了该资料）。「不再工作」与「停缴社保」分开：续缴到某年龄时，养老金按辞职之后继续缴费（按续缴基数、没有公积金）重算，每月续缴花费与房租作为必需支出（`Plan.spend_flows`）只在退休后的月份起作用；计划买房时，购房那个月起取消房租（不超过房租本身）。应急金与「一年后失业一年」按全部必需支出算（日常生活、房租、续缴社保、房贷），不只是日常生活预算；折算空窗比例的「空窗时每月花费」同理。医保保费请计入每月续缴花费；北京退休医保累计缴费年限与养老不同，官方规定未在此核对。
- **路线**：`retire.route_id`／`route_from_age`（预设路线定义在前端 `plan-routes.ts`，存的只是标识与年龄，参数随应用版本更新，用户不逐项维护）。`project()` 新增可选的缴费分段 `Employment`（从某月龄起的基数与公积金月缴存），平均缴费指数按月加权；路线的储蓄阶段与缴费分段在 `retirePlan`／`buildRetireCalc` 里从换路线的年龄起取代用户设置，各路线并排由 `routeCompare` 用同一构建函数只换路线得出。
- **大额计划（买房、买车、其他）**：存为 `retire.life_events`（最多 20 件，字段见 `plan_profile.rs::LifeEvent`；金额为整数分字符串、日期 `YYYY-MM`），在 `plan-events.ts` 拆成一次性支出（并入 `Plan.spends`）与持续月度收支流（`Plan.saving_flows` 退休前改每月储蓄、`Plan.spend_flows` 退休后加支出；固定名义的月供按通胀折现）。`plan0` 是不含任何计划的账本，逐件影响与「付不付得起首付」都相对它算；已计入的并入主账本。选择「每件拆成事件」而不是独立目标模块，是因为物谱不划拨资产：Wealthfolio 靠账户划拨比例（同一账户在各目标的占比合计 ≤ 100%）让目标共用资金，且攒钱目标的支出不会进入退休模拟，物谱改为让所有事件进同一条时间线。公积金贷款与提取暂不建模。
- 心愿的一次性支出、目标卡片与概览共用同一引擎，不存在两套结果。

## 7. 心愿接入（阶段 4）

读取「考虑中」且有预计价格的心愿，作为带日期的一次性支出进入逐月账本：

- 有计划日期：按该日期计入；计划日期已过且仍在考虑中：**不计入**，规划页列出「计划日期已过，未计入」，不自行猜日期；无计划日期：按今天计入并标注。
- 心愿详情增加一行只读信息：「按当前储蓄，计划日期时可支配资产约 X；买下后 FIRE 推迟约 N 个月」。N 以「其他考虑中心愿都不发生」为基线，只加入该心愿计算；规划页另给全部考虑中心愿同时发生的总推迟，并标出击穿应急金线的支出。
- 该行只在规划模块开启、所需输入完整时出现；它不改变心愿状态，也不代替「已买到，记录购入」确认。购入后盘点余额已反映该支出，心愿退出考虑中，自然不再计入。

不为此在心愿表单增加字段。

## 8. 数据、事务与兼容约束

以下是目标业务约束；物理表结构、命令名与迁移版本在实施时结合当前 schema 确定，不在设计阶段占用版本号。

| 能力 | 约束 |
|---|---|
| 月度收入 | 稳定 ID、修订号、请求回执；进入最近删除与恢复；纳入备份规范与恢复检查 |
| 常态标记 | 随盘点 ID 引用的独立事实；不改写盘点；盘点永久删除时一并清理 |
| 个人资料与参数覆盖 | 单行、严格字段校验（拒绝未知字段）、修订与回执；备份可恢复；不记录在日志中 |
| 区间储蓄读取 | 只读命令，与盘点在同一读事务内取数，响应携带资料库 generation，过期响应被拒；无写入副作用；可比判定复用现有盘点比较规则 |
| 规划计算 | 不碰数据库的纯函数，所有「今天」由调用方传入；年龄按日历月计算 |
| 模块开关 | 新增「规划」可开关模块，关闭只隐藏入口与心愿详情中的提示，不删除资料 |

金额输入与记录保持整数分。规划输出是估算，内部可用 f64，展示舍入并标「估算」，不得写回或冒充已记录事实；这是对「不用浮点累计金额」的有限例外。缺少必需输入显示「需要补填」，不填零；有默认值的假设项标注「这是假设」。

迁移是增量的，旧资料不改；新表纳入规范 schema 校验、备份检查摘要与恢复。新版备份不可交给旧版应用恢复。收入与个人资料属敏感信息：测试、预览与截图只用虚构资料，不接触正式资料库 `local.thingary.main`。

## 9. 验收标准

### 阶段 1：储蓄分析

- S01 区间可比：不完整盘点、账户范围变化、无收入记录的区间被跳过并显示对应原因，结果与盘点比较的可比判定一致。
- S02 口径：用已知数值核对 S、E、储蓄率；公积金缴存被扣除；公积金提取（内部转移）不影响结果；储蓄、支出为负时不截断。
- S03 间隔不等：1 个月与 3 个月的区间按月数折算后可比；月数用天数 ÷ 30.4375。
- S04 滚动统计：中位数与加权平均与手算一致；少于 3 个区间标「样本少」；标为不计入常态的区间被排除。
- S05 异常提示：阈值边界、中位数接近 0、无收入记录与少于 3 个区间各有测试。
- S06 收入漏记提示：记录月数少于区间整月数时提示，仍计算。
- S07 收入记录：新增、编辑、删除、恢复、同日多行、零金额、修订冲突与请求回执重试都正确；公积金缴存可为 0。
- S08 备份恢复：含新表的备份检查、恢复与旧备份兼容；高版本备份被旧版拒绝。
- S09 复盘三段式：现状、变化、原因按日期列出盘点备注、区间内物品购入、重要支出与周期付款；关闭模块后相应项隐藏；原因不改变数字。
- S10 空与错误：无盘点、仅一次盘点、读取失败、过期 generation 都有可辨认的状态，不画零。

### 阶段 2：养老金

- R01 退休年龄：三类职工的出生年月 → 期望退休年龄（年＋月）测试向量，含起算月前后边界，不依赖当前日期。
- R02 计发月数：整岁取表值，非整岁按月线性插值，并标注近似。
- R03 公式：基础养老金与个人账户养老金与手算一致，缴费指数限定在 0.6–3。
- R04 随 a 重算：辞职年龄越早，N、个人账户、公积金余额与 P、D 越小，并有测试。
- R05 最低缴费年限：不足时提示，不静默给出结果。
- R06 个人养老金：年缴上限、领取 3% 税、每年省税提示。
- R07 名义与实际：出口同时给名义值与今天的钱，折现与通胀假设一致。
- R08 参数表：可编辑、带来源与生效日期；缺项显示「需要补填」。
- R09 个人资料：严格字段校验、备份恢复；缺必需输入不当零。

### 阶段 3：退休／FIRE

- F01 所需资产 F(a)：与手算和逐月推演互相核对。
- F02 达成年限：FIRE 与传统两种模式；不可达显示「不可达」。
- F03 敏感性：两张 5×5 矩阵每格按各自 a 重算，网格结果单调合理，空与不可达格有表示。
- F04 起点资产：锁定资金（公积金、个人养老金）不计入当前可支配资产，到 R 年才解锁。
- F05 应急金线：击穿时标出，不阻止计算。
- F06 假设标注：所有假设项带「这是假设」；退休前收益率不由盘点推导。

### 阶段 4：心愿接入

- W01 只读：不改变心愿状态、购入关联与通知；规划未填完整时该行不显示。
- W02 日期规则：有日期、已过期未计入、无日期按今天并标注。
- W03 基线：单个心愿的推迟以其他心愿不发生为基线；规划页给总推迟。
- W04 购入后不再计入，不与盘点余额双计。

### 共用验证

界面覆盖当前三种风格的浅／深、800px 与正常桌面宽度，提供同尺寸前后对照；正常、空白、未知、加载、读取／保存失败均可辨认；键盘与中文输入单独验收。实施阶段运行 `npm run build`、`npm run test:ui`、`npm run check`、`npm test`，所有时间相关测试注入固定日期并在多个时区运行。浏览器预览加虚构夹具，不代替原生验收；未执行的路径如实标记未验。

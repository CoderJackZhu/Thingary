## 3. 第一批：V00–V05 的具体范围

以下列出已获准的首批范围，执行状态见开头表格。第一批只使用可丢弃的虚构资料与独立临时数据目录；不会建立用户的真实资产库。已有产品、竞品、UI 文档和原型需保留。

### V00 · 固定验证环境与数据契约

- 依赖：无。预计范围：ADR-001、验证报告、后续清单/配置约定（2–3 个文件）。
- 交付/验收：核对 SDK、工具版本与依赖兼容；确定本次仅在当前 Apple Silicon Mac 验证，记录最低打包目标、应用标识、临时数据根；给出统一字段长度、金额范围/小数策略及分页上限，区分空值与零。
- 验证：只读环境检查和当前官方资料核对；将实际版本、选择理由和未决项记录到 `docs/VERIFICATION_REPORT.md`（执行时创建）。当前旧版本观察记录不能直接充当重新验证结果。
- 边界：不为方便而升级全局工具或采用其他 Agent 的私有依赖环境；需要额外系统安装、身份凭据或改变已有配置时，说明具体需要再处理。图片限制在 V03 实测确定。

### V01 · 最小可打包桌面窗口

- 依赖：V00。预计范围：最小模板生成产物；手动修改仅构建/窗口配置、A 的基础外壳和说明。
- 交付/验收：创建并锁定 Tauri/React/TypeScript/Vite 的最小工程；能构建本机 App 并离线打开；窗口可关闭和再次唤起，⌘Q 完整退出，无项目自建常驻服务；不把 HTML 原型整个复制成产品代码。
- 验证：从干净构建产物启动，记录实际构建与开发命令、退出前后进程和打包目标；查看原生窗口、主题、焦点。对应 R01 的基础部分，尚非完整 AC39/40。
- 边界：无真实资产页、账号、更新器、远程配置或后台自动任务。依赖安装是项目级安装，不自动修改全局运行环境。

### V02 · 单条虚构资产的可靠提交

- 依赖：V01。预计范围：领域类型、单连接存储、最小业务命令、迁移、集成用例（约 5 个文件）。
- 交付/验收：最小资产输入通过命令持久化；重启后同一 ID 可读取；未知/零、包含首尾自然日、负净成本的纯计算样例正确；同 request_id 重试返回同一结果，不同内容冲突，旧 revision 不覆盖新数据。
- 验证：临时目录测试、事务前后失败点、提交成功后丢回执再重试；记录真实 SQLite 版本与事务配置。对应 R02，计算用虚构费用参数即可，不提前实现维护/售出页面。
- 边界：只建验证所需最小实体，不能为完整 P0 一次创建所有表。对未来关联的约束在对应业务任务继续增加迁移。

检查点 V-A（V00–V02 后）：工程能打包，单条保存可重复验证；若基础工具或提交正确性未通过，停在失败项处理，不继续铺页面。

### V03 · 图片提交中断实验

- 依赖：V02。预计范围：文件暂存、提交协调、附件最小迁移、故障用例、报告（约 5 个文件）。
- 交付/验收：一张虚构图片可托管并关联资产；移动原文件后仍可读；复制后、入库前、提交后中断均可判定恢复结果；重试不破坏共享或软删除引用。确定 JPEG/PNG/WebP/HEIC 的实际能力、单文件与解码上限及不支持文案。
- 验证：使用自行生成/公开许可的测试图片及可控故障注入；权限和空间失败用临时测试边界模拟，不填满用户磁盘或改用户文件权限。对应 R03 的底层协议验证。
- 边界：未通过 HEIC 等能力时保留缺口，不悄悄从 P0 目标删除；缓存生成可失败并重建，不能用缓存替代原图。

### V04 · 一致备份实验

- 依赖：V03。预计范围：备份协调器、manifest、快照与归档、集成用例、报告（约 5 个文件）。
- 交付/验收：临时库和原图形成可验证备份；等待已有提交并暂停新的写入，草稿不会被当成已保存数据；取消选择不创建任务；无权限或写入故障不生成伪成功文件。
- 验证：用非空数据库和附件同时触发编辑/备份请求，检查快照、引用与哈希；记录写入暂停时长和中途失败表现。对应 R05 前半段。
- 边界：不是完整备份功能交付；目前只有验证实体，未来维护/保障/心愿等必须在 T18 再做完整恢复验收。

### V05 · 隔离恢复与崩溃恢复实验

- 依赖：V04。预计范围：恢复协调器、数据集指针/日志、校验器、故障用例、报告（约 5 个文件）。
- 交付/验收：备份还原到新临时目录并切换；各个切换点终止后都能选择一套完整可读数据；损坏、缺附件、不兼容、路径异常及保护副本失败时不覆盖原数据；旧数据集请求不能写入新库。
- 验证：仅终止测试子进程，核对恢复前后 ID/状态/原图及目录；覆盖一次测试版本迁移失败，不把断进程实验宣称为完整断电耐久性证明。对应 R05 后半段。
- 边界：不使用真实数据演练，不自动清空旧数据集、不发布安装包。真实备份 UI 与所有实体覆盖仍由 T18 完成。

**CP0（第一批终点）：** 输出真实命令、版本锁、实验记录和失败清单；逐项说明 R01/R02/R03/R05 哪一部分已证实、哪一部分未证实。只在原型协议可行、临时数据不被损坏且剩余缺口有明确归属时，建议继续开发；不把第一批成功叫作 P0 成功。第一批授权不自动覆盖 T01–T21。

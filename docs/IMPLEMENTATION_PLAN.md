## 7. 模型成本、Codex / Hermes 与协作入口

### 7.1 默认执行方式

默认建议 **GPT-6 Sol 中档完成常规实现，GPT-6 Astra 按阶段风险审查；只把关键核心和难题交给 Astra High**。既可在 Codex 中直接选 Sol，也可由 Hermes 使用 Sol 作为唯一主负责人。更换执行工具本身不保证省费用；模型调用量、上下文、返工和付费方式共同决定成本。

第 4 节中“Sol 主导”表示规格已明确，可由 Sol 完成实现、相关测试、构建及必要原生验收；“混合”表示先由 Astra High 核对列出的关键规则，再由 Sol 按已审契约实现，最后审实际差异；“Astra High 主导核心”表示状态/恢复等关键代码由 Astra 完成或直接参与，普通表单与页面仍可交 Sol。不是整阶段每次读文件、运行命令、写报告都用 High。

M3 / GLM 可作为 Hermes 的可选单个辅助执行者：适合已有契约下的独立组件、明确样例的测试补充、资料核对和文档整理。先用一个有边界的小任务验证其实际质量，不凭模型名称假设 Rust、Tauri 或原生工具能力。不要让它们自行决定资金口径、schema 迁移、恢复协议，也不要把其自评“通过”当验收。GLM-5.3 与 GLM-5.3-Flash 必须区分，使用实际提供方可调用的精确模型 ID。

Hermes 官方支持为子代理配置不同模型；子代理主要依赖传入的目标与上下文，因此交接仍需明确文件、输入输出和验收，不能指望它知道整段历史。[官方委派说明](https://hermes-agent.nousresearch.com/docs/user-guide/features/delegation)。本项目不默认开 MoA，不为每一步同时咨询 Sol/M3/GLM/Astra，不自动递归拆解。

### 7.2 成本与升级规则

- 默认一个主执行者，不开子代理；确有独立小任务且本阶段已授权委派时，先限一个辅助执行者，禁止多个模型同时修改同一批文件。M3 与 GLM 是可替代候选，不要求每项任务都调用两者。

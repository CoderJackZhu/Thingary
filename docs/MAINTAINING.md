# 文档职责与维护方式

代码和正式文档在公开 Thingary 仓库维护。维护者的详细过程记录另存私有档案，外部贡献者不需要取得该档案即可构建、验证和贡献。

## 每份内容只维护一个当前版本

| 内容 | 唯一维护位置 |
|---|---|
| 产品用途、下载和阅读入口 | README |
| 安装、操作、备份、更新与常见问题 | USER_GUIDE；DMG 离线版由它生成 |
| 业务范围与计算／数据语义 | PRODUCT_RULES |
| 功能设计草案、分阶段规格与验收条件 | 私有维护者档案；实现时把现行行为写入 PRODUCT_RULES、ARCHITECTURE 与使用指南 |
| 架构、关键取舍与一致性约束 | ARCHITECTURE |
| 环境、命令、预览和验证方法 | DEVELOPMENT |
| 贡献规则与提交要求 | CONTRIBUTING；AGENTS 引用这些规则 |
| 版本迭代、冻结、验收、打包与发布放行 | RELEASING |
| 直接内置的第三方内容及许可告知 | SOURCE_NOTICES；锁定依赖由第三方清单与随包告知脚本维护 |
| 用户可感知的版本变化 | CHANGELOG 与对应 Release 说明 |
| 讨论草稿、执行流水、复盘、每版放行单及验收证据 | 私有过程记录，引用公开提交号与发布流程，不另维护通用规则 |

历史档案是固定快照，不再修改成第二套“最新规则”。历史结论与当前说明冲突时，核对代码和现行用户决定，修正当前说明，并在过程记录中解释原因。

设计获批不代表功能已经可用。公开文档只描述当前源码的行为与约束：功能实现时，把影响用户和贡献者的规则、口径和关键约束写入现行文档，不链接私有档案；设计理由中贡献者需要的部分同样写入公开文档。每阶段完成后记录已实现／已验／未验的边界，不能把自动检查写成原生验收。

## 后续开发与以前有什么不同

1. 开始任务，在公开仓库检查分支、HEAD 和工作树，读当前业务规则和开发说明。
2. 需要详细计划时写入私有笔记；影响社区协作的范围和设计理由在公开 issue／文档中表达。
3. 代码、测试和有效文档一起修改并提交到公开仓库。
4. 在私有笔记登记该公开提交的完整 SHA、验证环境、结果和未验证项，然后独立提交笔记。
5. 发布从公开标签构建；当前操作指南、许可和所需源码都应在公开提交中。

两仓库不互相 merge，不运行全量源码同步，不依赖私有文件才能构建。代码提交是事实锚点；私有笔记缺失不应阻止外部贡献者使用源码。

## 同步与一致性

跨仓库提交不是原子操作。先提交代码，再登记笔记；中断时根据代码 SHA 补记即可。未提交工作记录为“进行中”，不能引用一个还不存在的最终提交或写成已发布。

公开文档引用其他公开文档，不链接维护者私有地址或个人本机目录。私有笔记可链接公开提交和公开规则；无需复制规则全文。行为变化时，对照上表逐项判断需要更新的文件。

提交前检查相对链接、图片、锚点、公式样例、支持范围和版本一致性。版本、备份格式与数据库 schema 不混用；未验证的平台、无障碍或系统行为保持明确说明。

## 过程资料与公开历史

工作记录在独立的私有仓库中提交，目录与公开仓库并列，避免 `git add` 误带入。私有仓库也不保存真实资料、数据库、用户备份、令牌或签名私钥。

这次整理保留现有公开 Git 历史：从 main 移走的旧文档仍可在历史及旧标签中查看。私有归档保证今后的记录分开保存，不承诺撤回过去公开过的内容。

## 文档展示原则

README 先回答“做什么、怎么下载、如何开始”，构建与贡献说明通过链接展开。使用指南采用清楚的步骤、具体例子和对应图片；未知值、恢复替换与安装限制在操作附近解释。开发阶段编号、个人安装记录和执行流水不进入用户步骤。

贡献者需要的设计理由与已知缺陷应公开说明。原始讨论留在私有笔记，不代表可以把有效约束、关键风险或支持边界隐藏起来。

## 截图与发布说明同步

版本顺序、冻结后补验和裁剪统一见[版本迭代与放行](RELEASING.md#release-lifecycle)。业务规则与操作说明随实现更新；开发中保留受影响界面的同尺寸对照，主要缺陷修复后定稿发布截图和指南；随包内容完成检查后再制作最终包。

发布前对照实际应用更新 README 主图、当前功能介绍与使用指南的操作图，检查导航、按钮名称、版本、已发布／待实施状态。截图的来源、尺寸和复现路径统一维护在 [images/README](images/README.md)，旧图不可仅改文件名冒充新版。

只使用内存虚构预览或隔离资料库，不读取正式资料。截图保持真实界面，等待主题动画和页面切换结束，逐张检查焦点、裁切和弹窗；浏览器截图不作为原生能力已验的证据。

文档提交运行相对链接／锚点／图片检查，并用 `node scripts/offline-guide.mjs <临时输出目录>` 生成离线指南，核对图片和内部跳转。README、指南、规则、架构、开发说明、INDEX 与活跃设计的当前状态应一致。已发布标签和 DMG 保持不变；之后修订的在线文档随主分支更新，下一次新版本再打包，不能静默替换同版附件。

首页与帮助页共用 `site/index.html` 的顶部导航，GitHub 仓库入口位于使用指南与语言切换之间；窄屏保留可访问的图标入口。首页页脚同时提供源码链接。修改共用导航后检查桌面与窄屏，避免隐藏仓库入口或挤出语言切换。

## 修复与复现

### 1. 未知回执核对后仍显示旧图标和旧错误

复现：在分类编辑行保留未保存的名称，将图标由摄影改为音频；内存 IPC 先实际应用变更，再模拟响应丢失及回执查询不可用。页面正确锁定，但恢复查询并重新加载后，旧实现仍选中摄影，并保留“暂时无法确认操作结果”错误。见 [修复前记录](t06c/icon-recovery-before.json)。

修复：即时保存的图标直接来自父级已确认 snapshot，不再保存另一份 `draftIcon`；成功核对后清除编辑行旧错误，保留名称草稿。正常图标重试成功也清除旧错误。失败核对不解除锁定，不自动重放请求。

复测：模拟提交成功但丢失回执、核对失败、恢复核对、提交前失败、重试成功。核对后图标为音频，名称草稿保留，旧错误清除，只有一次写入；提交前失败不会提前更新图标。见 [可重复脚本](../../tests/t06c.browser.mjs) 和 [实际结果](t06c/browser-regression.json)。此部分是生产 React 组件加开发入口内存 IPC，**不冒充原生数据库故障验收**。

### 2. 详情缩略图样式压缩弹出大图

原生 HEIC 实测发现：`.detail-section .photo-image` 的后置规则把嵌套大图预览压到 105px 高。缩略图能显示，但预览未使用窗口可用高度。

修复：把 105px 规则限定到 `.detail-section .photo-tile .photo-image`，保留原有预览高度、A「静序」布局及色彩。浏览器实测大图高 488.398px，符合窗口高度的 60%（488.4px）；缩略图仍为 105px。重打包并重开后，原生大图也已视觉复核：[修复后原生预览](t06c/native-heic-after.png)。

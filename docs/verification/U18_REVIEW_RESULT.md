## 1. 必须修订的发现

### R1 · P1：分类溢出引发无限更新，整个应用区域空白

位置：`src/TaxonomyFields.tsx:317–327`。

`useLayoutEffect` 无依赖数组，每次提交都执行 `measure()`；溢出时 `planCategoryLayout` 返回新对象，`setVisible(plan)` 再次触发渲染，即使内容完全一样也不停循环。新建 ResizeObserver 也随每次提交重复发生。现有“纯函数稳定性”测试只验证输入输出值相等，无法覆盖组件状态更新环。

**独立复现：** 本轮 Vite 1438、Ego Lite TaskSpace 16，打开 `visual-preview.html?category-fixture=30`，1920px 宽从总览点「全部资产」，捕获 `Uncaught Error: Maximum update depth exceeded`，随后 `.cat-chip-row` 和应用主体均消失。诊断见 [category-crash.json](../ui/desktop-layout/review/category-crash.json)。没有改代码或注入替代实现。

**修订出口：** 只在实际测量结果改变时更新布局，稳定 effect/observer 生命周期；用真实 React/DOM 场景覆盖溢出首次进入、切状态页、改变尺寸与选择隐藏项，断言无 error/空白/重复更新。修复后重新完成分类全部交互和视觉验收。

### R2 · P2：周期「计划／付款记录」仍只有 26px，文字横向叠画

位置：`src/wealth.css:38–39`，覆盖它的是 `src/app-layout.css:11`。

新增 `.recurring-tabs button {width:auto}` 与后加载的 `.segmented button {width:26px}` 优先级相同；后者仍胜出。`nowrap` 仅将逐字竖排变成水平溢出，未解决按钮尺寸。

**独立复现：** 800×600 的周期费用页，两个按钮 bounding width 都是 26，内容 scrollWidth 分别为 50、76，computed width 都是 `26px`。见 [测量 JSON](../ui/desktop-layout/review/recurring-tabs.json) 与 [截图](../ui/desktop-layout/review/recurring-tabs-800x600.png)。作者 `after/recurring-payments-800x600-B-light.png` 也可见同一遮叠。

**修订出口：** 正确限定图标分段与文本分段的宽度作用域/层叠，实际验证两个按钮的可点击区域互不重叠且完整包住文字，三尺寸六组合复查。不能再仅用文字是否换行判断修复。

### R3 · P2：长分类选中后未检查容纳能力，仍可能把更多按钮推出容器

位置：`src/category-layout.ts:20–37`，渲染关联 `src/TaxonomyFields.tsx:370–379`。

compact 只检查全部/未分类/更多三个固定按钮；选中项比剩余预算宽时，函数仍返回 `compact:false, selectedPinned:true`，渲染无换行长按钮，未按设计收敛为选择器。独立调用：容器 300，固定宽 70/60/90，选中项宽 160，间距 6，返回非 compact，但实际四项需 398px。此问题即使 R1 修复仍存在。

同时预算始终预留更多按钮，未先判定“不显示更多时能否全部放下”：容器250，固定70/60/90，唯一分类80（实际合计222），却返回 `visibleIds:[],showMore:true`。修订时一起补精确边界，避免无必要收起。

**修订出口：** 全部可容纳优先直接展示；隐藏选中项加固定项无法完整容纳时转 compact；为首/尾/超长选中、空分类、恰好容纳和字体变化后的实际宽度补测试及 UI 实证。

### R4 · P2：时间轴入口迁移时丢失模块开关条件

位置：`src/main.tsx:888`。

原入口受 `modules.timeline` 控制；新底部入口无条件渲染，而 `:165–171` 仍会在模块关闭时把 timeline 导航退回总览。结果是关闭模块后侧栏仍显示入口，点击后又被退回，不符合既有关闭规则及 AC07。作者报告声称仍由该开关门控，与当前源码不符。

**证据边界：** 这是 diff/调用逻辑确认的缺陷。本轮尝试浏览器关闭开关，预览明确报「此操作需在原生 App 验证：modules_set」，没有将该尝试写成原生或端到端通过。

**修订出口：** 恢复同一开关门控，实测开/关及当前页被关闭后的回退；模块设置里的页面名称同步为物品统计（不要全局替换业务术语）。

### R5 · P2：设置子页只通过 Esc 按来源返回，鼠标返回与上下文不完整

位置：`src/main.tsx:525–541`、`:545–554`、`:889`。

`backFromSubpage` 只由 keydown 调用，未提供点击返回来源的按钮。唯一面包屑点击只 `setSection('settings')`，不走滚动/焦点恢复；从物品/心愿“前往最近删除”进入后，鼠标无法按约定回实际来源。`openSubpage` 又清除 detailId，返回状态只保存 section，未保存原详情 ID；保存的焦点是即将卸载的 DOM 元素，设置重新挂载后不再是原节点。

**独立补测：** 设置外观→素材库的入口和面包屑存在，Esc 能返回设置外观，确认这条基础路径可用；但源码及页面按钮清单中没有来源返回按钮。该局部通过不等于 AC08 全部通过。

**修订出口：** 增加鼠标可见返回动作并共用返回逻辑；分别处理“回实际来源”和“面包屑回设置”；恢复来源详情/分组/滚动和稳定标识的入口焦点，验证删除引导进入最近删除后返回。普通表单关闭语义保持不变。

### R6 · P2：分类错误/重试仅声明 props，实际调用未接线

位置：`src/main.tsx:949`、`src/TaxonomyFields.tsx:245–246`。

CategoryFilter 调用只传 entries/value/onChange/disabled，未传 `taxonomy.loadError` 和 reload。首次读取失败时无 snapshot，所有入口禁用；用户在物品页既看不到原因，也没有原地重试。仅设置页处理不符合已经明确的 UI §4.2/AC12，不能把这项再当成未决定的可选范围。

**修订出口：** 正确接入错误与重试，初次失败且无分类时也有可达入口；不要让全局 disabled 同时禁用恢复动作。验证首次失败、保留旧 snapshot 后失败、重试成功及切库后不残留旧选项。

### R7 · P1：视觉“通过”证据包含 21 张空白图，U18e 完成声明不成立

位置：`docs/verification/U18_DESKTOP_LAYOUT_RESULT.md` §7–9、`docs/ui/desktop-layout/index.html`、实施计划 U18e。

实际打开标准 1280×820 和800×600 的分类 after，均只剩底部“界面验收”标识。对全部 after 做像素检查：去除底部25px，**21张整块只有单一颜色**，包括18张标准分类矩阵以及2张菜单展开、1张compact。清单见 [blank-screenshots.txt](../ui/desktop-layout/review/blank-screenshots.txt)。另两张较早的分类截图有内容，不能替代最终标准矩阵，也不能证明当前代码无 R1。

因此“72张齐全/链接全通”只证明文件存在，不证明页面有效；AC04/05/06/10及相关分类交互需重验。周期截图仍显示 R2，也不能保留 AC03 无条件通过。原生行为尚未执行以及返回/键盘缺口也不满足 U18e 出口。作者 AC05 的表格“通过”和摘要“部分”互相矛盾。

**修订出口：** 修复后重新抓取并实际审看 affected after，截图前检查目标页面/关键控件出现且无渲染异常。保留历史证据和修正说明，不以数量/链接检查取代视觉审核；补 before 缺失组合或逐项注明缺口，不冒称18组合完整前后对照。为最终源码记录可验证指纹并绑定截图/构建；不可把临时换文件后的 diff 行数一致当作内容一致证明。

## 改动和结论

实际生产组件已调整：`src/main.tsx` 的侧栏、工具栏、概览、列表/网格和右摘要；`AssetViews.tsx` 的持有成本与详情；`AssetEditor.tsx` 的分组和渐进展开。图片仍由原有 `Photos.tsx` 读取，删除/恢复仍调用原有流程。`app-layout.css` 为页面布局层，颜色沿用原有主题变量。没有更改 Rust、schema、IPC 保存契约或依赖。

这些页面已经有浏览器截图和操作证据。没有因此宣布原生 Mac 视觉、完整 T06 或 P0 通过；本轮未重打原生 App，也未再次运行 Rust 实验。已安装的旧 App 不会因该分支提交自动更新。

## 和原型的具体对应

| 页面 | 本次落地 |
|---|---|
| 浏览 | 克制侧栏与细线图标；搜索和新增固定在顶部；概览/筛选分组；密度一致的列表与网格；右侧大封面、成本、资料及动作 |
| 新增/编辑 | 540 px 模态框；名称/金额/日期优先；图片分组；更多资料渐进展开；校验能展开隐藏字段并聚焦 |
| 详情 | 封面与身份区；物品资料、备注、图片和持有成本分区；技术档案信息折叠；删除保持可恢复 |

原型里的维护、退役、售出、心愿、全部资产统计和分类数据尚未实现，不能复制为假数据。当前概览明确使用“本页”口径：7 条基准样例，6 条金额已知，合计 ¥35,487.00；2 条金额或日期待补充。零元样例计为已知金额。相机没有原型维护费，实际组件按本机日期计算，因此此日显示 1,201 天、¥8.15/天，不是原型固定日期下的 ¥8.50。

## 浏览器验证

入口 `visual-preview.html` 直接导入生产 `main.tsx`，通过开发专用内存 IPC adapter 提供虚构记录与原型原创插图。原生图片选择明确提示需在 App 验证。样例刷新重置、不访问真实资料库。默认生产 Vite 入口仍是 `index.html`，没有修改打包配置。

| 检查 | 本轮证据 |
|---|---|
| 列表/摘要与详情 | 单击相机显示摘要，打开完整档案显示原记录和图片；正常/缺少图片的两种呈现已查看 |
| 名称最小新增 | 只填名称成功进入详情，金额/日期/日均仍待补充 |
| 折叠字段校验 | 品牌输入 201 字后收起“更多资料”，保存自动展开，焦点为 `field-brand`，显示 200 字限制 |
| 取消和零元 | 修改后取消显示放弃确认，继续编辑保留输入；金额 0 保存显示 ¥0.00，日期未知时日均待补充 |
| 返回与查询 | 搜索 Fujifilm 后打开详情再返回，搜索内容和相机选中保留；清除条件回到全部结果 |
| 删除恢复 UI | 虚构相机移入最近删除再恢复，重新进入同一档案，金额/日期/备注/图片保留。此处只验证组件流程，不验证 SQLite 持久化 |
| 首次使用 | `?state=empty` 显示“从第一件物品开始”和新增入口 |
| 加载失败 | `?state=error` 显示失败原因和重试，新建入口禁用 |
| 保存失败 | `?state=save-error` 显示失败信息，原输入“虚构失败保留”仍在，允许修改/重试 |
| 深色、窄窗口 | 900×720 深色网格为两列，右摘要保留，DOM 无横向溢出；800×600 详情无横向溢出，编辑框 540×550，可滚动访问展开字段和操作 |
| 构建 | `npm run build` 通过，TypeScript 与正式前端构建成功；确认开发 fixture 未进入正式产物 |
| 已有纯逻辑测试 | `npm run test:ui` 14/14 通过；这些不是原生 UI 自动化 |

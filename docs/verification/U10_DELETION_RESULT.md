# U10 删除与恢复统一规则：验证记录

## 1. 交付

| 规则 | 实现 |
|---|---|
| D17-2/3 附属一起隐藏 | 关联到已删除物品的支出及其退款退出时间轴与支出统计；物品删除后时间轴保留“心愿已实现”，只隐藏该物品的购入 |
| D17-3 心愿删除 | 资料库升级到 schema 18（心愿加删除标记）；已删心愿退出心愿清单、预计总额、总览计数、时间轴、系统提醒，也不能编辑、攒钱、转资产；资产详情不再显示已删心愿作为来源 |
| D17-4 恢复即撤回 | 心愿经统一的删除/恢复命令恢复；物品恢复带回附属记录（原有行为） |
| D17-5 一个最近删除 | 新增“心愿”筛选；每行注明带走内容（维护、保障、关联支出、图片、付款、账户余额数）；逐条“永久删除”与“清空最近删除”均二次确认；永久删除同时清除只为它存在的记录、审计与回执，提交后删除不再被引用的图片原件与缩略图；不自动清空 |
| D17-6 即时撤销 | 删除物品、维护、保障、心愿、盘点、账户、支出、计划、付款后底部出现 10 秒“撤销”条 |
| D17-1 删除含义 | 删除物品确认框说明“不用、送人、丢失请用退役，卖掉用售出” |
| D18 入口划分 | 完整档案去掉“删除物品”，状态按钮改为“退役 / 重新启用 / 售出”；维护、保障的删除移入各自表单；“撤销误记售出”移入售出修改表单（可“返回修改”）；时间轴“更正”表单新增“撤销误记”，只作用于最近一条且无有效售出时 |
| D14 统一样例 | 新增一条已删除的虚构心愿，展示最近删除中的心愿（仅新建或重置的样例含此项） |

**自行决定的一处边界：** 由心愿实现的物品在该心愿仍存在（含在最近删除中）时不能永久删除，提示先永久删除心愿；清空时先删心愿再删物品。原因是“已实现”心愿必须对应物品，否则下次打开会自动补建一件。

**永久删除的图片保护：** 同一张原图若仍被其他物品、心愿或素材引用则保留；一天内新选入但尚未保存的图片也保留，避免打开中的表单丢图。

## 4. 原生验收（隔离身份）

专用身份 `local.possio.u10.acceptance`（`.local/u10.conf.json`，调试构建），首次启动进入统一样例，全部为虚构资料。只用辅助功能对目标应用按钮执行按下动作并截取该窗口，未向其他应用注入键盘；用户切到其他应用时暂停，待用户确认后继续。

| 支出删除与撤销 | 编辑支出“删除”后净支出 ¥22,040 → ¥18,440 并出现撤销条（截图）；撤销后回到 ¥22,040，连续 4 次成功 |

**首次支出撤销“失败”的原因（已查明，非应用缺陷）：** 撤销条按设计 10 秒后消失；那次删除与按下之间隔了一轮操作，超过 10 秒，撤销条已不在。验收脚本按名称匹配“撤销”，此时唯一匹配的是菜单栏“编辑 › 撤销”（文本编辑用），按下它不会恢复记录，所以支出留在最近删除。复现：删除后等 11 秒，名称匹配只剩菜单项，按下后支出仍在最近删除；撤销条可见时则有两个匹配，按钮在前，撤销成功。数据始终留在最近删除，可手动恢复。

## 5. ⌘Z 撤销删除（发版后追加）

撤销条显示期间按 ⌘Z 撤销删除。页面自己监听 ⌘Z 在原生 WebKit 中收不到（菜单先处理，与 T20 结论一致），因此把编辑菜单的“撤销 ⌘Z”改为原生菜单项转给页面：焦点在输入框时执行文字撤销，撤销条显示且无打开的表单时撤销删除，其余不动作。隔离原生验证：删除支出后按 ⌘Z，净支出 ¥18,440 → ¥22,040 并显示“已撤销删除。”；搜索框输入 abc 后 ⌘Z 清空、⇧⌘Z 恢复 abc。按键前均确认测试 App 在前台，正式 App 未运行。UI 逻辑测试 100 项通过。

## 6. 未验边界

- 维护、保障、售出撤销入口在浏览器预览走通，未在原生再操作；财富页盘点、账户、周期计划与付款的撤销条未逐一原生操作（共用同一删除按钮，支出路径已验证）。
- 浏览器预览不含心愿清单与时间轴，这两部分以原生结果为准。
- 撤销条是便捷入口：撤销请求的回执丢失时只提示去最近删除核对，不单独保存待核对请求。
- 已安装的 1.5.1 样例不会补入新的已删心愿，重置样例后才有。

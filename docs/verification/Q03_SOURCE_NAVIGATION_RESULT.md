## 交付

- **稳定来源与事件（Q03a）**：`source.rs::Target`（asset/wish/snapshot/expense/payment/virtual/plan）与 `validate_source`（generation、有效 ID、软删除、付款计划关系与 paid 状态、支出关联物品）；`timeline.rs` 事件投影为每条事件附 `target`/`domain`，`timeline_view` 提供领域（全部/实物/心愿/财富盘点/支出）× 年份 × 事件类型筛选，年份选项跟随领域与类型、不随当前选择消失；每份有效盘点按盘点日投影一次（完整显示净资产、不完整显示缺 N 个账户）。`review_overview.recent` 改用同一含盘点投影，同一批移除 ReviewView 前端盘点合并，无双份。
- **导航与返回（Q03b）**：`source.ts`/`useSource.ts` 重写为可测编排 `openSourceRequest`——先按当前资料库校验，再解析；请求被取代或离页（alive 失效）时不发布任何状态。App 维护 returnContext（页面、资料库身份、滚动、综合年份、时间轴筛选）；返回仅在同一资料库内恢复，滚动在目标页数据渲染完成后恢复，不被加载占位截断。综合页模块跳转传递年份（支出页 initialYear、时间轴 year）。
- **来源页面接入（Q03c）**：五领域页面 + 心愿按稳定 ID 打开：支出/心愿按 ID 重读；周期/虚拟/财富解析器先重读 overview/summary 再定位（同 generation 更正可见），付款精确到期次（更正付款记录带原记录），盘点以 expectedId 保护打开（同日新建/替换不误当原记录），用户主动改日期即解除保护。未决提交回执优先：pending/busy 时解析器抛「请先核对上次保存结果」而非打开编辑器。离开目标页未消费的 focus 被丢弃，刷新不重复弹窗，同一 ID 再次打开由新 token 区分。
- **综合与时间轴整合（Q03d）**：`SourceTimelinePage` 替换旧 `TimelinePage`（双入口删除）；ReviewView 待关注改为每含义一个精确入口（合组保留「进入计划／打开虚拟档案」双 target），近期记录每条带「查看来源」；实物概览最近事件同样按 target 打开（心愿不再按名称搜索）。失效来源提示并刷新，不误开同名记录。
- **预览适配（Q03e）**：`visual-preview.ts`/`wealth-preview.ts` 增加 `timeline_view`、`validate_source`、心愿列表/读取与虚构心愿（含同名对）、`?source=missing` 失效样例；不另建业务统计。

## 审阅修正（2026-09-28，Claude 审阅后按用户同意修复）

- 物品来源原先在 App 内先 await `validate_source` 再切页，绕过了 useSource 的 alive 保护：①离页后晚返回的校验会把页面拽到物品详情；②等待期间 returnContext 被原页面立即消费，返回后滚动丢失。预览 IPC 瞬时返回掩盖了这两点。改为与其他来源一致的同步切页，由 `read_asset` 自带请求序号丢弃晚响应，并以“找不到／已移入最近删除”说明失效来源。
- 从时间轴打开支出时，列表年份改为该支出自身年份，不再沿用综合页年份。
- 来源失效只在目标页提示一次（去掉 App 顶部重复提示）。
- 时间轴刷新不再先清空内容，App 数据刷新时不闪加载态、不丢滚动。
- 验证：`npm run build`、`npm run check`、`npm run test:ui` 122 项、`git diff --check` 通过；浏览器预览为 `validate_source`/`read_asset`/`expense` 注入 300ms 延迟后实测：物品来源加载中切到时间轴仍停在时间轴；物品来源往返滚动 500→500；综合页年份 2025 时从时间轴打开 2026 支出，列表落在 2026；`?source=missing` 只出现一条提示且不开编辑器。这些修正无新增自动测试（逻辑为删除分支，由上述浏览器实测覆盖），原生验证仍归 Q04。
- zcode 只读复核发现：从物品详情「查看原心愿」留下的名称筛选（wishFocus）不会被心愿来源清除，来源打开的详情背后列表仍按旧名称过滤。`openSource` 打开心愿时清除它。预览样例没有“来自心愿”的物品，无法复现原路径；已确认心愿来源仍按 ID 打开，列表搜索为空、状态为全部。
- 「付款待确认」的「进入计划」打开计划编辑表单，用户确认保持现状。

# U11 物品批量操作：验证记录

日期：2026-09-28 · 分支 `claude/batch-u11a`，起点 `ec6dacb`。规则见 [D19](../PRODUCT_DESIGN.md#d19--物品批量操作2026-09-28-用户确认随-170-发布)，界面对照见 `docs/ui/batch/`。用户授权自动完成开发、验收、合并、发版与安装。全部验证只用临时虚构库、浏览器内存预览与隔离身份，正式资料库未打开。

## 1. 交付

| 步骤 | 实现 |
|---|---|
| U11a 选择 | ⌘ 点击加选/取消（从摘要中的物品起算）、⇧ 点击连选、工具栏“选择/完成选择”与行前勾选框、Esc 取消；⌘A 选中当前筛选的**全部结果**（后端返回全部匹配 id，不限当前页）。⌘A 与 ⌘Z 一样改为原生菜单项转给页面：输入框内仍是全选文字。更改筛选/搜索或离开列表即清空选择 |
| U11a 批量面板 | 选中两件及以上（或选择模式下一件）时替换摘要栏：已选数量、状态构成、购入合计（未知金额单列不按 0）、操作按钮 |
| U11a 批量表 | 分类与渠道、状态标签、退役/重新启用（全部已退役时切换）、统计口径、删除确认；每行默认保持不变，“全部设为”填满整列，改动处标“将更改”，不适用行灰显说明 |
| U11b 批量表 | 添加保障：默认从购入日期起一年（未知时今天起），表头统一类型与年限，实时状态预览与进度条；售出：售价逐件必填（可为 0）、日期与渠道可统一、净成本预览，已售出行灰显 |
| 后端 | `batch_change` 一次事务按单件规则（退役复用同一 `append_event`，售出复用同样日期检查）写入全部行，出错时整批不保存并指出物品；回执保存每件原值，`batch_undo` 整批撤回并跳过之后被改过的物品；批量售出/保障照常写审计与回执，备份校验通过 |
| 撤销 | 每次批量保存后出现撤销条（⌘Z 同样可用），撤回整批并说明跳过件数 |

## 4. 隔离原生验收

身份 `local.possio.u11.acceptance`（`.local/u11.conf.json`，调试构建），首次启动为统一样例（9 件）。只对该应用按钮执行辅助功能按下并截取其窗口；每次键盘输入前确认它在前台，正式 App 未运行。

| 场景 | 结果与证据 |
|---|---|
| 选择模式选 2 件 | 面板“已选 2 件 · 使用中 2 · 购入合计 ¥26,789.00”，含全部 7 个操作；[截图](u11/u11-01-panel.jpg) |
| 批量退役与 ⌘Z | 2 件退役后“使用中 5 · 已退役 3”；再加选 1 件时已退役两行显示“已退役 · 不适用”，保存 1 项后立即 ⌘Z 显示“已撤销 1 件”；[截图](u11/u11-02-retire.jpg) |
| Esc 与 ⌘A | Esc 清空选择；⌘A 选中全部 9 件 |
| 批量添加保障 | 9 件按购入日期起一年默认，购入日期未知的“随身录音设备”从今天起；预览显示保障中/已过期；保存 9 项后撤销条撤回“已撤销 9 件”；[截图](u11/u11-03-warranty.jpg) |

**⌘Z 的一次未生效：** 第一次保存与按键分在两轮操作，间隔超过撤销条的 10 秒，按设计不再撤销（与 U10 相同的测试时序原因）；同一轮内保存后立即按 ⌘Z 生效。

## 5. 未验边界

- 原生未操作的表：分类、标签、统计口径、删除、售出（下拉与文本输入在辅助功能中不可靠设置），这些以 Rust、UI 逻辑与浏览器预览覆盖。
- 撤销条是便捷入口：撤销请求回执丢失时只提示重新读取核对，不单独保存待核对请求。
- 批量操作只作用于物品；心愿、支出、账户不批量。

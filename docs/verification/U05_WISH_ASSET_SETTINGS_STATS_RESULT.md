# U05 心愿同步资产、设置与统计修正（2026-09-27）

## 范围与结果

- 心愿手动实现或攒钱达到目标时，在同一事务中建立一件关联资产；心愿仍留在“全部／已实现”。资产继承名称、分类、渠道及图片引用，手动实现的备注为“手动实现心愿”。心愿预计价不当作实际购入价。
- 旧资料中已实现但未关联资产的心愿，在打开资料或恢复旧备份时补建一次；已关联的记录不重复创建。业务库从 schema 13 原子升级到 14，完整备份的格式版本相应更新。
- 自动攒钱实现后若更正到不足目标，心愿回到“进行中”，关联资产移入最近删除，保留可能发生的后续编辑；再次攒够会产生新的关联资产。手动实现仍保持已实现。
- 设置页右侧资料管理改成紧凑、对齐的操作行，说明内容折叠；左侧分类与渠道可拖动整行预览，且有独立的成组上移／下移按钮。手柄仍支持键盘方向键。
- 侧栏太阳中心改为稍大的实心圆，浅色为深色、深色为浅色；新增半白半黑的“跟随系统”第三档。
- 统计页新增全部／周／月／季／年购入范围、状态数量与占比、分类柱状图与圆环、状态长进度条及售出回收分析。持有周期细分为 0–3、3–6、6–12 个月、1–2、2–3 年及 3 年以上。回收率只比较已知购入价与售价，不混入维护费用。

- `npm run build`：通过；`npm run check`：fmt 与 Clippy 通过。
- `npm run test:ui`：90/90 通过；`npm run test:demo`：2/2 通过。
- Rust 全套故障注入测试在 macOS 原生图片框架可用的环境下通过；沙盒内的单项 `IMAGE_CORRUPT` 经同项原生复跑通过。新增测试覆盖手动实现后的资产备注、分类、图片和来源关系，攒钱回退、重复请求，以及 schema 13 的已实现心愿补建一次；统计样例核对周／月／全部及售出回收。

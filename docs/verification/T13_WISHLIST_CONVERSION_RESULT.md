日期：2026-09-26。起点 `main` = `d3203b7bf82752cf1a16e6283f0522b1c21d79b0`（含 T12），分支 `codex/t13-wishlist-conversion`，由 Claude 串行实现与验收；无远程、未推送。

## 事务契约与实现

- **schema 12**（11→12 单事务迁移）：`wishlist_items` 增加 `converted_asset_id`（外键到 `assets`）与 `achieved_at`；部分唯一索引保证一件资产只对应一条心愿；两个触发器保证「Achieved ⇔ 有关联资产且有实现时间」，且关联一旦写入不可改写或撤回。`wishlist_audit` 因 SQLite 不能放宽 CHECK 而原样重建，新增 `convert` 动作，保留原序号。旧备份 schema 1–11 仍可恢复并迁移；schema 11 以下若出现无法追溯的 Achieved 行则拒绝。
- **唯一转换**：`convert_wishlist` 在一个事务内依次核对请求回执、心愿存在／未关联／Ongoing／revision，经与普通新增共用的 `write_asset` 写资产（分类、渠道、详情、图片走同一校验与附件提交），再把心愿置为 Achieved（revision+1、写关联和实现时间，更新行数必须为 1）、写 `convert` 审计和请求回执，然后提交。回执内容是资产本身，所以回包丢失后沿用既有 `saved_request` 按原请求核对。同请求同内容返回同一资产；同请求不同内容为 `REQUEST_CONFLICT`；已实现心愿再转换为 `WISHLIST_ACHIEVED`；放弃心愿为 `WISHLIST_STATUS`；旧版本为 `REVISION_CONFLICT`；未来购入日期沿用资产校验拒绝。
- **实付与预计分离**：表单只沿用名称、分类和封面；购入金额默认留空，预计价只作说明文字显示，从不写入价格。心愿保留原预计价、备注、分类、加入时间和自己的封面附件。
- **封面**：打开表单时 `stage_wishlist_cover` 把心愿封面原图按正常图片草稿暂存，保存时资产获得独立附件（同一托管文件、不同附件 ID）；原图缺失时提示可不带封面继续，不阻塞转换；提交时托管文件缺失则整笔回滚。
- **追溯与软删除**：心愿读取带 `converted_asset`（ID、名称、是否已删除）和实现时间；资产记录带 `origin_wishlist`（原心愿名称、预计价、加入与实现时间）。资产被移入最近删除时心愿仍为 Achieved，卡片引导前往最近删除，不提供再次转换；恢复后同一 ID 与关联继续有效。
- **界面**：进行中卡片新增「已购入…」，复用资产表单的转换模式（标题「确认购入」、说明预计价仅作参考、按钮「确认购入并建档」）；取消停留在心愿清单且不写入；成功进入新资产详情，显示「来自心愿…预计…加入…」和「查看原心愿」（跳到已实现筛选并定位该心愿）。已实现卡片显示实现日期与「查看资产」或最近删除提示。

购买事件仍只来自资产本身；心愿实现不产生第二个购买事实。全局时间轴中的心愿事件归 T14。

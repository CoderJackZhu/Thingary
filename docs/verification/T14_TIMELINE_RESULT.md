# T14 有效时间轴实现与验证

日期：2026-09-26。起点 `main` = `81201ce66f5a0bd2f57039837e83028ca8415e37`（含 T13），分支 `codex/t14-timeline`，Claude 串行实现与验收；无 schema 变更、无远程。

## 实现

- **只读投影，不存事件**：`src-tauri/src/timeline.rs` 用一条 `UNION ALL` 查询从业务事实派生事件；没有事件表，所以更正、删除、恢复、撤销和重启都不可能产生重复或残留事件。全局页与资产详情调用同一 `list_timeline` 命令，详情只多一个资产 ID 条件。
- **有效事实**：购入（未删除资产的购入日期与实付价）、退役／重新启用（生命周期事件，按序号）、售出（仅未撤销）、维护（未删除）、保障生效（开始日已到或未知）与保障到期（结束日已到，查询时派生）、加入心愿、放弃心愿。已删除资产及其全部子事实、已删除维护／保障、已撤销售出都不出现。
- **心愿实现即一次购入**：由心愿转换的资产只产生一条「购入 · 实现心愿」事件，带原心愿名称；心愿本身不再生成第二条实现／购买事实。资产删除后该购入消失，而加入心愿的历史保留。
- **日期口径**：按真实业务日期倒序，建档时间不参与；未知日期单列「日期待补充」，不放入任何月份，补填后自动归位。心愿的加入／放弃按本机自然日（`date(...,'localtime')`）。同日按生命阶段倒序（售出→退役/启用→到期→维护→生效→购入→心愿），再按序号与时间戳稳定排序。
- **界面**：侧栏「时间轴」开放为全局页，按年月分组，筛选 全部／购买／维护／保障／退役／售出／心愿；事件可打开对应物品或心愿（按心愿当前状态打开相应筛选）。资产详情的「物品时间轴」改用同一投影，保留退役／启用的「更正日期」，并补上以前缺失的维护、售出、保障事件。沿用既有 `lifecycle-history` 样式、tokens 与分段按钮。

「资产建档」不作为时间轴事件：建档时间仍在详情「档案信息」中，时间轴只呈现业务事实，从而满足 AC38「建档与购入分开」。

# Possio 竞品调研与定位

整理与来源核验日期：2026-09-24

本文整理原对话「个人资产管理软件规划」的竞品研究，覆盖持物 iThings、有数两个直接产品竞品，以及八个开源实物管理候选；来源包括官网、帮助文档、App Store 和官方仓库。是否开源不作为进入产品比较的门槛，源码复用另行评估。**核验层级为项目声明与公开文档，没有安装实测、执行测试或完成源码审计。** 商店与官网内容可能随版本变化；仓库链接指向可变的默认分支，后续复用前应重新核验并固定提交版本。文档没有使用 star 数量推导成熟度。

对应产品范围见 [产品设计](PRODUCT_DESIGN.md)。此处只记录外部事实、比较判断和可借鉴方向，不另存一份产品需求。

## 1. 结论

**持物 iThings 应是首要直接竞品与业务体验参照。** 它与 Possio 都围绕个人物品记录、成本回顾和生命周期展开；官网已列出心愿、维护与售出分析，不能因其移动端定位或未确认源码许可而排除。此前只比较开源候选，会低估业务重合程度，并夸大自行开发的差异化。[持物官网](https://www.ithingsapp.com/)

**有数同样进入优先研究的直接竞品组。** 其物品成本与处置回顾切中了同类需求，不能仅因名称中有“记账”就归为流水工具；本轮中国区商店快照中的评分数量也明显更多，具体数据和限制见第 4.2 节。[有数 App Store](https://apps.apple.com/cn/app/有数-物品记账与个人资产管理/id6739918572)

开源同类已经存在：WorthBase、ItemMemo、Lynx 直接覆盖个人物品和成本分析；rInventory 公开描述了 Apple 设备与 Mac 使用；HomeInventory 有桌面启动器；HomeBox 和 Shelf.nu 覆盖不同规模的库存与设备管理；micasa 提供本地桌面系统上的终端应用。

**现有材料不足以排除直接使用持物的可能。** 其 App Store 列出 Mac 兼容条件，但同时标注为 iPad 设计、未针对 macOS 验证。应优先验证它在 Mac 上的操作路径与数据迁移，再判断 Possio 的额外价值；“尚未确认满足全部条件”不能作为市场空白的证明。[商店平台信息](https://apps.apple.com/cn/app/ithings/id6747913105)

因此，Possio 的差异化假设应是**围绕 Mac 重新设计的操作效率，以及聚焦个人实物的完整体验**。生命周期、本地数据与备份是已有竞品覆盖的能力，不能单独宣传为独有优势。高完成度是本项目需要交付的目标，不是目前已经建立的优势。

## 2. 比较口径

| 维度 | 本项目所需含义 |
|---|---|
| 业务匹配 | 重要物品的购买、持有、保障、维护、退役、出售、心愿与成本回顾 |
| Mac 可运行 | 是否能在 Mac 上使用；浏览器、终端、移动兼容和桌面 App 分开记 |
| Desktop-first | 表格、侧栏、详情面板、快捷键等交互是否围绕桌面设计；必须实测才能完整判断 |
| 本地持久化 | 数据可在本机长期保存，离线可用；Web 内存数据不等同持久化 |
| 无自建服务 | 最终用户无需运行 HTTP/API 服务、容器或额外守护进程 |
| 数据可迁移 | 是否声明备份、恢复、结构化导出以及附件处理 |
| 产品相关性与源码复用 | 先按用户任务判断是否为竞品，再单独核验仓库与许可；不能用开源筛选替代产品比较 |
| 公开热度信号 | 记录地区、核验日期与评分数量；抓取快照不等于同时点实时数据，评分量不等于下载量、活跃用户或产品质量 |

自托管不等于无服务器；有 SQLite 不等于无服务器；有 `.dmg` 不等于应用直接访问本地数据库；使用支持跨平台的框架不等于项目已经交付所有平台。

## 4. 重点项目

### 4.1 持物 iThings：首要直接竞品

**为什么必须重点研究：** 用户把它视为原始需求参照，而公开能力也覆盖了相同的核心任务。持物用于理解自己拥有的物品及其成本，比较价值高于仅在库存、团队设备或房屋维护方面相邻的产品。它是否提供可复用源码，不影响这一判断。

#### 已核实的公开能力与边界

| 维度 | 官方公开信息 | 对 Possio 的含义 |
|---|---|---|
| 物品建档与心愿 | 从名称、价格、日期、分类开始，补图片、保障、维护；心愿达成后转资产 [快速开始](https://www.ithingsapp.com/guide/getting-started) | 快速建档和心愿联动已经有直接参照，需研究转化前后信息如何保留 |
| 成本与生命周期 | 官网列出持有时长、成本、售出分析；商店说明包含日均成本，版本记录涉及保障、退役、售出和时间轴 [官网](https://www.ithingsapp.com/)、[商店说明与版本记录](https://apps.apple.com/cn/app/ithings/id6747913105) | 功能闭环高度重合；具体公式、退役计时和编辑一致性仍待实测 |
| 运行平台 | 官网提供 iOS 与 Android 下载，鸿蒙尚在准备；商店列出 macOS 14.0+、M1 或更新芯片，同时标注“专为 iPad 设计，未针对 macOS 验证” [官网](https://www.ithingsapp.com/)、[兼容性](https://apps.apple.com/cn/app/ithings/id6747913105) | 移动产品在 Mac 兼容运行与 Desktop-first 是两回事；不能断言持物没有 Mac 使用入口 |
| 本地数据与同步 | iOS 以本地数据为基础，可选 iCloud/CloudKit；Android 提供本地备份与登录后的云备份快照 [备份文档](https://www.ithingsapp.com/guide/backup) | 本地优先并非 Possio 独有；云快照也不能等同于跨平台实时同步 |
| 迁移与恢复 | 文档说明备份迁移，内容可能包括资产、心愿、分类、图片、备注和设置 [备份文档](https://www.ithingsapp.com/guide/backup) | 字段覆盖、附件完整性、重复导入处理及第三方可读性尚未验证，不能先宣称 Possio 更可靠 |
| 范围与付费 | 官网还覆盖投资、虚拟订阅；会员文档列出月/年订阅与终身购买，权益以应用内为准 [官网](https://www.ithingsapp.com/)、[会员说明](https://www.ithingsapp.com/guide/account-membership) | Possio 聚焦实物是范围选择，不是功能更多；不能把付费等同于不适合使用 |

以上是截至核验日读到的公开说明，不是安装体验结论。商店抓取快照和各平台版本可能不同；不以评论中的旧额度或某次价格作为当前完整会员规则。本次未确认可复用源码仓库与许可证，也不据此断言其一定闭源。

#### 对照 Possio，应该借鉴什么

| 用户任务 | 研究持物时的重点 | Possio 的桌面设计方向（规划，未实现） |
|---|---|---|
| 买到新物品 | 必填字段、补充资料的展开时机、保存后的去向 | 键盘完成基本录入，图片与更多字段渐进补齐 |
| 把心愿变成资产 | 实付价与预计价、日期、图片和历史关联 | 保留关联历史，桌面详情可回看转化前后信息 |
| 维修、退役或出售 | 动作入口、维护费用、状态和成本的联动 | 在同一详情上下文完成操作并核对统计变化 |
| 比较长期持有成本 | 金额含义、统计范围、缺失数据与成本口径 | 利用表格多列比较、排序和详情面板解释差异 |
| 回顾与迁移 | 时间轴信息层次、备份恢复与附件范围 | 档案可追溯、导出可理解、恢复结果可验证 |

**研究判断：** 可以把“围绕持物所服务的核心需求，做一个适合 Mac 的个人实物应用”作为内部方向描述。实际价值需要来自更顺手的桌面流程，不能停留在放大移动界面；也没有必要为了差异化引入金融、订阅等额外领域。

#### 下一步实测清单

正式界面设计前，优先用测试数据比较：新增一件物品 → 心愿转资产 → 补维护 → 退役/售出 → 查看成本与时间轴 → 导出并恢复。记录应用版本、设备、操作步骤和结果，尤其检查 Mac 窗口布局、键盘导航、多列比较、筛选保留与文件操作。暂未看到某项功能时记为待确认，不记为“不支持”。

如果持物的 Mac 兼容版已经满足实际使用，应重新比较直接使用与自行开发的维护成本；若仍决定做 Possio，应把真实操作差距作为桌面验收依据。本轮未安装或购买持物，也未验证其计算公式和恢复完整性。

### 4.2 有数：重点直接竞品，参考成本表达与物品展示

本节对象为 App Store ID `6739918572` 的「有数 - 物品记账与个人资产管理」，避免与同名服务混淆。商店说明聚焦物品而非逐笔生活流水，因此与 Possio 有直接业务交集。

**公开能力：** 商店列出拍照与 AI 抠图、物品陈列、目标日均成本与时间进度、售出价及买卖差额、资产总览，以及服役中/退役/卖出状态。平台标注为 iPhone 设计、未针对 macOS 验证，兼容条件含 macOS 12.4+ 与 M1 或更新芯片。提供内购，会员项目有多个价格档，不能仅凭列表认定当前统一售价。[官方商店说明与兼容性](https://apps.apple.com/cn/app/有数-物品记账与个人资产管理/id6739918572)

#### “更受欢迎”的证据范围

2026-09-24 核验的中国大陆区 App Store 页面快照：

| 产品 | 评分数量 | 平均评分 | 来源与快照说明 |
|---|---|---|---|
| 有数 | 4,594 | 4.7 / 5 | [商店页](https://apps.apple.com/cn/app/有数-物品记账与个人资产管理/id6739918572)，检索标注当日抓取 |
| 持物 | 374 | 4.8 / 5 | [商店页](https://apps.apple.com/cn/app/持物-智能资产管理与记录/id6747913105)，检索标注 5 天前抓取 |

**判断：** 有数在这些快照中的累计评分规模明显更大，支持提高其研究优先级；不能据此得出活跃用户、收入、留存或口碑全面领先的结论。两页不是同时点实时采样，后续引用具体数字应重新核验；也不能把评分数量比当作用户数量比。

#### 对 Possio 的参考价值（研究判断）

| 研究主题 | 值得验证的问题 | Possio 的设计取舍 |
|---|---|---|
| 物品展示与录入意愿 | 图片、卡片和完成录入后的反馈，是否让用户愿意持续维护档案 | 研究图片优先的 Grid 与高效比较的 List 如何配合；抠图不是自动进入 P0 的理由 |
| 成本表达 | 用户是否理解持有天数、日均成本和目标之间的关系 | 解释分母与费用范围，避免把成本下降直接解释为使用充分或购买值得 |
| 状态与售出复盘 | 退役如何计时，卖出如何抵扣，修改历史后是否一致 | 与产品设计第 6 节计算契约对照，不照搬未经验证的公式 |
| 首次使用与付费 | 免费阶段能否完成核心任务，付费触发是否清楚 | 记录实际限制与流程摩擦，不从热度推断商业模式适合 Possio |

**待确认：** 当前资料不足以确认心愿转资产、保修与维护关联、完整时间轴、离线行为、同步和含附件的备份恢复。未确认不代表不支持；同样不能把商店中的资产净值用语当作已验证的市场估值算法。本轮没有安装、购买或验证其源码许可。

后续与持物使用同一组测试物品比较新增、改价、退役、售出和成本回顾，再探查上述待确认项；Mac 兼容版也应实际验证窗口、键盘与文件操作。持物主要帮助检查完整流程，有数主要帮助检验成本表达与物品展示，这只是研究侧重点，不是对两款产品功能边界的断言。

### 4.3 WorthBase / 家底：优先参考业务计算

官方 README 描述了账户快照、实物状态、估值、售出结算、维护和经常性费用；成本模型包含线性、预期寿命、残值、不分摊四种策略，还支持次均成本。数据为本地 SQLite，声明提供 JSON/CSV 和备份；发布入口是 Android，iOS 自行构建。[官方说明](https://github.com/callmebg/worthbase/blob/main/README.md)

**判断与借鉴：** 它是成本与结算设计的重要参考。值得研究公式边界、维护费用去重、迁移和恢复；金融账户及复杂摊销不应直接进入 Possio MVP。原对话提到的 207 个测试是 README 声明，本次没有执行，不能据此认定引擎已经过独立验证。

### 4.4 ItemMemo / 物记：个人持物与统计参考

官方列出物品与分类管理、总览、日均成本、闲置/高成本提醒、日/月/年趋势、分类占比、JSON 迁移及明暗主题。开发入口包含 H5 和微信小程序，项目采用 uni-app 与 Vue 3；文档将其描述为本地优先、离线可用。[官方仓库](https://github.com/FLYFISH567/ItemMemo-APP)

**判断与借鉴：** 产品方向接近收敛后的实物版，可参考总览信息密度、提醒和统计呈现。未确认独立 Mac 构建、完整心愿联动和维护/售出结算闭环；不能从「离线可用」推导其数据模型就是 SQLite。

### 4.5 Lynx Asset Management：日均成本的直接参考

README 声明价格、额外费用、日期、分类/标签、退役/售出及统计排除标记，支持列表/网格、中英文和主题。公式以价格加额外费用除以购买后天数；Android 使用本地 JSON，Web 使用临时内存，导入导出为自定义 TXT。[官方仓库](https://github.com/Shan-Mao/lynx_asset_management)

**判断与借鉴：** 可参考状态与统计开关如何呈现。Mac 版本未确认，Web 不宜被当作长期档案库。原公式并没有证明当天购买、退役计时和售价抵扣等边界正确，后续阅读源码时应重点检查；Possio 仍使用自己明确的计算契约。

### 4.6 rInventory：Apple 平台方向参考

README 声明以 Swift / SwiftUI / SwiftData / CloudKit 构建，记录名称、位置、数量、图片，提供分类、搜索和行/网格展示，并描述 iPhone 到 Mac 的 iCloud 同步。[官方仓库](https://github.com/Somebud0180/rInventory)

**判断与借鉴：** 这是 Apple 平台相关候选，适合参考浏览和导航。其公开重点是物品与位置；完整日均成本、出售结算、心愿和维护闭环尚未确认。未安装 Mac 版本，不能把「目标覆盖 Apple 设备」写成「已证明成熟的 Mac Desktop-first 产品」。

### 4.7 HomeInventory：有桌面包，但运行方式不同

此处特指 `asdteke/HomeInventory`，不与同名商业产品混淆。官方列出保修、发票、维护、附件、购物清单、备份恢复及活动记录。架构为 React → Express → SQLite；Tauri Launcher 的职责包括检查依赖、启停 API/UI、显示本地 URL，文档列出 macOS `.dmg`。[官方架构与启动说明](https://github.com/asdteke/HomeInventory#architecture)

**判断与借鉴：** 保修、维护、附件及活动历史值得研究。桌面安装包解决启动便利性，但没有消除服务架构；家庭共享、认证、借还等也超出当前边界。不能只因它用了 Tauri 就视为与 Possio 的「IPC 直接访问本地数据」方案等价。

### 4.8 HomeBox：家庭库存模型参考

项目当前参考地址为 `sysadminsmedia/homebox`。官方声明使用 Go、SQLite 和嵌入 Web UI，提供分类/位置/标签、图片、文档保障及购买维护记录；快速开始采用 Docker 部署。[官方仓库](https://github.com/sysadminsmedia/homebox)

**判断与借鉴：** 可研究物品资料、附件、购买与维护的组织方式。用户对界面和使用方式不满意，是当前产品需求的重要来源，但不等同于普遍质量结论。应把差异表述为「服务式 Web 产品不符合低频打开 Mac App 的偏好」，不能断言只能 Docker 或必须一直运行。

### 4.9 micasa：本地数据与维护参考

官方将其描述为家庭维护终端工具，覆盖计划、项目、设备、服务商、报价及历史；采用 Go、SQLite，提供 macOS、Windows、Linux 二进制。默认离线，存在可选模型查询方向。[官方仓库](https://github.com/micasa-dev/micasa)、[官方文档](https://micasa.dev/docs/)

**判断与借鉴：** 本地持久化与低依赖形态值得参考，维护历史和到期计划也有价值。但 TUI 与所需图形 Mac 产品差距明确，房屋工程与供应商报价不进入 Possio。原讨论的「真本地」应限定到默认运行形态，而非承诺一切扩展永不联网。

### 4.10 Shelf.nu：企业设备管理边界参考

官方定位为团队实物设备管理，列出预约、借还、责任人、位置、角色、套件、QR、CSV 与活动记录。技术体系包含 Web 应用、PostgreSQL 和 Supabase，支持自托管路径。[官方仓库](https://github.com/Shelf-nu/shelf.nu)、[官方文档](https://docs.shelf.nu/)

**判断与借鉴：** 可观察资产筛选与信息组织，但权限、团队借还、预约和多工作区不是当前个人持物需求。功能多不代表适合直接改造为单机 App；不要因名称包含 asset 就把它列为业务上最接近的竞品。

## 5. 最终差异化定位

> 物志 Possio 是一个面向 Mac、无需服务器的本地个人实物档案应用，用完整的心愿、购买、使用、维护、退役与售出记录，帮助用户回顾自己拥有过什么以及持有成本。

这一定义包括三项交付目标；其中桌面效率是相对持物、有数需要重点验证的差异化假设，后两项是应达到的产品基线：

1. **Mac 桌面操作效率**：侧栏、表格、多列排序、详情面板和键盘路径。视觉完成度需要实际设计和体验验收。
2. **完整的个人生命周期**：心愿转资产、保障与状态分离、维护影响成本、出售结算、统一时间轴。
3. **本地与长期可迁移**：无需登录或部署服务；SQLite 和托管附件；可靠备份恢复；清晰可读的数据导出。

这些能力在现有产品中已有先例，而且持物已覆盖多项组合。产品机会应通过具体桌面任务验证：录入是否更顺手、多物品比较是否更清晰、回顾与文件管理是否更方便。仅凭“本地 + 生命周期 + Mac 可运行”不足以证明优势；实物范围的收敛也不等于持物的扩展功能妨碍使用。

「未发现成熟代表」只能作为有范围的研究结果：本次样本与文档不足以给全市场的成熟度下定论。若后续发现高度匹配项目，应重新比较直接使用、贡献上游和自行开发的总成本。

## 6. 参考与实现策略

| 研究顺序 | 重点 | 预期产出 |
|---|---|---|
| **持物 iThings（优先组）** | 端到端个人持物流程、Mac 兼容体验、成本展示与迁移 | 直接竞品体验基线、真实桌面差距与是否有必要自建的判断 |
| **有数（优先组）** | 物品展示、成本理解、处置复盘、首次使用与付费触发 | 成本表达与录入体验参考，使用同一测试数据与持物比较 |
| WorthBase | 成本、维护、出售结算、迁移与恢复 | 边界问题清单与自有计算契约 |
| ItemMemo / Lynx | 总览、排行、闲置、统计范围 | 桌面页面原型中的信息取舍 |
| rInventory | Apple 物品浏览与导航 | Mac 交互可借鉴点，需实机确认 |
| HomeInventory / HomeBox | 保修、维护、附件、活动历史 | 资料关联和业务流程检查项 |
| micasa | 本地档案、维护计划 | 数据可靠性与维护体验参考 |
| Shelf.nu | 筛选、批量操作、团队复杂度 | 明确当前不引入的领域边界 |

原对话建议不直接 fork WorthBase、HomeBox 或 Shelf.nu。该建议仍适合作为工作方向：它们的平台导航、部署模型或领域范围与目标差异较大，直接 fork 不一定减少总工作量。是否最终采用上游代码，应以具体模块评估为准，不把建议写成不可变原则。

学习模型和公式不等于可以无条件复制源码。本次没有完成八个项目的逐文件许可审计；实际复用时核验目标版本 LICENSE、归属和分发要求。当前没有复制竞品代码，也没有下载或运行其应用。

## 7. 原讨论中保留、修正与尚未验证的内容

| 原判断 | 整理后处理 |
|---|---|
| 开源几乎没有同类 | 修正：已有多个直接或相邻项目，功能本身不构成空白 |
| WorthBase 是最值得看的业务参考 | 修正：持物优先用于端到端产品比较，WorthBase 用于开源成本实现研究；两者都需验证 |
| 持物只需保留为需求来源 | 修正：正式纳入首要直接竞品，不因移动端或开源状态被排除 |
| 有数似乎更受欢迎 | 部分支持：本轮中国区快照中的累计评分规模更大，不代表活跃用户或质量领先；纳入重点直接竞品 |
| Possio 的区别是持物只能手机用 | 修正：商店列出兼容 Mac；应比较 Desktop-first 的实际操作价值 |
| rInventory 最接近成熟 Mac 桌面体验 | 收窄：Apple 平台方向接近，Mac 完成度未实测 |
| HomeInventory 有 dmg，是否就符合需求 | 明确：其 Launcher 仍启动服务，应比较实际架构 |
| HomeBox 必须 Docker 常驻 | 修正：文档快速开始使用 Docker；核心差异是服务式产品形态 |
| UI 简陋/成熟/高质量 | 用户偏好或待体验判断，不作为未经实测的客观评分 |
| WorthBase 200+ 测试 | 官方文档声明，本次没有运行或验证覆盖质量 |
| 没有一个成熟产品满足全部条件 | 仅可表述为本次样本未确认，不能证明不存在 |

持物 iThings、有数已在第 4.1、4.2 节作为直接竞品展开；Wealthfolio 保留为桌面体验与技术方向参照，不因此列入个人实物直接竞品。早期提及的 Ownlog 名称冲突、价格、商标及商店可用性未在本次展开核验，不能作为 Possio 已获可用名称的证据。

下一轮优先完成第 4.1、4.2 节的持物与有数实测，再把观察转化为桌面设计和验收依据。当前「独立实物 App、Mac 优先、本地无服务、完成度优先」仍是产品方向，是否优于直接使用现有产品尚待验证。

## 1. 不变量

1. 实际金额为整数分，日期为本地自然日；月份保存规范 `YYYY-MM`，转换时明确月界，不以任意年龄代替公共时间线。
2. 未知、已知零、估算值、选择不纳入分别表达；不能仅用一个数值 0 编码。
3. 真实资料共享，方案仅存假设；采用、模拟、解锁推演不写真实账户余额。
4. 一个实际支出来源只能有一个事实身份；方案、愿望、物品、费用通过稳定 ID 引用。
5. 单次付款、贷款本金减少、持续费用和受限资金移动分别入账；同一项不能重复计入。
6. 比较用同一事实起点和参数上下文；历史基准冻结，最新重算不覆盖它。
7. 关闭模块不能读取其隐藏事实；手填模拟金额始终标为假设。

## 3. 起点资金

### 3.1 三种总额

- 金融净资产：完整盘点中计入的资产余额减负债，继续沿既有财富口径。
- 规划可用资金：该方案纳入、当前可动用的资产份额；不先减掉全部长期贷款本金。
- 受限资金：该方案纳入、需达到条件才能解锁的资金；不用于解锁前支付。

债务在现金预测中按还款处理，另维护剩余本金；未来净资产视图减当时剩余债务。不能用“净资产减全额贷款”的数值起步，再从同一现金流扣完整本金。

未建立还款计划的负债，必须给出处理方式：短债按明确月份一次支付，贷款按付款计划，或标为未覆盖。没有足够负债资料时只能展示局部现金情景，不给出综合负担充足结论。

### 3.2 选择与默认

账户行显示名称、金额、日期及“可动用/受限/待确认”。明确的现金存款可建议纳入，用户在首次确认资金范围时保存选择；投资、其他资产、受限权益必须确认可用性，不能只由名称推断。

公积金与个人养老金建议受限，但具体解锁日期须来自已支持估算或手填确认。未知解锁日期在主情景不贡献可用现金，仍列出余额和缺项；明确“未计入可用资金”而不是余额为零。

参与比例默认选定账户 100%，详情可减少；一个账户在同一方案中的总参与份额不超过 100%。目标共用该范围，不为每个目标复制比例或建立实际划拨。

物品购入价不进入资金池。计划售出只能显式建立预计回收事件；没有已知回收金额不能补缺口。已确认售出仍以账户盘点为现实起点，避免又加一次现金。

### 3.3 日期与模拟金额

事实起点锚定最近完整盘点 ID、修订和日期 B，预测从 B 之后开始，不把旧余额改称今天实际余额。首页显示“截至 B”，预测当前值另标“按假设推算”。旧不完整盘点不提升为完整起点。

手填模拟起点包含金额、截至日和备注，允许负数作为资金不足情景；不创建实际盘点。未知起点不计算绝对资金结果。切换为正式盘点需明确替换来源，不能同时加上两个起点。

## 4. 未来净投入、费用包含与阶段

### 4.1 简化模式

用户确认的每月净投入指日常收支后、计划资金范围的净增减，不含投资估值收益，不含内部账户转账。输入允许正/零/负/未知。

表单显示已知现有还款和受限缴存，询问是否已包含在这个净额。新计划支出及其新增持续成本默认尚未包含。没有相关来源时不出现这组问题。

对已包含的独立费用，保存它在阶段净额中的参考金额 Qref；计算先还原为 Qref 未扣前的净额，再扣本期实际预测的 Q(t)。因此既有车贷到期会增加净投入，不能既双扣又忘记到期后的变化：

`该期净现金变化 = 用户净投入 + Σ已含费用参考额 − Σ这些已含费用的本期预测额 − Σ额外费用本期预测额`。

“已含费用”与“额外费用”集合互斥且各按来源/期间唯一；新事件费用只能进入其中一个。部分月份中用户净投入和参考额按期长折算，实际到期费用按 B 之后的排期计算，不用月均金额覆盖已知付款。

每项费用只出现在一个归一化列表。受限缴存区分资金来源：个人养老金等由可用现金转入的，按包含关系扣现金一次并增受限池一次；工资扣缴/单位缴存已在税后到账之前处理的，只增加受限池，不再扣用户税后净投入。公积金合计缴存不能全额当作税后现金支出。来源未知则列待确认，不推定为现金转入。

无法确认费用包含关系时显示影响范围/待确认，不给完整结论。前端提供一句解释和费用清单，不让用户自己计算 Qref。

新净投入条件有自己的参考费用与包含关系；从旧阶段引用时必须核对原适用金额，不擅自平均。保存的参考金额不随后续债务更正悄悄改变，来源修订变化触发重新确认；费用引用不依赖新建职业阶段。

历史资产变化只作旁边参考，标明包含估值变化，不能当作实际结余直接填入或自动更新未来净投入。用户另行输入测算金额时保存为独立假设，不把历史涨幅改称已证实的投入能力。

### 4.2 明细模式

当前承受能力、退休预算及后续明确期间事件采用“期间收入 − 期间支出”得到净额。收入中养老金、出租等来源分别标识；支出中日常预算与单列贷款/房租/缴费注明包含关系，归一化后各计一次。

同一覆盖期间只能净额或收支明细生效。切换展示替代关系，保留被替代数据为只读历史，不同时累加；净额不能反推真实工资和消费。

新模式不组织职业主阶段；后续期间事件的覆盖区间统一左闭右开，重叠替换须选择或合并，独立费用按来源去重后可叠加。旧阶段规则仅用于兼容：起止互不重叠、空隙未知、不自动沿用职业。开放状态不能擅自接回工资。

### 4.3 费用边界

日常预算、现有还款、独立房租、社保续缴、订阅和计划新增费用均可标明已包含/额外计入/本情景排除。实际付款记录是来源参考，不再次作为未来支出。

周期费导入未来时显示覆盖到何时；有结束日遵守结束日，无结束日要求确认预测截止，不能把全部订阅自动延长至寿命终点。相同来源 ID 与覆盖期去重；不按名称合并。

### 4.3.1 支出类型与覆盖标准

沿用既有费用的 essential（必需/灵活）属性及来源身份，不新增日常消费记账体系，也不强迫首次把一个生活总预算拆成多桶。

- 基础反求覆盖全部已纳入预算与安排，称「维持所选生活预算所需投入」。用户只填一个总预算时计算整个预算，不自行推断其中多少可省略。
- 已有标记按原值保留；必需保障检查包含明确必需支出及未包含的债务/合同付款。费用已含关系照 §4.1，各来源只计一次；标记灵活不能删除已发生债务或必须履行的付款。
- 仅灵活支出缺口时可以说明缩减空间，但完整目标仍未覆盖。若暂不能可靠拆出必需缺口，仅显示完整预算缺口，不凭总缺口推断最低保障已经满足。
- 后续「只保留必需开销」比较用同一起点与参数、明确不同的预算范围再计算，不静默删灵活项、不自动采用。未明确预算分类或关键资料缺失，不给完整最低保障结论。
- 报告和模拟说明判定针对完整预算、必需支出，还是其他已确认条件。最低保障满足不等于原退休目标达成；现有成功率解释随实际算法保留，不能因换标签修改旧冻结结果。

这是一套支出属性与结果口径；单独的最低预算比较可后置，不作为基础第一批的新增计算任务。

### 4.4 积累条件、压力条件与时间线适配

本节为总设计 §4.4 的计算权威；问答、模块职责和交付分层只维护在总设计。下述按基础、独立工具与后续增强区分，不把全部能力作为第一批实施依赖。物理映射在实施时确定，不因此启动全套持久方案或报告开发。

#### 基础输入与归一化

1. 未来月度净投入为可选固定条件，正/零/负/未知分开。未知时可在目标及其他关键输入完整的前提下反求所需月投入；预计达成日期等依赖未来投入的结果保持未知。反求候选只是计算变量，不保存为用户能力，也不将未知临时变零后绘制既定预测曲线。
2. 月度金额用整数分，沿用统一金额基准与月账本。年等值可由月金额乘12展示，不引入额外独立假设；年度实际到账或季节变化不因展示年等值而得到覆盖。以后支持原生年度输入时再明确均摊与余数规则，保证完整12月合计和单位切换不丢分；这不是第一批的输入要求。
3. 通用模型只有可选月净投入，不接收职业阶段或储蓄阶段列表。旧阶段不计算、不平均迁入；没有通用输入时重新设置。后续明确期间变化须作为独立情景条件实现，不恢复旧职业产品路径。
4. 净投入不含内部转账、投资估值及另行计算的投资收益；外部收入已含净额时也不再单独增加。经营者只纳入可用于个人目标的金额，营业额和需保留的周转金不能自动成为个人可用资金。
5. 各输入按 §4.1 核对费用包含与独立来源；新输入复用稳定费用引用和排期，不重复计现有贷款。未来缴存及养老金按 §7.2 独立确认，不由净投入符号推断。
6. 计算上下文固定 B、金额基准 T、事实修订、参数/模型版本及时段。普通目标不依赖完整养老金 Profile；年龄/政策输入按需依赖，不能伪造生日、账户余额或社保值绕过校验。

固定月条件描述平均分配的情景，不能证明每月实际到账或月内支付安全。已知到账日期可作为后续明确流输入；若原净额包含同一来源，采用前须解除重复包含。B 后推演不补写真实历史，旧盘点始终显示「截至 B」。

#### 结果能力与需求上下文

按能力归集缺项，不以一个全局 `isReady` 同时控制所有结果。需求上下文携带已知输入及原有未知状态；只有执行求解候选或已确认条件推演时才编译数值 Plan。反求候选 0 是被检验的变量，不是「投入未知」的替代编码。未知费用覆盖也不能随候选默认已包含或排除。

| 能力 | 最少条件与未知投入的处理 |
|---|---|
| 已知资金展示 | 已读取的事实及截至日；其他规划缺项不隐藏已知余额 |
| 所需月投入及偏低收益需求 | 目标/期限、起点与可用性、全部已纳入预算/费用、退休收入计入方式、收益/金额基准完整；不需要未来投入。引用政策估算才依赖其资料，本次不计无需伪造资料 |
| 预计达成时间、完整资产路径、购买后余额与相应心愿影响 | 上述对应条件，加明确未来投入或带标签的临时试算条件；未知不画零值路径，不显示不存在的预计日期 |
| 市场路径比例、投入敏感性及收入中断测试 | 对应数值试算上下文及模型参数；未知投入时提示填写可选试算金额，不能阻断独立需求结果或自动采用所需金额 |
| 当前承受能力 | 可用资金、可靠到账、当前必要开销及费用覆盖、底线设置和检查时段；不依赖退休需求、未来投入或完整养老金资料 |

各结果同时携带本次采用条件、覆盖范围和局部缺项；读取失败与用户选择不计分开。异步比较固定同一读取上下文，旧响应不能替换新结果。市场条件测试只能改变声明的参数，不通过投入正负同步改缴费。

基础主判定覆盖全部已纳入预算及其支付约束。当前代码的完整预算缺口会使 `failure_month` 非空；即使必需支出完全覆盖也不能显示完整目标成功。终点恰好为零、此前无支付缺口且未设置额外余额要求，在有限检查期可判定预算覆盖，但应明确终点没有余量，不能称「仍有余钱」或终点以后安全。必需预算独立比较及额外终点储备为另行明确的条件；不默默改用 Wealthfolio 的必需支出与终点严格大于零标准。接口、模拟和文案必须使用同一口径，旧冻结结果保留原版本。

#### 第一批持久化与保存接缝

当前 `StoredProfile` 与计算用 `PensionProfile` 同形并强制完整北京资料。实现时分开持久输入与完整估算输入：共同出生年月/金额假设/退休条件保留；养老金专属职业分类、地区、累计缴费月数、账户余额、基数及有关事实允许未知。完整北京估算由独立校验收窄后调用既有模块；不要把持久类型可空一路传给计算器，或用0/默认北京代替缺资料。已有值原值保留，养老金编辑只修改其字段。

复用现有唯一 `plan_profile` 记录及统一revision，`retire.core`、`life_events`与发生/付款引用仍只有一份。通用条件载荷位于 `retire.basic`：缺失表示待重新设置，不回退旧估算；存在时使用通用能力，不叠加或外推旧阶段/route。目标、预算、收益与期限复用相应字段，目标年龄未确认保持未知，不能用出厂50岁冒充选择。旧JSON只在读取／历史回执边界解析，事实与引用保持严格校验。

| 基础载荷职责 | 最小语义 |
|---|---|
| 契约版本 | 本次基础输入版本；读取旧资料不自动添加 |
| 资金起点选择 | 实盘/模拟互斥。实盘引用最近完整盘点及计算时修订；模拟保存整数分金额或未知、截至日/未知、备注，明确是规划假设，不生成盘点。B来自所选起点，T沿唯一金额基准 |
| 单一投入假设 | 稳定ID、可空的整数分月金额；正/零/负/未知分开。ID只用于费用/来源引用，不代表职业阶段 |
| 退休收入计入模式 | 未选择、本次不计全部退休收入、选定手填流、北京估算加选定额外流；复用已有 `income_items`定义，以稳定ID单独保存纳入选择及来源角色，不按名称猜来源 |
| 独立未来缴费条件 | 北京引用时明确缴费时段/停止月份、基数和已支持的续缴/池缴存条件；未知仅阻断依赖它的结果。不能由净投入正负/阶段/职业/反求候选推断 |

| 退休预算作用域 | 新模式主金额为用户填写的预算总额；已有支出桶、房租、续缴与其他有关来源分别确认已含/额外及已含参考额。沿稳定ID计算退休期规范化支出，不沿旧日常生活桶直接重复相加 |

资金起点的模拟载荷属于基础保存分区，和可选投入一样可明确保存或仅临时预览；普通取消不落盘。切换实盘/模拟必须明确替换来源，二者不相加。财富模块关闭时service不得调用其账户/盘点/汇总来源，也不得从缓存或旧规则取旧账户金额；可明确使用模拟起点。仍引用隐藏事实的费用/贷款不能声称已覆盖，需显式补充模拟条件或给出相关缺项。上下文同时携带模块状态、起点类别及其确认/截至日期。

退休预算规范化保持总额可理解：设主总预算为S，已含来源在这份总预算中的参考额为Qref，对应未来实际排期为Q(t)，则退休期按同一金额基准计算 `S(t) − ΣQref(t) + ΣQ(t) + Σ额外来源(t)`。已含来源保留起止/通胀/必需标记；尚未发生的新费用默认额外。已含参考额不超过主总额，来源及包含范围不清楚时blocked，不静默截成0。不得既保留总预算又全额叠加这些已含分项；也不得因已含而删除其到期/涨价规则。参考额与范围冻结在预算确认时：其扣除持续于所确认退休预算范围，不跟随源到期一同归零；到期停止的是Q(t)，避免把省下的月供自动又加回消费。若用户希望释放部分转作其他消费，须改预算，不自动重新分配。

例如退休预算4000已含持续房租1000，编译为其他生活3000加房租1000；租金变化由该源排期处理。若房租明确额外，则4000加1000；已有灵活桶可按已含参考额拆出并保留属性，不强迫新用户拆全部预算。原规划的spend_cents生活桶语义不变，新模式与其预算作用域互斥；旧用户重设时先核对当前合计及哪些明细已含，不把旧生活桶直接改标总额。预退休投入费用与退休预算包含是两个时间范围，各计一次，不因核对一个而自动推断另一个。

退休收入计入真值表（池解锁仍独立）：

| 模式 | 北京政策养老金 | 明确选定的手填国家养老金流 | 明确选定的其他流（年金/租金等） |
|---|---|---|---|
| 未选择 | 不计算，需求列选择缺项 | 不自动采用 | 不自动采用 |
| 本次不计 | 不计 | 不计，定义保留 | 不计，定义保留 |
| 手填 | 不调用政策估算 | 按选定定义计一次 | 按选定定义计一次 |
| 北京估算 | 资料及独立缴费完整后计一次 | 同一来源替代项不得同时计入，保留定义供核对 | 仅明确选择并确认来源不同的项计入 |

未选定ID的流只是保留定义，不参与本次；北京模式不会把所有income_items自动当额外收入。来源角色须明确，不能按标签“养老金”推断；旧未知角色需核对才能与政策来源联合。每笔实际来源只有一个预测收入身份，金额/起领/是否保购买力等未知阻断依赖该流的完整需求；本次排除不补成事实0。

不在新载荷复制core、账户、事件、付款、余债或养老事实。通用输入没有启用旧阶段的隐藏参数；没有basic的旧资料读取时仅保全事实，重新设置时目标、完整预算、费用与月投入独立确认。最后一次事务保存通用输入，不归档或展示旧假设；关闭不保存。本次退出不实施命名方案系统。

缺出生年月、目标、预算或收入选择允许保存未知，但相关计算保持blocked；普通取消不保存草稿。已更正事实不会由旧请求或旧假设重新写回。

读取/更新服务复用统一generation和来源修订。推荐一个带类别的分区更新命令：基础规划编辑提交其允许字段，养老金编辑提交其允许字段，已有资金/事件编辑也明确自己的字段范围。后端在同一事务读取当前记录、按允许字段合并、校验完整结果，沿用 `expected_revision`、`request_id`、回执与提交未知核对。首次基础保存不需要养老金事实；不得在UI先拼一份全零养老金资料。旧完整 `plan_profile_save` 保持兼容，但不能让旧请求静默删掉基础载荷或覆盖更新后的资料；明确删除/清除与省略字段分开。

当前Profile/Retire/Core为严格 `deny_unknown_fields`，所以新增载荷或空值即使不新增表，也改变旧客户端读取边界。实施时按实际schema进度登记兼容迁移与备份边界；不批量重写旧ID/金额/日期/资料或建立全套Scenario。备份inspect/恢复须调用同一新校验，旧客户端不能恢复新格式时明确拒绝，不以宽松反序列化绕过。

保存指纹包括序列化DTO。新可选字段缺失时应不参与序列化；旧非空值、顺序与历史回执用金样本核对。尤其当前未提交的 `setup_completed` 默认false会参与序列化，应在共享准备时核实旧回执兼容，不能只验证旧JSON可读。必要兼容fallback只接受确实不含新条件的旧请求；不得删除新字段后算旧指纹，让同request_id修改新条件仍被当作重放。旧引导标记不作为新模式计算门控，不必为四步向导再建一套持久草稿。

#### 第一批 core 数值与读取接入

`src/plan-basic.ts` 导出 `buildBasicCapabilities(sources: PlanningSources, temporaryContribution?: string): BasicCapabilities`，并由 `plan-retire-calc.ts` 重导出。未知投入仍计算requirement；只有明确投入携带预测Plan。临时参数不写库，其context.source及prediction.source为temporary。`solveBasicRequirement` 用完整固定目标月账本求整数分候选，并区分边界/付款约束；所设及降低200 bps两组收益分别验证，不输出候选FI日期。明确预计投入的Plan带input_mode=basic，不使用旧阶段/route/35岁检查点，养老金时段和受限池不随退休触发改变。

完整总预算先扣退休已含参考额成为其他部分，再按稳定来源添加实际明细、租金、续缴或事件费用；参考额在作用域内固定，来源结束只停止对应实际费用。净投入已含参考额先还原，再扣实际费用。个人养老金现金转入在明确区间分别进入退休前/后同一本账，工资扣缴/单位公积金不再次扣税后现金。普通首期流按B余天比例折算，事件付款保持月初顺序。完整预算不足为失败；终点零但无缺口表示有限期间覆盖、无余量。

`buildRetireCalc(saved,snapshot,review,incomes,today,nativeSources?)` 在basic模式消费同一个能力结果，返回capabilities及仅明确投入的plan/proj/out；review允许null。原模式接口仍保留。UI使用nativeSources或直接调用buildBasicCapabilities，不拼不同批来源。`loadPlanContext()` 改从原子service读取，返回sources及nullable review；心愿旧桥接需将ctx.sources传为第六参数。`isReady` 拒绝未知或temporary预测，`impactOf`再次核验。

总览PlanSources新增generation/writeVersion/modules（JSON camelCase），与原子profile/snapshot同批；TS新增字段可选仅兼容旧调用。原生review_overview也执行Worker实际模块开关，财富关闭跳过财富汇总、历史统计及盘点时间线。`summaryRetire`保留旧discriminant方便UI分支接入：未知预计投入时kind=blocked/step=saving，同时capabilities.requirement可以ready，main给需求；不能把该blocked当成全局能力关闭。`basisNotes`区别模拟和真实盘点。提交成功、恢复/切库/模块切换后必须invalidate并重读整批，连接write_version不作为跨重启永久事实序号。

#### 独立的当前承受能力

CurrentCashFlow 用明确可靠到账与必要开销计算当前净额，不能由退休预算、未来净投入或职业推定。可靠到账明确没有才取零；开销及费用覆盖未知时，不输出完整承受能力。

状态结束未知时，只在所选有限时段计算当前条件下的轨迹/触底，不自动恢复工资或接回基础投入。长期需求可独立求解，携带「当前状态尚未衔接」；不能声称提供了完整当前路径。旧盘点的现实变化未覆盖时，提示更新或明确局部试算。

完整步进区分到达底线（≤）、跌破底线（<）和耗尽（≤0）；底线不是支出。净流出不为正也要检查已知后续费用，未触及只说明到所选终点。无收益/其他事件时可用「(可用资金−底线)/月净流出」近似核对；未知不进入零值公式，起点已低于底线直接显示差额。

这个工具不依赖退休目标、未来缴费或职业模块。实现其持久保存时才接入对应保存/恢复；不需要先完成联合压力流程或全部旧计划转换。

#### 后续通用比较与期间覆盖

偏低/偏高分别是显式条件，不相加、不加权成未确认的期望，也不称置信区间。单次计算只采用一份条件，比较固定同一事实起点及其他参数。

压力或已知变化以期间收入减支出替换对应常规净投入，不叠加原净额和两份生活费。联合长期路径须有明确覆盖区间和恢复条件；无恢复条件仅给局部结果。原净额已经考虑的日常收入中断不再折减一次，同一次休息事件或旧兼容阶段与压力覆盖冲突时选择或合并。

每份结果说明被改变的条件及未覆盖项；临时查看不改当前方案。已有市场路径能力保持其市场模型含义，不将新增条件比较表述为职业真实概率。

#### 职业模块输入契约

模块只在用户明确采用后，把建议转换为通用投入、期间收支、费用或已支持的退休收入条件。通用引擎不接受职业名称作为改变财务结果的隐含参数，不新增「程序员35岁」或「公务员稳定增长」分支。

采用条件记录模板/来源版本、用户覆盖值及确认依据；来源标签用于解释与追溯，不参与数值分支。打开、关闭或选择模块不自动采用，移除/更新模块不改已保存条件。不同模块产生相同归一化输入和上下文时，结果必须完全一致。

新增期间条件仍须经过费用去重、合法时段、缴费独立及引用校验；不能以模块建议跳过基础校验。参考路径没有可靠金额或概率依据时保留未知，不制造真实收入、未来社保事实或行业平均。具体职业模块尚不实施，也不新增通用核心对它们的依赖。

## 5. 金额基准和月度步进

### 5.1 金额与收益

统一金额基准日 T，首次测算默认为计算当日；已保存方案的原始输入保留其原基准日，显示时转换到 T。实际起点 B 与金额基准 T 是两个不同日期：B 日盘点金额仍是 B 日名义事实，进入实际口径时间线时按同一通胀指数换算到 T，不能直接把不同购买力的数相加。

输入标签“按今天价格估计”仅在基准日为当天时使用；选择未来报价时标记为到支付月份的名义金额。固定名义月供逐月折现，随通胀预算保持实际购买力。保存原输入、原基准和转换参数，内部用高精度换算，只有展示/持久事实边界舍入，不能反复转换改写事实。冻结基准固定当时 T，最新对照需转换到一致基准。

简易首次试算可明确采用“不计投资收益、不计通胀”情景，用户保存时确认；高级可设收益/通胀并显示两者关系。不得将不计收益表述为资金保本。

受限池单独使用其假设，不让同一余额同时在可用池收益和受限池收益。解锁转移不新增总财富，不把领取金额与同一来源未来收入重复计算。

### 5.2 时间顺序

事实锚点是 B 日收盘余额。首次部分月份的常规净收支按 B 后剩余自然日比例折算，页面说明此近似；后续按整月。不从当前日期重新开始完整贷款期限。

月份级模型采用保守顺序：月初已有可用资金支付单次计划支出；对剩余正资金计本期收益；期内净收支与当月解锁在月末结算。首月只处理 B 之后的事实与计划。付款月未知则不给有日期的支付结论。

该顺序用于判断月份级压力，不宣称具体付款日现金充足。确切的年付账单/工资到账日在同月但无法排序时标注月内时点未覆盖，不假定月底收入能支付月初费用。

同月多笔支出合并核对，结果与列表排序无关。新增贷款本金直接形成购买融资和债务，不作为额外可用资金再参与支付；现金只扣首付/杂费，剩余本金按后续还款减少。

不足时记录缺口，资产负数部分不计收益；主结果不能只凭期末总余额忽略月初付款缺口。所有目标、退休求解与高级路径采用同一单月步进和资金可用性规则。

## 6. 计划发生与盘点接续

### 6.1 状态与日期

现实发生记录为“未确认发生/已确认发生/已取消”；逾期且未确认另显示派生状态“日期已过，待核对”。纳入开关不替代这些状态。

预计日期已过不压到当前月，不自动确认购买。该支出暂停未来日期推演，综合结果标记有待核对安排，不能无说明给出全部安排可行结论。用户可调整预计日期、确认实际发生、取消或更正。

状态转换：未确认可确认发生或取消；取消可明确重新考虑；已发生不能靠改纳入开关撤销。已发生的更正需核对事实拥有方和修订，退款/售出是新的真实来源，不能自动回加资金。已发生后的停止持有或停止费用只改变后续排期，不抹掉历史付款。

发生确认最少实际日期及已知付款分项。房车需核对首付/杂费、债务截至日/余款和持续费用。部分金额未知可保存发生记录，缺项部分不计入，当前可计算结果带标注。未来计划的发生对话框默认「还没发生」，不默认今天已发生。仅当已保存 occurred 记录没有付款金额（包括明确零）、来源账户/引用、盘点吸收关系或贷款接续时，允许「撤回为尚未发生」：去掉该记录，保留事件资料；已有事实只走更正。

未来信息完整且未发生的计划按预计日期计入；逾期或核对不完整的部分暂停，不移动至今天。

### 6.2 哪些付款已经被起点吸收

按付款分项处理，而不是对整件购买一刀切：

| 情况 | 预测处理 |
|---|---|
| 实际付款在 B 之后 | 在 B 后现金预测扣一次；不能又加回已记录物品成本 |
| 付款在 B 当日或之前，且确认对应资金来源属于该盘点范围 | 已吸收，不再扣；余额变化来自盘点 |
| 来源账户未在起点范围/日期或金额未核对 | 显示待核对；不自动宣布已吸收，也不默默双扣 |
| 一笔支出分期发生，只有部分在 B 之前 | 已吸收部分不扣，剩余部分按期继续 |

保存显式的核对关系：付款分项、来源账户/事实、被哪份完整盘点吸收、确认修订。新盘点可以计算候选关系，但需来源一致；不只凭日期或同名推断。确认不改真实余额。

“单次付款不再扣”不等于停止全部持有费用；贷款原始开始日、剩余期、仍持续的物业/养车费保留。历史重复换车实例不重放，仅预测未发生的后续实例；实例使用稳定身份，不随今天变化重新编号。

### 6.3 愿望与实际来源

从愿望生成目标时保存 wish_id 和共同 intent_id；更新预计价/日期可显式同步，用户有覆盖值时展示差异，不静默覆盖。已购入必须沿既有愿望确认/关联物品协议；单独确认规划发生不能自动创建另一件物品。

物品购入、重要支出或周期付款已有事实时优先关联，不能复制第二笔金额。取消愿望不自动取消已发生事实；误记购入需到拥有方更正。来源删除与恢复按稳定 ID，不能按同名重绑。

## 7. 债务与受限资金

### 7.1 债务

现实贷款锚定截至 B 的剩余本金/期数；已发生事件不再根据原总价重算为新贷。利率与方式可标估算；只有月供但期限未知时可建立明确的持续付款情景，不能声称已算清剩余债务或完整退休负担。

标准等额本息为已有支持方式，零利率均分；不本轮新增组合贷和公积金资格。还款先计当期利息，剩余部分减少本金；现金付款计一次，净资产仅减剩余本金。提前还款事件联动本金及后续期限/月付选择，不把同额再当消费。

当前阶段净投入已含还款时按 §4.1 归一化；退休阶段按明细继续扣剩余还款，不能因停止工作删除债务。贷款到期只停止其对应费用，不同时取消维护费。

未接续的负债不阻塞基础需求；对应未来还款未计入并标可能偏低。负债余额保留，绝不补零或重复扣本金。

### 7.2 养老金与受限池

养老金可选不计/手填/支持地区估算。手填时保存金额基准、开始/结束、调整方式。引用估算时保存事实版本与未来缴费假设，采用不同停工阶段可得到不同收入，不把一个固定金额套给所有方案。

已有个人养老金、公积金余额从明确账户/模拟余额取得；引用同一账户只计一次。缴费、余额增值、转移、领取分别表达；缴存区分现金转入和工资扣缴/单位缴存，后者不能再从税后现金扣款。政策税费只由已支持估算模块产生，本文不新增或保证政策规则。

未来缴费在方案确认，最新明确零优先于旧非零。未来工资增长与净投入增长不绑定；用户选择同样增长时记录为显式假设。

积累金额正/零/负不能推断就业、养老缴费月份或公积金。未来社保分别确认持续缴费/暂停/未知及适用范围；未来公积金区分工资扣缴/单位缴存与现金转入，金额或本次排除分别表达。普通条件比较仅改变积累金额时保持这些缴费条件不变；联合压力改变缴费时显式展示。新模式引用养老金前须解除现有以负储蓄判定停缴的逻辑，旧模式保留原解释仅供兼容核对。不引用养老金的独立承受能力工具无需等待其余养老流程改造。

本次不引用的受限池不会因未核对余额挡结果，仅在依据列表说明本次未采用。北京估算或明确引用该池时才收集相应缺项。

## 8. 方案保存、比较与采用

真实记录只维护一份；方案复制产生新的方案/目标/阶段 ID，保留共用现实意向和来源引用。复制不是新的实际购买。

比较将两份完整假设投影到同一 B、同一事实修订和参数版本，显示起点、支出日期/价格、投入阶段、预算、养老与收益的差异，以及共同输出差异。多个条件一起改变时不宣称精确因果分解；可逐项恢复比较。

指定当前方案为独立操作；保存方案不自动切换当前。采用与冻结基准在同一事务/请求回执内完成，冲突整批失败；无变化重复采用返回既有结果。当前方案不能直接删除，先选择替代或取消当前；归档保留历史。

查看比较不修改事实、采用标记或原假设。尚未保存的临时比较明确标注，退出不留草稿。

### 8.1 反求金额与时间

只在确定性基线、完整关键输入下反求。简化模式调整目标前适用区间的月净投入；旧阶段模式仅调整选定积累阶段。其他安排/收益/退休日期保持固定，界面明确调整范围；不能同时改变收入、生活费与停工时间却称求得单一答案。

采用简化基础模式时，反求变量为目标前适用区间的同一个月净投入条件，现有费用参考额、已知变化覆盖、退休预算/日期、养老及收益保持固定。用户未来投入未知不会单独阻塞求「需要多少」，但基础目标、资金起点未声明和非法输入仍会阻塞；费用包含关系未知使用额外计入的只读假设。求解结果不自动写成用户预计投入；不能通过缩小生活费或提高收益凑出答案。

基础反求固定目标退休月份与完整检查终点，候选从事实起点后适用积累区间投入，退休后不继续投入；每个候选按同一费用作用域归一化、调用完整月账本，再验证目标资金和全期支付。不能沿旧 `requiredSaving` 的恢复阶段逻辑在目标后接回未知工资，也不能随候选大小移动退休月份或缴费截止时间。FIRE/传统模式只控制明确预计投入后的预测行为，求目标需要多少时两者用同一固定目标条件。积累区间已不存在时给当前所需资金/差额或不适用说明，不除以0、搜索负月份或伪造未来投入能补今天支出。

基础需求另提供偏低与偏高收益条件反求：退休前/后实际收益各降低或提高 200 bps（2 个百分点），其余已确认预算、退休收入、费用、日期、金额基准与通胀条件固定。这是明确压力幅度，不是历史分位或真实概率；不把 2% 减至 0% 表述成降低 2%。结果列所设、偏低、偏高三组收益值；违反合法收益范围时说明不能应用，不暗中截断而仍声称降幅相同。`contributionReturnMatrix` 是候选投入/收益的结果网格，不代替三次最小需求求解。

所设收益的恒定路径不是资产分布的中位路径，反求金额也没有对应的五成成功保证。此轮不新增随机反求、行业收益校准或成功率目标输入；以后若按模拟达标比例反求，须另定种子、采样精度、搜索稳定性及预算判据，不复用确定性结果冒称保证。当前 `requiredSaving` 搜索非负候选，返回 0 表示无需新增正投入，不代表可额外提款；达到搜索上限仍未通过需说明范围或支付约束，不能解释成永久不可达。

明确正/零/负需求并展示口径：若起点已满足目标及期间约束，显示无需新增正投入；反求负数不得直接变成可消费额度建议。求解上限沿当前领域金额边界确定，不输出越界占位。只对经证明单调的变量区间用二分；每个候选仍调用相同完整账本，边界舍入后再验。

基础结果以整数分月投入为规范输出，年等值仅供阅读，不要求用户估计年度结余。若某期被已知变化覆盖，该期不参与调整；当前状态结束未知时可以给独立的长期条件要求，但不能声称同时解决当前衔接。后续年度原生输入另设明确精度规则，不反复转换改写原值。

每个候选都用完整联合时间线检查支付和已设置底线。同月月初付款不能用之后的投入补足；此时说明需要现有资金或延期，不输出任意大的月投入假答案。

首次可支付月份只在明示搜索时段内求解，超出显示该范围内未找到；未来退休条件动态变化时先固定停工条件，不能直接假定全局单调。候选达到边界后按整数分舍入并再跑完整验证；结果是条件性方案建议，采用仍需明确保存。

## 9. 读取、写入、恢复与删除

读取上下文至少含 generation、事实写版本、snapshot ID/修订、scenario ID/修订、参数/模型版本、today、模块状态。跨来源混合版本作废重读；共用批次结果提交后，各页面才刷新。

写入沿用 request_id/回执和 expected_revision；重复请求返回原结果，内容改变不得复用原请求。未知结果先核对回执。恢复/切库/模块关闭立即使旧请求与异步结果失效。

新增持久对象必须纳入规范 schema 校验、领域校验、完整备份/恢复、最近删除及引用检查；不只把 JSON 放前端本地缓存。基准结果存储是有意保存历史，普通即时计算不落盘冒充事实。

软删除来源：基准保留当时的资料并注明来源已删除；当前方案关联标失效，不按同日/同名重绑。恢复来源后核对原 ID 与修订。永久删除含基准原始资料的来源前，明确列出依赖，须先解除当前引用并删除相关基准；不能留下隐藏副本却宣称已彻底删除。

删除方案不连带删除真实物品/付款/盘点；已归档方案的基准可保留。删除发生记录需明确其引用方案的影响；撤销必须核对原实际来源，不自动回填余额或撤销物品生命周期。

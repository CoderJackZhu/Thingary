# 可选职业变化情景：实施与验收

状态：A、B 的共享准备与计算原型已实现，C 的独立虚构预览已完成浏览器范围验收，见[开发文档](DEVELOPMENT.md#职业变化情景原型)。D 已完成技术任务走查和表达改进，实际用户用途验证尚未完成；E 普通应用入口、持久化和安装后置。代码起点 `b6a58f167d7b81ead05be501a35c7b75cd454dc1`。本文件是本扩展的实施契约，基础规则沿 [PRODUCT_RULES](PRODUCT_RULES.md) 与 [数据规格](PLANNING_DATA_SCENARIOS_DESIGN.md)。

## 目标与边界

以一次收入变化、一段连续空窗、固定退休目标，回答空窗期间的资金不足，以及恢复后至目标前需要的月净投入。职业名称不进入公式；没有 35 岁、行业工资或失业概率默认值。基础界面和保存结构不增加职业字段。用户先给变化月、空窗长度及其收支；恢复后预计净投入可留空。

首批只提供独立开发预览，使用内存虚构资料，不调用原生服务或访问正式资料库，不进入普通应用导航与默认构建入口。预览用于核对结果和用途，不能冒称原生功能已验。用户用途验证完成后再决定正式可选入口；同意实施不自动意味着用途已验证。

## 计算契约

- 从同批 `PlanningSources` 只读编译，复用资金、预算、来源引用、发生事实、余债、费用包含与养老金资格。提取基础编译与求解的边界，保持基础导出行为；基础代码不依赖职业模块。
- 阶段为当前、空窗、恢复。日期按月，区间左闭右开；当前月按既有收盘日剩余天数处理。恢复月从变化月加空窗长度派生。未知恢复只计算明确检查期，不生成假复工日期；恢复不早于目标时反求不适用。
- 当前净投入复用已确认值；有当前积累区间而投入未知则不能虚构转变时资金。恢复净投入允许负数或未知；未知不妨碍反求。反求固定目标，不能由 FIRE 模式改变退休月。
- 每段独立确认已含/额外/排除的费用，沿同一稳定来源校验和编译；未发生费用不能当作当前净投入已含，已发生月供结束后参考额仍按所声明条件保留。空窗净流替换原储蓄，不叠加。
- 空窗完整支出单独输入，并扣除已含来源的参考额后与实际费用排期合并；负的剩余生活开销拒绝。普通开销按月初支付、可靠到账按月底计入，这是明确的时点假设，不是日级账单预测。
- 未来养老/公积金沿原已确认缴费起止范围，允许在空窗及恢复段明确继续、停缴或更换基数与月缴存；停缴不改变历史事实。现金自缴额单独确认是否已含，既不从个人账户入账反推，也不由净投入正负决定。养老金回调由新路径重算并门控资格。首批不调整个人养老金原有独立缴存区间，不自动推荐地区政策或待遇。
- 职业缴费覆盖只在本次目标前的相应阶段有效，不延长原缴费截止月，也不改变目标之后的原安排；停缴阶段同时停公积金，暂不支持两者独立停续。无法表达的安排须提示，不近似成已有路线。
- 付款检查只覆盖明确收支区间与已知付款；工作阶段只有净投入时不能称全程付款安全。共享账本提供可选月内余额审计，不另写现金引擎。参与资金的及时动用假设未确认时，保留长期条件需求而不提供现金安全结论。已知恢复前付款不足不能被未来候选投入修复。
- 所有金额遵守既有整数分输入和统一购买力基准；收益、费用和缴费在单次反求中固定。内部合法步长求解，代回检查；0只表示无需正投入，搜索上限未满足不等于永远无解。
- 结果分别标记长期目标需求、空窗资金检查、预计投入条件结果、未覆盖项和缺项。目标终点不向后外推。提供一项变化的对照，不把条件通过比例称概率。
- 退休预算、收入或目标缺失时，局部资金检查可仅编译积累区间；其内部编译不构成退休结论。恢复阶段的缺项或非法缴费只阻断依赖该阶段的结果；空窗或当前资金本身缺项仍阻断空窗检查。

## 验收矩阵

| 编号 | 必须验证的行为 |
|---|---|
| C01 | 无阶段变化时与基础同条件一致；输入对象、事实与既有来源不被修改 |
| C02 | 零收益手算、恢复后反求代回及少一分边界；预算变化确实改变需求 |
| C03 | 空窗替换原投入；已含月供不双扣、到期接续、首付不重复 |
| C04 | 明细月初支出/月末收入即使净额为零也可不足；仅净额不显示完整付款通过 |
| C05 | 恢复前缺口不可被候选收入补救；首个恢复月已知月初付款同样检查 |
| C06 | 停缴/继续/变更基数影响未来资格和账户，现金费用只扣一次；受限池不能支付提前费用 |
| C07 | 未知收入/开销/恢复/费用/缴费按能力阻断；未知投入仍可反求；零与未知不同 |
| C08 | 零空窗、非法月份、恢复超目标、首月比例、负投入、非零通胀、金额边界 |
| C09 | 来源 generation/revision 变化使旧结果失效；关闭/取消不保存，不进入基础消费者 |
| C10 | 只改单项条件的对照，显示差异且不合成为概率；不预填收益或职业行业值 |
| C11 | 虚构预览正常/未知/空白/错误、窄窗、键盘；浏览器证据不代表原生已验 |
| C12 | 明确记录用户用途验证是否完成，以及正式入口、保存、原生的未验状态 |

每步先跑相关测试；首批收尾运行 `npm run build`、`npm run test:ui`、`npm run check`、`npm test`。记录失败与未验事项，不借总测试数声称覆盖全部矩阵。保留其他工作树改动，不改根 `.gitignore`，不读取 `local.thingary.main`。

## 实现入口与后续执行

`plan-basic.ts:prepareBasicPlan` 提供来源归一化与只读编译，原 `buildBasicCapabilities` 保持通用入口；`plan-pension-path.ts` 编译临时缴费覆盖，`plan-ledger.ts:project` 的可选观察回调返回月内余额。`plan-career-contract.ts` 与 `plan-career.ts` 定义职业条件和各项结果，`plan-career-compare.ts` 仅改变一个条件。`src/career-preview/` 是虚构展示适配器，`tests/plan-career.test.mjs` 对真实来源形态到结果的路径验收。

D 使用同一虚构基线完成三项任务：只延长空窗、只降低恢复后投入、只提高退休预算。记录用户能否辨别“需求”与“预计投入”、能否说出付款覆盖范围，以及相较分别使用当前承受能力和通用反求减少了哪些手工步骤；困惑优先通过说明和简化修复。没有这项观察，不把自动测试通过视为有用性已成立。

走查后的表达：改变恢复预计投入时，首要差异是目标时点资金；固定目标及预算意味着所需投入不变，不能把需求差额为零当作没有影响。任一组预计投入未知时，提示先确认两组金额，不虚构资产差额。空窗和预算对照显示所需投入增加／减少；两组详细结果仍保留独立的付款范围和缺项。初步手工衔接同一虚构起点与通用反求能得到相同结果，仅支持计算一致性与步骤衔接可行，不作为用户体验优越的证据。

E 仅在 D 支持继续时接入现有规划页内的主动入口，沿同批来源、revision/generation 与读取生命周期失效，关闭即丢弃本次条件。先复用事实，再按需确认阶段费用和缴费；不把开发预览的演示数值带入正式界面。E 需逐项验证正常、未知、错误、切库／更正后的失效、取消不写和默认界面一致，并使用隔离身份完成原生验收。若以后要求保存条件，须先补独立版本化载荷、事实引用与失效规则，再评审迁移和回执；首批不预留基础模型字段。

## 窗口地图与社保方案（扩展，仍是独立虚构预览）

在同一计算上叠一层只读函数（`plan-career-map.ts`），不改基础规则，不预测收入：

- **窗口地图**：横轴是高收入窗口关闭的月份，纵轴是关闭后每月净投入，每格只显示原目标是否满足、缺口或先不够的原因（目标、空窗中现金、已知付款）；不加权、不称概率。
- **最少窗口**：给定关闭后条件，原目标不再依赖窗口所需的最早关闭月；仅当现在的投入高于关闭后的投入时有定义。零收益、关闭后不再投入时与闭式 (所需资产−起点资金)÷月投入 一致。
- **最长空窗**：给定变化月和关闭后投入，资金不触底线且原目标仍满足的最长空窗月数，并说明先到的限制；仅当空窗期净流入不高于恢复后投入时有定义。
- **社保方案对比**：同一情景只替换空窗期或恢复后的缴费安排（停缴、所选下限、原基数、沿用原安排），并排显示用户填的每月现金、这段合计、目标时月养老金与资格、目标时资产；“回本”不计上调和利息。医保、等待期、失业待遇不在此核实。
- **补偿金与限期补助**：空窗期可选的用户输入，一次性到账记变化月月底，限期补助在前 N 个月每月月底到账；留空即没有，不查政策、不给默认值。

- **推迟退休让步**：条件下原目标满足不了时，逐岁向后扫描最早满足的退休岁数，与原目标并排显示，不写回目标；养老金缴费仍按已确认的原安排。后续投入为负时更晚的目标可能更差，所以是逐岁扫描而非二分。
- **养老金资格成本**：停缴后离按月领取资格还差多少个月，以及按用户填的“灵活就业自缴”每月现金补齐大约要花多少。
- **按问题进入**：预览按三个问题组织——“现在离开能休息多久”“再做多久可以降低投入”“换工作后每月至少要攒多少”；每个问题只要它需要的条件，窗口地图和详细对照放在结果之后。界面用“每月能攒多少”（收入拿到手、扣完全部花销后每月剩下的钱）代替“净投入”。
- **已核实的社保规则（2026-10-08 官方原文）**：按月领取基本养老金的最低缴费年限从 2030-01-01 起由 15 年逐步提高到 20 年，每年提高 6 个月（国务院渐进式延迟法定退休年龄办法）；北京灵活就业职工医保首次参保 6 个月后享受待遇，断缴 3 个月内足额补缴视为连续，超过 3 个月视为初次参保重新等 6 个月（首都之窗·北京市医疗保障局，2025-07-09）；失业保险金条件含“失业前用人单位和本人已缴纳失业保险费满一年”，领取期间职工医保费由失业保险基金缴纳（北京市失业保险金申领发放实施办法（试行））。**未核实**：灵活就业自缴的失业保险能否领失业金、退休后医保累计缴费年限要求。

验收：闭式核对、地图与单次评估一致、窗口越晚关闭缺口不增大、最长空窗代回、输入与来源不被修改（`tests/plan-career-map.test.mjs`）。预览新增“含北京养老金（虚构）”样例以显示养老金列。

## 退出与回退

没有新增存储字段或迁移；普通应用未引用预览。共享准备/审计是通用内部能力，职业编译和预览可独立移除。若无法让用户区分条件需求与收入预测，先修解释或进一步缩小输出；若现有工具已能同样清楚完成任务，改进工具衔接而不增加重复入口。

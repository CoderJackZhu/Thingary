# 虚拟资产标签与计费设计

状态：已实现，已独立复审修复，纳入 2026-10-05 重建的 0.0.1 Beta，原生完整交互验收尚未闭环。2026-10-06 的单次使用结束修复已通过隔离原生保存、重开、筛选、金额保留和重启验收；每期付款提前天数排列已检查，其他既有功能仍按原验收边界记录。本文描述目标行为与技术取舍；有效规则已归入 [PRODUCT_RULES](PRODUCT_RULES.md)（“虚拟标签、计费方式与储值”小节），操作归入 [USER_GUIDE](USER_GUIDE.md)（“标签、计费方式与储值”小节）。本次公开包包含这些功能；发布不表示原生完整交互验收已通过。

## 1. 目标与范围

用户录入 GPT 月订阅时，应能直接填每月价格、开始使用日期，看到累计估算；持续续费无需猜测最终结束日期。历史订阅填真实结束日即自动显示已结束。房租继续通过周期费用管理，能表达每月预付下月租金、固定一年季付，不要求重复建立虚拟资产。

本次覆盖：虚拟标签、独立计费方式、订阅默认值、自然日历与固定天数、免费试用、本期特殊到期、后续续费价格、自选提醒、按充值投入的储值档案及相关兼容迁移。复用既有虚拟资产和周期费用入口，不增加一级导航。

逐次消费流水、自动扣款／抓取平台账单、账号与激活码、汇率、按量成本不属于本次。支付方式只作为可选文字备注，不建支付账户系统；永久权益通过单次购买表达，不设“终身订阅周期”。

## 2. 标签、现有分类与计费方式

“虚拟分类”在本次界面统一称为“标签”，复用现有标签体系；不另建一套虚拟分类目录。现有实物分类仍用于物品主分组，本次不迁移、删除或改名实物分类。

| 概念 | 回答的问题 | 存储与界面约束 |
|---|---|---|
| 标签 | 这项东西属于哪个自定义分组 | 复用 `named_choices(kind='label')` 的稳定 ID 和管理操作 |
| 标签适用范围 | 在哪些档案里可选 | 实物、虚拟、通用；通用标签使用同一个 ID |
| 计费方式 | 投入怎样计算 | 单次购买、订阅、储值；独立字段，不能由标签名称推断 |
| 系统状态 | 是否开始、有效、结束或停用 | 按日期与既有事实推导，不作为可手填标签 |

每条虚拟档案本轮保留一个可空标签，与现有实物单标签习惯一致；不扩大成层级标签或多标签项目。设置沿用“标签”入口，提供适用范围筛选和分域引用数量。在实物创建的新标签默认实物，在虚拟创建的默认虚拟；管理中可明确改为通用。标签名可自定义、不预置业务分类；同名校验沿用现有标签名称政策，不偷偷创建两个同名 ID。

旧标签 ID、名称、排序、启停、实物引用保持，迁移只补上“实物”适用范围。希望复用旧标签时将其设为通用。列表按当前领域过滤可选标签，已选但停用／范围改变的标签仍可读，不能静默清空；范围收窄前须处理另一领域引用，事务整体成功才修改。改名两域同步显示；删除须统计含最近删除的所有引用，并明确迁移至兼容标签或清空，不能只改 `asset_preferences`。

既有“标签投入分析”仍只聚合实物生命周期成本，通用标签关联虚拟资产也不把订阅费用加入实物分析。金融账户类型、投资收益计算不被标签替代；本轮不新增金融账户标签或跨域总资产汇总。

旧 `kind=license/domain/subscription` 是业务类型，不再充当新档案计费方式。迁移保留原值与既有显示，新增显式计费字段；域名可采用单次或周期计费。新表单以计费方式为主，标签可空。旧买断软件、域名、独立订阅都能继续编辑，原类型不被改名标签覆盖。

不对应上述旧类型的新档案采用中性通用类型，由迁移扩展合法取值；界面不强迫用户再选一次类型，也不借 `subscription` 冒充储值。旧类型仅在已有档案的补充资料中保留。

## 3. 三种计费方式

| 方式 | 基础必填 | 可选 | 累计投入 |
|---|---|---|---|
| 单次购买 | 名称 | 标签、实付金额、购买日期、有效至、提供方、支付方式、链接、备注 | 已知单次实付；未知金额不视为零 |
| 订阅 | 名称、每期价格、开始使用日期、周期 | 标签、最终结束日及高级设置 | 计划估算与明确确认的付款分别显示 |
| 储值 | 名称 | 标签、首次充值及后续充值、额度、到期日、提供方等 | 累计已知实付充值；赠送不计投入 |

新建虚拟档案默认订阅，每月、自动续费开启、无最终结束日期、试用关闭、提醒关闭。已有档案打开时完全使用其已保存方式，不能重新套新建默认值。

单次购买可明确结束使用并填结束日期，使用既有停用事实；界面显示“已结束使用”，有效期位置显示实际使用结束日，历史支出不受影响。购买日期过去不自动结束，一次性事项不必设置伪造的到期日。

单次购买有效期空值的旧语义保留：买断软件永久有效、域名待补充、旧独立订阅持续使用。新建普通单次购买无结束日显示“未设置有效期”，可明确选择“永久有效”，避免无期限自动等同永久；这一区别用新字段表达，不能靠改旧空值实现。储值无到期日表示未设置，不能推断商家承诺永久。

## 4. 订阅日期与周期

### 4.1 四类日期

| 日期 | 含义 | 默认值 |
|---|---|---|
| 开始使用日期 | 整项服务的开始，可以是历史日期 | 今天 |
| 计费开始日期 | 首个付费期的开始；免费试用会向后推 | 开始日，或试用结束的次日 |
| 本期服务起止 | 某一期的覆盖区间，包含末日 | 根据周期计算，作为明确的只读摘要 |
| 最后使用日期 | 整项服务真正终止的末日 | 空，表示持续进行 |

付款日期独立于服务日期。新订阅默认在每期服务起点付款，基础区域显示推算的下次付款；修改付款排期在高级区域，不要求用户录入一个未来日期才能创建历史订阅。历史排期锚点保存首个付费期日期，不能把滚动的“下次付款”写回锚点。

服务末日包括当天，`today > 最后使用日期` 才结束；开始日在未来显示未开始。缺少付款记录不说明服务停用或到期。过去付款日不说明服务已经结束。结束日早于开始日为字段错误，未知结束日保持空值。

### 4.2 日历周期与固定天数

基础周期为自然月／季／半年／年，默认自然月；保留现有半年能力。自然月不是 30 天，年不是 365 天。第 k 期始日从原始锚点加 k×月数计算，不逐月从短月结果累加：1 月 31 日、2 月 28 日、3 月 31 日。每期末日是下一期始日前一天，最终一期截断至服务结束日，不自动按天打折。

高级区提供固定天数：7、30、90、365 或自定义 1–3650 天，并明确写“固定 N 天”。第 k 期从原始锚点加 k×N 天；闰年与时区／夏令时不改变自然日计数。日期加减使用日期类型，不以本机毫秒时长除以 24 小时推算。

新自然月字段与现有 `interval_months` 保持映射；新增独立周期类型和天数字段，不能拿 `interval_months=0` 作隐含标记。读旧计划继续走原语义，只有明确编辑新配置才采用新规则。

### 4.3 自动续费、暂停与终止

基础区“自动续费”默认开，并提供可空“最后使用日期”。开启且无结束日：持续续费；开启且有结束日：在该日内按周期续费。关闭：展开“使用至”，建议当前推算服务期末，用户确认保存后成为明确结束日；已知已付覆盖可作建议来源，但不能因为未记付款把服务判为无效。

未手改的表单建议随开始日、周期和试用即时更新；手填或已保存的结束日期保持原样。重新开启续费只清除本次尚未手改的自动建议，不清除已有明确终止日。

不增加“已经结束”手动选项，统一由日期判断。关闭自动续费不记录退款、付款或平台取消动作。未开始即关闭时建议首期末；本期末未知时必须填写截止日，不虚构一个已付期。

旧 `paused` 表示暂停排期，保留其原义，不批量转成自动续费关闭或补出终止日。旧暂停显示“已暂停排期”；恢复沿用现行从当天恢复且不补暂停待确认。新基础自动续费与旧高级暂停是不同字段，界面解释清楚，不用同一个开关双写。

### 4.4 免费试用

默认关闭，打开后默认 7 天。试用 N 天从开始日计入第一天，试用末日＝开始日＋N−1，计费起点＝开始日＋N。允许明确调整计费开始日，但必须晚于试用末日；中间空档不假设为免费服务或产生收费。开始日改变只联动未手动调整的计费日期。

默认付费锚点从计费开始日建立；试用期不计入付费期数、累计估算、固定负担或重要支出。试用内服务已结束时估算为零，不安排首笔收费。试用开关不自动生成“已付零元”记录，也不改历史付款。

手动推迟计费形成空档时，显示“试用已结束，计费尚未开始”，不把空档显示为当前已付服务期；是否仍可使用不由费用记录推断。固定负担展示带“计费开始于某日”说明，未来 12 个月预测只计入实际收费安排。

### 4.5 本期特殊到期与续费价格

本期特殊到期日放高级区，明确对应的期 ID／原始期始日，不能只存一个无归属全局日期。覆盖末日调整只影响未确认的目标期及后续预测，不重写已确认覆盖；与下期相连时重新建立后续锚点并保存规则生效期，历史仍按原锚点。日期早于本期开始、超过最终结束日或造成重叠时拒绝并定位字段。

后续续费价格可空，空则沿用本期价格；填写时显示生效期，默认从下一期开始。保存为价格分段，不回写历史 `plan_rates` 或实际付款金额。取消该设置只取消尚未生效的未来价格；已生效部分仍保留历史。周期、试用、锚点更正同样要保留生效区间，不能仅给新字段就让历史估算全部漂移。

已存在付款与目标新排期不一致时，保留付款事实并显示“与当前排期不同”，让用户单独更正，不自动移走付款日期、覆盖期或期 ID。未保存计划修改时禁用历史范围补记，两个入口保持一致。

## 5. 费用展示与历史补记

| 指标 | 来源 | 是否进入重要支出／金融净资产 |
|---|---|---|
| 累计费用（估算） | 服务起止、付费周期、价格／排期历史 | 不进入 |
| 已记录支出 | 单次实付、用户确认付款、实付充值 | 只进入重要支出；不直接扣金融账户 |
| 月均／年化负担 | 当前有效付费安排 | 只作计划，免费试用期间不显示为当前实付 |
| 储值赠送与额度 | 充值实付＋赠送、或明确额度事实 | 不进入支出与金融净资产 |

订阅按已经开始的付费期累计整期价格，截止今天或服务结束日取较早者；最后一期服务截短不自动减价。对未开始和试用内无付费期者估算为零。初次录入的历史价格未知时用所填价格估算，并显式说明这一假设；后续调价／排期变更按分段规则计算。

已记录支出为零且没有付款事实时，显示“未记录付款”，不把它写成“总共花费 0 元”。明确已付零元和未记录需通过事实数区分。列表主金额订阅标“估算”，详情邻近显示已记录支出与未确认说明；单次、储值主金额为实付，不加估算标记。

历史范围补记保留独立操作：明确确认确实已付，填写期间和每期实付；价格不同可分段提交。已有 paid／skipped 和覆盖期保持，不重复生成；试用阶段排除、终止后的期排除。预览期数／合计必须与保存完全一致，范围上限和处理复杂度受控。补记失败／结果未知先查回执，不重做。

固定天数的月均／年化只作换算：年化为每期金额×365÷N、月均为年化÷12，用整数有理数一次舍入到分，并注明按 365 天折算。未来 12 个月预测逐期按实际日期枚举，不能拿年化替代。免费试用若跨越预测期，预测只计入收费期。

## 6. 储值：按充值投入

不引入“按消费记录”开关。首次充值与后续充值共用同一事实结构：充值日、可空实付、赠送（默认无赠送）、可选到账额度、支付方式和备注。首次金额不明时允许先建档案；无充值输入就不造一条金额为零的事实。

实付 150 元＋赠送 50 元，默认本次到账 200 元、累计投入 150 元。到账额度默认实付＋赠送，允许用户明确修正用于折扣充值，并提示“额度不等于支付成本”。实付未知时投入待补充，不能倒推“额度−赠送”冒充实付；只有赠送且明确未支付时实付填零，和未知区分。

充值实付是唯一支出来源，每条充值独立稳定 ID，按充值日期进入重要支出；赠送不进入，档案另一个价格字段不得再次计入。未知充值日的已知实付列入日期待补充，不归入今天。部分实付未知时累计显示“仅已知部分”和待补充笔数，无任何已知值时显示未知；无充值记录显示“尚未记录充值”。

累计到账额度不是当前剩余余额。本轮不推算消费：详情可选手动记录“剩余额度／记录日期”，用于低频盘点；显示“截至某日”，不自动用累计到账减出余额，也不自动补上后续充值。历史余额更正不产生支出，充值更正也不悄悄改动已记录余额；提示余额记录日期以便用户判断是否需更新。额度只支持人民币金额，不引入点数／次数转换。

到期日可空，日期过去自动到期；额度到期不退回累计实付、不写退款。停用不删除充值；储值档案删除带入最近删除，相关实付暂不参加当前支出，恢复原 ID 后恢复同一事实；永久删除按现有确认规则处理父子关系。

## 7. 提醒：用户选择一次，再按明确规则运行

订阅新增与旧数据迁移均默认关闭续期提醒。每期结束仍可在详情看见，但不每个月生成到期警报、侧栏红点或“待确认付款”干扰；期末、下次付款、通知是三个独立概念。房租及其他周期费用原有付款提醒保持。

高级区或虚拟订阅详情打开“备款提醒”，可选“每期提醒”或“仅本次”；新版订阅首次选择默认每期、扣款前 3 天，可选 0–30 天，开关仍默认关闭。既有提醒保持单次。单次日期默认建议当前待续期日前 3 天，若建议已过则建议今天。只有用户开启时才按既有通知权限流程申请，拒绝权限时保留设置并说明未能通知，不能显示已安排成功。

按 2026-10-05 用户决定，每期自动提醒，确认已付后转到下一期。当前／未来未记录付款期与直接付款入口共用推导，排除已有 paid／skipped，历史漏记不重现为本期待办。按期减去提前天数，稳定源 ID 加付款日形成通知 ID；预安排未来 12 个月内的扣款期，打开或写入时补充。虚拟列表与详情提供确认本期／下期已付，复用已有实际付款表单与回执；只记录真实扣款，向付款账户备款不产生订阅支出。

单次提醒修改日期替换原提醒；每期提醒修改提前天数替换对应安排。关闭、停用、到期、删除、模块关闭、资料库切换时撤销待通知；自动续费关闭或排期暂停时暂停每期提醒。历史结束记录、过去提醒日不补发；已过提醒日期显示已过，可主动重新设置。

有效性临近标签不等于主动提醒：持续续费订阅不显示周期性的“即将到期”；有最终结束日的订阅保留到期日期与状态，默认不进入订阅待办／红点，主动提醒以开关为准。旧单次域名等既有到期状态维持，储值默认无主动提醒，不能把所有虚拟状态直接合并为警报数。

复用 `reminders`／原生通知通道，扩展合法 kind、查询、撤销与备份验证，保留保障／心愿的现有行为。提醒以稳定源 ID 与资料库身份防止重建重复、旧异步计划覆盖新状态；样例模式不能替换自己的提醒。原生时间沿用现有调度，不另建通知框架。

## 8. 桌面交互与列表

基础区同屏提供名称、标签、计费方式；订阅显示每期价格、周期、开始日、自动续费及可选最后使用日期，并即时显示本期／计费开始／下一付款摘要。无需展开就能理解一个普通 GPT 月订阅。

```text
新增虚拟资产                            保存  关闭
名称              GPT Plus
标签              AI 工具       管理标签
计费方式          单次购买 | 订阅 | 储值
每期价格          ¥140          周期：每月
开始使用          2024-01-20
自动续费          开启          最后使用：未指定
本期：…至…；下次付款：…；持续续费
▸ 试用与更多订阅设置
  免费试用 / 固定天数 / 付款安排 / 本期特殊到期
  后续续费价格 / 备款提醒（每期或仅本次） / 支付方式
▸ 档案补充：提供方 / 链接 / 备注
```

高级设置一层展开，不能再层层叠套。切换计费方式前提示已有付款／充值约束；已有事实的跨模式转换本轮不提供一键重解释，保存拒绝丢弃事实并引导新建或保留原方式。未提交的新建表单切换可保留本次输入，但只提交选中方式，关闭即丢弃普通未保存输入。

虚拟页筛选：全部／标签／计费方式／状态；标签支持未设置。表头可排序名称、开始／购入日期、每期价格或单次金额、结束日期、累计费用，未知置后，稳定 ID 打破同值，完整筛选后排序再分页。持续权益的最终结束空值置后，不能用本期末当最终结束参与排序。

保留虚拟页当前默认名称升序；“类型”列改为清楚的“计费方式”，仍可点击双向排序。不另加重复的上方排序下拉，筛选／搜索仅影响列表，不改变整库汇总。

混合列表金额标题为“费用”，单元格明确 `¥140／月`、`¥150 单次` 或 `实付 ¥150`；该列按未年化的原始金额排序，并在标题说明周期不同不代表负担可比。累计费用按各方式对应的估算或实际投入排序，并给每格明确标记。金额无确切单一可比值时不把它排成零。详情可看各期价格及事实记录，不用汇总掩盖付款是否已确认。

复用 `ChoiceField`、`CentInput`、`DateInput`、表头排序、侧栏与现有主题。浮层通过现有 portal／定位组件避免裁剪，正常宽度及窄窗口均不靠横向滚动才能看到操作。Tab 顺序、错误定位、Esc、中文输入、菜单键盘可操作；三种风格×浅深色一致。

## 9. 数据、接口与一致性

以下是目标数据职责，SQL／Rust／TS 最终命名由实现统一决定；不得靠前端拼接字段绕过后端约束。

| 数据职责 | 建议落点 | 不变量 |
|---|---|---|
| 标签范围 | 与 `named_choices` 关联的标签专用范围表 | 仅合法 label ID，范围收窄／删除事务覆盖两域 |
| 虚拟标签 | `virtual_assets` 可空 label ID 或独立关联表 | 每档案最多一个，不更换旧档案 ID |
| 计费配置 | 虚拟计费扩展，与旧 kind 分离 | 模式与计划／充值／旧单次价格约束明确 |
| 新订阅配置与分段 | 关联唯一计划的扩展、规则与价格历史 | 服务与付款锚点分开，分段不重写事实 |
| 充值事实 | 独立 `virtual_topups` 等领域表 | stable ID、修订、整数分、可空未知值、父子生命周期 |
| 余额记录 | 明确金额和日期的可选记录 | 是盘点值，不作为支出、不推算消耗 |
| 备款提醒 | 既有提醒系统扩展 | opt-in，每期或单次，撤销与 generation 一致 |

旧记录的模式映射：有已关联计划→订阅／关联周期方式；无计划→单次投入，包括旧 `kind=subscription`。不得仅看名字或 kind 把旧价格转月费。带计划的域名仍保持原有效期推算路径，明确编辑后才能采用新订阅配置。旧独立订阅保留“持续使用但价格是单次投入”的提示。

字段验证复用现有金额与文本上限：单项金额 0–99999999999 分，付费订阅每期金额须大于零，免费阶段通过试用表达。充值赠送、到账与余额不得为负；累计用整数并检查溢出。首次充值日期默认今天且可清空，充值事实日期不能在未来；未来计划不要伪装成实际充值。新试用天数采用 1–3650 天，日期与周期越界给字段错误，不自动截断。

权益与计划／首次充值／标签引用在一次保存事务和同一请求回执中维护，独立补充值也是一次事务；修订冲突全部失败，不能先保存档案再补计划。保存结果未知要查回执；重复请求同 payload 返回原结果、不同 payload 拒绝。编辑、新建、删除、恢复都受 generation 约束。

重要支出新增充值来源需要同步来源跳转和去重：来源 ID 为充值事实 ID，跳转定位父档案＋对应充值，过滤／分页外也应可找到。订阅继续来自原 payment 事实，单次继续来自原档案价格。虚拟／周期／支出／标签管理及总览缓存联动失效，不让旧响应覆盖恢复后的新库。

## 10. 升级与备份

当前基线 schema 21；实现依次迁移至 22、23、24（应用版本仍为 0.0.1）。24 保存独立自动续费状态，以及每段的付款锚点、服务开始日和试用信息；22→23 正确保留固定天数。付款候选／补记／估算共用生效规则；外键校验在提交前完成，失败回滚并恢复连接设置。使用增量版本迁移，版本号根据实现起点分配；继续发布 0.0.1 不代表可以重置 schema。迁移前保护副本、事务／故障钩子、失败可重试沿用现有机制。

配件迁移为 schema 25；当前源码未发布的每期备款提醒迁移至 26，只补提醒模式与提前天数。旧单次提醒和旧待核对保存请求的序列化指纹保持不变，新模式仍须用户主动开启。

旧金额、日期、ID、类型、修订、价格历史、付款与 skipped、图片、软删除关系和停用状态保持原义；默认值只补到新字段。旧标签补范围且不改关联。读旧数据不自动生成充值、付款、试用或提醒。新建默认值只在新建表单应用。

备份不仅要把新表放进 SQLite，还须更新规范 schema 定义、`validate_dataset`、引用约束、manifest schema、inspect 摘要与恢复检查。覆盖旧 schema 17／19／20／21 的备份恢复及新 schema 全量 round-trip，尤其独立订阅、有计划域名、最近删除、停用标签、提醒 kind。更高版本备份被旧版拒绝，应提示需新版本；不承诺降级应用可直接读新库。

升级保证是“旧事实保持且新功能可用”，需要隔离的虚构旧库证明；不能通过检查真实用户库完成验收，也不能把构建成功写成旧数据无风险。

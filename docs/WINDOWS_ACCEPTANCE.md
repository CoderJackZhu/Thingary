# Windows 候选版验收

本页维护 Windows 的固定验收方法与支持边界；逐次结果、截图和日志另行保存。使用者安装见[使用指南](USER_GUIDE.md#windows-install)，构建见[开发说明](DEVELOPMENT.md#windows-validation)，候选包核验与发布见[发布流程](RELEASING.md)。

## 当前范围

源码版本为 **0.0.7 候选**，目标 Windows 10 1809+／Windows 11 x64，尚无公开 Windows Release。Mac 公开版仍为 0.0.6；Windows 接入基线为 schema 40；当前候选的账户类型与目标迁移已至 schema 42。`.thingary` 容器格式、整数分、未知值、稳定 ID 与业务导航保持既定语义。

检查结果统一维护在[开发说明](DEVELOPMENT.md#windows-validation)。源码接入与 Mac 自动检查不代表 Windows 原生运行、可见通知、人工安装与文件对话框、微软拼音、讲述人、Windows 10 或真实 x64 通过；每次按实际结果登记，不从脚本存在推定完成。

自动工程检查使用 GitHub `macos-latest`／`windows-latest`；NSIS release 构建使用 `windows-latest` x64，已安装隔离包验收使用标准托管 `windows-11-arm`，x64 程序经 Windows 模拟运行。运行器系统与模拟架构必须写入结果，不能冒充真实 x64 设备、性能测试或所有 Windows 版本的验收。[运行器官方范围](https://docs.github.com/en/actions/reference/runners/github-hosted-runners)可能调整，每次以实际任务环境为准。

## 数据隔离与准备

1. 检查分支、完整源码 SHA、工作树与候选版本。所有数据和图片均为虚构，不使用个人档案或真实备份，**不得打开或写入 `local.thingary.main`**。
2. 在 Windows 准备 Node.js 22、Rust stable MSVC x64、C++ Build Tools／Windows SDK、WebView2 与 PowerShell 7。安装锁定依赖并准备 Cargo 缓存，许可收集必须能离线完成。
3. 使用 `npm run build:win:acceptance` 构建 `local.thingary.win.acceptance` 的 debug NSIS。其标题为“物谱 · Windows 验收”，带 fault-injection 和仅 loopback 的 CDP 9227；只用于本次虚构验收，不是普通安装包。
4. 核对 `%LOCALAPPDATA%\local.thingary.win.acceptance`、`%APPDATA%\local.thingary.win.acceptance` 均未存在。若已有结果先保全，不让脚本删除或覆盖它们；按开发说明给构建、静态核验和完整脚本传入同一新身份后缀，并使用新的输出目录；不清除旧资料。
5. 安装后核对开始菜单 `Thingary Windows Acceptance` 快捷方式、AUMID、安装目录 `许可/BUILD_INFO.json` 的身份／源码 SHA／版本／许可散列一致，才启动。正式身份 release 候选包只构建与静态核验。

## 自动工程与包核验

| 检查 | 合格条件 |
|---|---|
| 四项回归 | 两平台分别执行 `npm run build`、`test:ui`、`check`、`test`，结果与源码 SHA 对应 |
| 双向备份 | `ci.yml` 互换虚构 `.thingary`，恢复后 schema、57 张表计数与 8 个托管原图 SHA-256 全部一致；Mac→Windows 和 Windows→Mac 各自通过 |
| Windows 文件边界 | 短暂／持续占用、明确错误保全、恢复清理顺序、中文／长路径、名称代理 reparse point／junction 拒绝、非名称代理云文件标签放行与故障恢复回归通过 |
| 图片 | JPEG／PNG／WebP、方向、损坏与解码限界；HEIC／HEIF 明确拒绝，不静默丢图 |
| 安装包静态检查 | x64 PE、版本／身份、许可全文与散列、源码锚点、`longPathAware`、`asInvoker`、未签名，包内没有资料或测试夹具 |

在 Windows 执行：

```sh
node scripts/verify-windows-package.mjs --acceptance
pwsh -NoProfile -File scripts/windows-native-acceptance.ps1
```

脚本先安装隔离包再检查已安装窗口；生成 `.local/windows-native-acceptance/summary.json`、分项结果、日志与截图。输出目录必须全新，可用 `-ArtifactRoot` 指定新目录；可用 `-FixtureArchive` 指定另一平台生成的虚构完整备份。脚本失败时保留失败证据，不把 `status=failed` 的附件当已验包。静默流程覆盖默认安装与卸载，不能证明交互勾选框、SmartScreen 或手工原生选择器已经通过。

脚本检查保存／取消／重启、第二次启动不产生重复主实例、恢复夹具界面、实际通知排队／移除与系统历史送达、默认卸载每个数据文件散列不变及重装。恢复夹具的表计数与图片散列和 UI 可见内容分别核对；生成截图不等于人工视觉复核通过。

自动截图的窗口尺寸检查还受系统「显示缩放」和「辅助功能 → 文本大小」共同影响；执行前分别记录两项，不把显示缩放 100% 推定为文本大小 100%。当前固定尺寸 fixture 在两项均为 100% 时已通过真实 x64 检查；其他组合出现尺寸等待超时，应保留失败结果，不能用单独重跑 fixture 的成功覆盖整轮失败。产品在其他缩放下的交互仍按 N8 另验。

## 原生交互与同尺寸对照

使用安装后的隔离包，每项分别记录环境、预期、实际、证据和未验范围。

- 首次样例 → 空个人库 → 物品保存／取消 → 账户／完整盘点 → 收入／资金流动／投资核对 → 目标／报告 → 备份／恢复 → 重启核对。金额未知和日期未知保持空白，明确零保持零，图片与关系不丢失。
- 原生选择器逐项核对选图、`.thingary`、`.xlsx`、文件夹及另存为，成功、取消、中文路径与不可访问路径；打开备份目录及更新检查，含断网分支。
- 窗口首次尺寸、记忆、最大化／最小化不覆盖普通尺寸；第二次启动只有一个主实例；多屏与 100%／125%／150% 缩放分别核对。
- Ctrl+N／E／F／Shift+F／,／Shift+D／A／Z、Ctrl 点击／Shift 点击和 Escape。文本框的全选／撤销与右键剪贴板菜单有效；页面背景不出现浏览器菜单；F5、Ctrl+R／P／加减号不触发浏览器刷新、打印或缩放。
- Windows 空闲 X／Alt+F4 退出；物品等普通编辑表单、页面拥有表单／功能设置／数据任务提示先完成或取消、保存过程中等待。已保留未知回执可以退出，重启后核对原请求，不重放输入。
- 微软拼音分别在搜索、金额相邻文字和表单名称中组合输入，检查 Enter／Escape 不误提交／误关闭；讲述人检查标题、标签、对话框、错误与焦点顺序。未经实际操作不能以按键模拟替代 IME／无障碍验收。
- 三种外观 × 浅／深，Windows 与 Mac 在相同逻辑内容尺寸 1600×1000 和 800×600 对照，另抽查 900×720；记录 DPI 和窗口实际内容区。覆盖正常、未知、空白、读取失败、保存失败；表格内部滚动、按钮焦点、字体和滚动条无截断。截图需稳定后人工检查，WebView 的 DOM 图不冒充系统桌面捕获。

### N1–N12 固定清单

每项在仓库外的验收报告记录「通过／失败／未做」、操作者、证据文件名、环境与复现步骤。未做或只完成部分时明确写「未验证」及原因；浏览器截图不能证明原生能力。实体键盘与通知目视由使用者完成；普通文件面板在用户明确授权后可由代理操作。登录、SmartScreen 放行和交互安装向导不可由代理代操作。

当前真实 x64 已完成五类原生文件对话框的成功／取消、中文带空格路径与父窗口模态检查；微软拼音在搜索、物品名称、备注中的 Esc／Enter 检查通过。用户使用讲述人检查侧栏、物品列表、新增表单和图标弹窗，读名、Tab 焦点与关闭后焦点返回通过。Windows 三风格 × 浅深 × 两种内容尺寸的 12 张原生窗口图已检查；同内容 macOS 对照仍未验证。单屏 100%／125%／150% 与重启后窗口可见已检查，多屏未验证。

带浏览器来源标记的基线隔离包 SmartScreen 放行与当前用户交互安装获用户确认：无需管理员权限、安装成功、开始菜单有入口；未留原生截图，因此只有用户反馈与下载标记证据。本地修复隔离包的安装身份与源码 SHA 已核对。用户确认人工卸载的删除数据选项默认不勾选；保持不勾选卸载、重装后，正常 Windows 会话中的全部资料文件散列一致，快捷方式 AUMID 正确。系统通知历史送达另有自动证据；缺 Runtime 与 OneDrive 场景仍需独立验证。

N3 当前隔离候选已在真实 x64 的正常用户会话复验：业务心愿首次排期、跨真实 GUI 60 秒刷新截止不变、应用退出后同 Group／Tag／XML 进入 `owned_history` 通过。用户确认关闭免打扰后显示右下角横幅；标题含心愿名称，当前心愿提醒正文为空。旧候选点击该提醒没有打开应用，定位为 unpackaged 应用缺少 toast 激活注册；当前源码启动时登记 `CustomActivator`／`LocalServer32`／快捷方式 `ToastActivatorCLSID` 并注册进程内 `INotificationActivationCallback`，机器侧已验证注册表写入、跨进程 `Activate` 唤起运行实例与关闭状态下经 `LocalServer32` 冷启动拉起进程，多轮唯一虚构名提醒按 120 秒截止准点进入系统历史。勿打扰开启期间横幅不显示但历史送达不受影响；用户已在通知中心实际点击含唯一虚构名的物谱通知，点击时应用为关闭状态，由通知平台经 LocalServer32 激活注册拉起进程（命令行含 -ToastActivated -Embedding）并显示窗口，通知唤起人工验收通过。系统通知列表已有验收身份；禁用时应用明确提示通知未开启，两条心愿的日期与提醒选项仍保存，重新允许后通知状态恢复正常。旧轮未见通知及不同资料副本的失败证据保留，不用新通过覆盖它们。

N3 的 120 秒验收延迟在同一进程内固定未改变计划的首次截止，过期也不重新计时；修改计划或重新加入才启动新计时。`inspect` 的 `history` 只包含固定测试夹具，业务心愿应关联 `owned_history`、排期 XML 与 UTC 截止。普通版本仍按当地 09:00 排期。保存后立即正常退出仍有排期已在真实 x64 通过；更改日期替换旧截止、取消后移除待发项并保留业务日期亦已通过。业务 ID 稳定时日期变更可以沿用同一 Tag，应比较截止及计划内容，不能仅凭 Tag 仍在就判旧排期未移除。

N2 缺少 WebView2 的联网下载和断网提示仍未验证。重启后 Sandbox 已可启动，但联网与断网两个全新 Windows 11 访客均自带 WebView2 Runtime，不能证明缺 Runtime 的分支。前提检测按 Microsoft 文档查询 Runtime 的 `pv` 注册表键，不依赖显示名称。Windows 10 访客亦未验证，不在工作主机卸载 Runtime 来制造条件。

N6 实体 Ctrl+逗号不能打开设置，根因已定位到 Edge/WebView2 引擎：同一会话内用带扫描码的合成输入完整复现——按住 Ctrl 时逗号 keydown 既不出现在 WebView2 `AcceleratorKeyPressed`（按文档任何 Ctrl 按键都应触发），也不出现在页面 DOM（keyup 正常送达且带 `WasKeyDown`）；无 Ctrl 的逗号、Ctrl+句号／分号／斜杠／N／D 的 keydown 全部正常。纯美式键盘与中文输入法 TIP 下结果相同，完整 Edge 浏览器同样复现，说明是引擎在到达宿主与页面前消费该按下事件，与本机软件、输入法、实体或合成来源无关。应用侧没有任何不引入全局热键、替代组合或仅 keyup 触发的合规修复；诊断观察为未提交的 fault-injection 补丁并已留档。侧栏设置入口可用；用户实体复测已完成：三次实体按下在原生观察中同样只记录到 keyup（扫描码 0x33），设置不打开，与合成复现一致，实体关联闭环。

N6 原候选包的普通物品编辑 Alt+F4 曾直接退出并丢弃输入，保留为失败记录。修复后的普通物品窗口 × 与实体 Alt+F4 已在真实 x64 提示先完成或取消，返回后输入保留；显式取消后无新增，保存校验失败保留备注。普通表单不保存草稿，Mac 行为不变。正常退出的提醒确认与系统禁用导致的错误提示／返回亦已真机复验；真实超时和迟到结果分支只有状态机测试，原生尚未覆盖。固定修复源码 `4f86470` 的[核心 CI](https://github.com/CoderJackZhu/Thingary/actions/runs/38544089283)和[安装与原生流程](https://github.com/CoderJackZhu/Thingary/actions/runs/38544089301)均成功，含 ARM64 Windows 下的 x64 模拟；不得继续称相应自动路径未执行，也不将其当作所有实体操作通过。

### OneDrive 标签与备份场景

1. 用户本人登录 OneDrive，在其指定的虚构测试子目录准备仅联机（云图标）与本地可用文件。可使用已有 OneDrive 目录，不要求启用新的「文档」备份或迁移主机资料；用户不使用 OneDrive 时记未做。代理不输入账号密码，不扫描个人文件。
2. 对用户指定的文件及目标文件夹输出 `Get-Item -LiteralPath <路径> | Select-Object FullName,Attributes`，并运行 `fsutil reparsepoint query <路径>` 保存原始标签。只读属性／标签，不为判定链接读取内容；确认仅联机文件在标签查询后仍为仅联机。
3. 修复前用隔离身份和虚构资料分别尝试将完整备份保存到指定 OneDrive 子目录、从那里恢复、把额外自动备份位置设为该处文件夹，记录错误与标签。已有修复前证据可以沿用，不为复现重装旧包。
4. 修复后按相同位置复测三项，全部成功；恢复后的表计数、记录与托管原图散列／显示一致。保存或恢复本身可能需要传输文件，这与只读标签检查不同。

Windows 按 `IsReparseTagNameSurrogate` 规则（标签 `& 0x20000000` 非零）拒绝符号链接 `0xA000000C`、目录联接／卷挂载点 `0xA0000003` 等名称代理；`0x9000xxxx` 云文件系列等非名称代理标签不作为链接。纯标签回归与现有 junction 拒绝回归不能代替 OneDrive 实机复测。当前 OneDrive 三项实机场景**未验证**。

## 系统通知

通知只在开始菜单快捷方式 AUMID 与已安装包身份一致时验收；未安装 `tauri dev` 不作为通过证据。

1. 用 fault-injection 验收入口将虚构提醒设为约两分钟后（自动脚本使用 20 秒缩短等待），读取真实系统计划队列，核对 Group `thingary` 与 15 字符 Scheduled.Id；退出调度进程后仍在队列。这个步骤只证明排队与保留。自动脚本继续在应用关闭后等待截止，核对相同 Group／Tag 的真实系统通知历史、内容及待发项移除；系统历史证据仍不等于肉眼确认桌面可见。
2. 手工创建虚构提醒后，用已构建的 `windows_notifications.exe inspect` 保存首次排期，保持 GUI 打开超过 60 秒后再读取，核对同一计划的截止时间没有后移；只读 `inspect` 不修改队列。记录退出时间，再在原截止后读取 `owned_history`（仅本验收身份的业务通知），按 XML、Group／Tag 关联手工心愿；原 `history` 字段仅用于固定夹具，空值不能证明手工心愿未送达。短延迟只在本进程内固定；重新启动带该环境变量的 GUI 或主动运行 driver `reconcile` 属于新的验收会话，会重新计时，不应混入同一观察。
3. 退出应用，等待截止时刻，人工确认可见 Toast／通知中心内容、时间与身份。截图记录系统状态；此项独立于 `AddToSchedule` 成功。
4. 更改／删除提醒或关闭相关模块，原排队项移除，不重复；重启及重装后不留下重复通知。
5. 系统关闭通知时出现明确提示，业务开关与提醒日期仍保存；重新开启后对账。盘点提醒按新完整盘点重新计时，不完整盘点不计。
6. 保存新的虚构提醒后立即正常退出，不提前检查队列或等待定时刷新；退出后从独立进程 inspect，确认该条业务提醒已排入系统。原生脚本分别记录跨 60 秒轮询后的送达与立即退出后的排期，二者不等于可见弹窗验收。强制杀进程不属于正常退出保证。
7. 日期分别用本地上午 9 点排期，抽查跨夏令时日期；系统时区更改后重新打开应用检查对账结果。过去日期不补发。

## 从使用指南迁入的验证记录（2026-10-15）

以下原写在使用指南「当前限制」中，属验收过程描述，已迁到这里；使用指南只保留面向用户的结论。

- Windows 0.0.7 未签名候选版目标为 Windows 10 1809+／11 x64，尚未公开 Release。真实 x64 已检查原生文件对话框、微软拼音、清单范围内的讲述人控件、单屏三档缩放及用户交互安装；安装流程仅有用户反馈，没有截图。人工卸载保留资料、重装后文件散列与快捷方式身份已核对；缺 WebView2、多屏仍有未完成项，自动检查不能代替这些验证。具体记录入口见[Windows 验收清单](https://github.com/CoderJackZhu/Thingary/blob/main/docs/WINDOWS_ACCEPTANCE.md)。
- Windows 隔离候选的心愿提醒已在真实 x64 上确认退出后进入系统通知历史并按排期准点投递；系统禁止通知时有明确提示，日期仍保存，重新允许后恢复正常状态。免打扰会影响横幅展示。此前点击已送达提醒没有反应的原因是 unpackaged 应用缺少通知激活注册；当前源码已在启动时登记该注册，机器验证（跨进程激活与冷启动拉起）与用户实际点击均已通过——用户点击时应用为关闭状态，由通知平台经激活注册直接拉起并显示窗口。其他提醒类型仍需分别验证。
- Windows 不支持将整个用户配置目录通过目录联接（junction）迁到其他盘的环境：资料根目录的上级含联接时会被拒绝。OneDrive 云文件占位符本身不作为链接，但 OneDrive 下的手动备份、恢复与额外自动备份位置仍需按验收清单实测，当前未验证。
- Windows 实机验收发现 Ctrl+逗号不能打开设置：已定位到 Edge/WebView2 引擎本身——按键事件在到达页面和原生入口之前就被引擎消费，完整 Edge 浏览器同样复现，与输入法、键盘布局、扫描码和是否实体按键无关（实体键的原生观察同样只记录到松键），应用侧无法收到该按下事件，也没有不改变其他快捷键、输入法或全局热键规则的修复。遇到此情况请点侧栏「设置」；其余 Ctrl 快捷键（N/E/F、Shift+F/D、A/Z）不受影响。
- Windows 普通物品表单的窗口 × 和实体 Alt+F4 已复验：先提示完成或取消表单，返回后保留输入；保存校验失败也保留输入。表单自身的关闭按钮仍丢弃未保存输入，不保存草稿。空闲退出会先确认系统提醒排期，保存后立即退出的排期已验证；系统禁用通知导致的退出错误可以返回应用继续使用。超过约 5 秒或系统返回错误时也可明确选择仍然退出（该次提醒可能无法送达）；真实超时与迟到完成的原生路径尚未验证。
- 核心记录、四问保存、投资核对、系统备份／Excel 文件选择、重启以及报告隐私复制已有隔离原生验证。VoiceOver 尚未验证，本轮未执行；真实输入法仅抽查支出名称中的豆包拼音组合，不代表所有输入法或表单通过。显示缩放、完整键盘路径、通知实际送达及 Dock 固定后重启仍未完整验证。

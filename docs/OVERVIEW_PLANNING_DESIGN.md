## 1. 目标、范围与设计理由

打开首页，用户应能依次回答：

1. 最近一次完整盘点时，我有多少金融净资产？
2. 过去的盘点呈现怎样的变化？
3. 依据现有资料与设定，距离退休目标还有多久，或目标年龄时资金够不够？
4. 这些结论依据哪些储蓄与盘点资料，下一步去哪里查看或补充？

### 1.1 已确定的布局

- 顶部左侧约占 2/3，保留金融净资产大数字、来源日期、变化与趋势曲线。
- 顶部右侧约占 1/3，增加一块「规划」摘要，展示退休结论、资产覆盖比例与历史常态月储蓄。
- 下方仍依次为「资产结构／持有物品」、辅助指标、「待关注／近期记录」。
- 窄窗口按「金融净资产与曲线 → 规划摘要」上下排列；关闭规划时金融净资产恢复满宽。
- 「只看物品」视图维持现行布局，不显示规划摘要。

### 1.2 选择 2∶1 的原因

| 方案 | 取舍 |
|---|---|
| 金融净资产与曲线继续满宽，规划放到下方 | 历史趋势有最多空间，但规划需要向下阅读，未来目标在首页的可见性较弱 |
| 顶部严格各占一半 | 两块权重相同，净资产曲线更拥挤；规划摘要需要的空间少于完整历史趋势 |
| **顶部约 2∶1** | **金融净资产保持主位，规划进入主要阅读区域；宽度不足时立即上下排列，保住图表可读性** |

### 1.3 本轮边界

本轮只增加只读摘要与已有页面的导航，复用当前计算与主题。养老金作为退休账本的组成部分；收益率、路线、预算、支出项、买房买车方案、心愿逐项影响与假设分析继续在规划页面查看、编辑。

本轮不增加首页编辑表单、规划模式切换、资产划拨、目标表、预测曲线叠加、模拟成功率、第二张历史储蓄图、通知或新的统计口径。金融净资产与物品购入金额继续分开展示。

## 2. 页面结构与布局要求

### 2.1 桌面结构

```text
原有顶栏、页面标题、日期、综合／只看物品切换
已有资料提示（例如最新盘点不完整，跨顶部两列）

┌──────────────────────────────────┬─────────────────┐
│ 金融净资产                       │ 规划             │
│ 净资产大数字                     │ 退休与财务自由   │
│ 截至日期 · 较上次 · 资产与负债    │ 主要结论         │
│                                  │ 辅助日期／年龄   │
│ 净资产历史曲线                   │ 资产覆盖比例     │
│                                  │ ─────────────   │
│                                  │ 常态月储蓄       │
│ 时间范围              查看盘点 → │ 来源与测算依据   │
│                                  │ 查看目标 →       │
│                                  │ 储蓄与收入 →     │
└──────────────────────────────────┴─────────────────┘
              约 2/3                     约 1/3

资产结构                           持有物品
重要支出／固定负担／平均持有／考虑中心愿
待关注                             近期记录
```

图中的框线表达区域边界，不要求给左侧套卡片。左侧沿用当前开放式金融净资产区域；右侧复用 `ui-card` 的主题表面。两区顶端对齐，不另加外层大卡片，也不在规划摘要内嵌套小卡片。

### 2.2 宽度、间距与断点

这里的 `W` 指 `.review-section` 内容区域的可用宽度，**已经扣除侧栏与页面左右留白**，不是窗口总宽度。

| 条件 | 顶部排列 | 具体要求 |
|---|---|---|
| `W ≥ 960 CSS px` 且两模块开启 | 两列 2∶1 | 列间距 16 px；剩余宽度按 2∶1 分配；最窄双列时左侧约 629 px，右侧约 315 px |
| `W < 960 CSS px` 且两模块开启 | 一列 | 净资产在上，规划在下，间距 16 px；不维持窄的 2∶1 |
| 规划关闭、财富开启 | 净资产一列 | 自动恢复满宽，无空白占位、无规划请求 |
| 财富关闭、规划开启 | 规划依赖提示一列 | 见 §6；不读取隐藏的盘点资料，不显示过去的估算结果 |
| 两者关闭 | 不显示该顶部区域 | 下方仍按已开启模块显示 |

宽度举例（四舍五入到像素，仅用于验收尺寸核对）：

| 内容宽度 W | 左侧 | 右侧 | 列间距 |
|---|---:|---:|---:|
| 1200 px | 789 px | 395 px | 16 px |
| 1040 px | 683 px | 341 px | 16 px |
| 960 px | 629 px | 315 px | 16 px |
| 959 px | 959 px | 上下排列、同宽 | 纵向 16 px |

实施应根据容器宽度判断，而非套用现有其他区域的窗口断点。下方结构表与列表的现有断点保持原义。两列子区均允许内容收缩与换行，长数字或文案不能挤出网格。

### 2.3 高度与对齐

- 有正常曲线时，顶部行预计约 360–420 px 高；这是检查目标，不是固定高度。
- 左侧曲线绘图区保留当前 190 px 高，不能为了匹配右侧高度把曲线任意拉长。
- 右侧卡片可随顶部行自然伸展，导航放在内容之后，并在空间富余时靠近底部。
- 缺资料、错误与长文案自然增加高度；禁止截断主结论、内部滚动条或用固定高度遮挡内容。
- 单份盘点或空盘点不画假曲线，不为图表留一个 190 px 的空框；右侧也不为了等高堆入多余指标。
- 页面整体仍纵向滚动；按通常字体显示时不应出现整页横向滚动条。

### 2.4 窄窗口结构

```text
金融净资产
大数字、日期、变化、资产负债
净资产曲线
时间范围／查看盘点

规划
退休结论、资产覆盖比例
常态月储蓄、来源说明
查看目标／储蓄与收入

原有资产结构、持有物品与下方内容
```

规划内容在一列模式中仍是一块摘要，不扩成目标页全量内容；可利用行内左右对齐减少高度，语义与阅读顺序不变。按钮在宽度不足时换行，文案和金额完整可读。

## 3. 左侧金融净资产与趋势

### 3.1 信息顺序

1. 「金融净资产」标签与现有说明入口。
2. 最近完整盘点的净资产大数字。
3. 「截至 YYYY-MM-DD 完整盘点 · 距今 N 天」。
4. 较上一份完整盘点的变化与变化率；不可比时说明原因。
5. 资产与负债金额。
6. 历史净资产曲线。
7. 「近 6 个月／近 1 年／全部」与「查看账户与盘点 →」。

最新一份盘点不完整的提示放在顶部两列之前，继续说明当前使用哪一份完整盘点。不能让右侧采用新但不完整的盘点，而左侧采用旧的完整盘点。

### 3.2 曲线要求

- 保留现有 `Sparkline` 的数据语义：完整盘点才作为金额点，不完整盘点的现有虚线标记保留，不当作零金额。
- 保留真实日期间距、全部有效点、悬浮详情、聚焦查看、左右方向键与 Escape 操作。
- 时间范围只裁剪左侧曲线，不改变顶部金额、资产结构、常态储蓄或退休估算。
- 某个范围内完整盘点不足两次时，该范围不可用；全部资料只有一份完整盘点时显示「完成两次完整盘点后显示走势」。
- 宽度改变只影响标签密度，不能删掉数据点。双列左侧常规显示至多约 6 个月份标签；一列更宽时可至多约 8 个，标签过密时进一步减少。
- 跨年标签必须提供年份线索；最后一个刻度和详情不能溢出区域。稀疏刻度不影响方向键浏览所有完整点。
- 提示浮层约束在左侧区域内，不覆盖规划主要结论；优先调整浮层定位而非裁掉详情文字。
- 保留当前轻量趋势表达；不新增纵轴、投资收益率、未来预测段或第二条规划曲线。

### 3.3 金额与布局

金融净资产保持页面最醒目的数字：桌面基准为当前 44 px，较窄时沿用约 36 px 的级别。使用主题数字字体与字重；金额不得通过省略号变成不可读的截断值。极长金额先缩减局部字号或允许合适换行，不把主要数字改成只显示「万／亿」且无法看到原额的缩写。

## 4. 右侧规划摘要

### 4.1 从上到下的内容

| 层级 | 内容 | 展示要求 |
|---|---|---|
| 区域标题 | 规划 | 14–16 px，语义标题；不增加说明性长副标题 |
| 目标名称 | 退休与财务自由 | 12–13 px；模式以「FIRE」或「传统」小字说明 |
| 主要结论 | 预计还需多久／目标年龄时盈余或缺口 | 24–28 px，最多优先排两行；完整文案必要时继续换行，禁止截断 |
| 次级结论 | 达成年份与月龄，或期望退休年龄 | 12–13 px；月龄不能只截成整岁制造已按期达成的错觉 |
| 资产覆盖 | 当前可支配资产／今天退休所需 | 单条细进度条与数字百分比，见 §4.4 |
| 历史参考 | 常态月储蓄 | 数字 20–24 px，低于退休主结论；明确历史口径与样本数 |
| 依据说明 | 盘点日期、未来储蓄采用的口径、按当前假设估算 | 12–13 px，可换行；不塞满全部测算参数 |
| 导航 | 查看目标 →；储蓄与收入 → | 同一行或两行链接式按钮，使用现有组件样式 |

摘要正常状态只包含一个主要结论、一条资产覆盖比例、一个历史储蓄数字和两个导航。当前可支配资产、退休预算、所需总额、收益率明细不再分别做大数字；通过说明入口或目标页查看。

### 4.2 FIRE 主要结论

复用 `buildRetireCalc` 生成的当前目标基线与 `plan.proj.fi_month`，按同一 `today` 求距离，不在首页另写一套估算。

| 情形 | 主要结论 | 补充说明 |
|---|---|---|
| 达成月份在未来 | 预计还需 N 年 M 个月 | 约 YYYY 年 · A 岁 B 个月；零个月可省略 |
| 已达到 | 当前资产已覆盖退休所需 | 按当前假设估算；仍保留目标与储蓄入口 |
| 在当前搜索范围内无 FI 月份 | 当前假设下，70 岁前尚未达成 | 若实际搜索终点早于 70 岁，改为实际终点年龄；不得把搜索范围之外写成永远不可能 |
| 比期望年龄晚 | 保留主要结论 | 加「晚于期望的 A 岁」，仅在真实月龄比较后显示 |

这里的 FI 年龄与真正开始退休的年龄沿用现行账本规则，不能将「财务独立的最早月份」改说成用户已经决定那时辞职。文案始终带「预计」或「按当前假设」。

### 4.3 传统模式主要结论

- 第一行可写「A 岁退休」；第二行写「预计盈余 ¥X」或「预计缺口 ¥X」。
- 使用当前目标结果中的 `funded_at_goal`、`assets_at_goal`、`required_at_goal`、`shortfall_at_goal`，与目标页保持相同判断及舍入。
- 盈余和缺口有文字说明，不能只依靠绿色或红色区分；未知结果不使用红色伪装成资金缺口。
- 不能将目标年龄那一刻的盈余写成「终身无风险」或直接换成 FIRE 达成年份。
- 目标页已有的必需支出缺口／资金耗尽诊断若影响结论，摘要应显示最重要的一条「规划期内存在资金缺口，请查看目标」，避免只报一项盈余而隐藏异常。该提示必须来自已有账本输出，不在首页创造新风险等级。

### 4.4 资产覆盖比例

使用目标页现有定义：

```text
当前可支配资产 = 最近完整盘点中计入的资产 − 负债 − 公积金类账户
今天退休所需 = required(plan, plan.now_months)
覆盖比例 = progressHundredths(当前可支配资产, 今天退休所需)
```

- 标签固定为「当前可支配资产／今天退休所需」，不能只写「退休进度」。这是资产比例，不能理解为时间进度、成功概率或目标已划拨金额。
- 使用现有 0–100% 限幅，负资产显示 0%；所需为零时按现有函数显示 100%。
- 缺计算输入时不显示百分比与进度条；不能显示 0% 的空进度暗示已算出结果。
- 比例数字保持与目标页相同精度，使用现有 `rateText`。条高 6 px，底色用 `--soft`，填充用 `--accent`；不是金额变化，因此不套涨跌颜色。
- 说明入口解释该比例，并可列出当前可支配资产与所需资产的精确金额；未知不补零。
- 即使达到 100%，文字仍为「按当前假设估算」，不生成庆祝动效或自动修改目标状态。

### 4.5 常态月储蓄与未来假设

首页「常态月储蓄」**只取 `review.stats.median_monthly_saving_cents`**，不取可能被用户储蓄阶段覆盖的 `calc.saving`。它是盘点与收入推出的历史参考，并非预测收入或工资。

来源说明示例：

```text
常态月储蓄   ¥7,619.20／月
近 12 个月可比区间的中位数 · 4 个区间
```

其中「近 12 个月」沿用统计窗口，以最新完整盘点为终点；不是以首页所选年份或曲线范围为终点。优先采用后端已给的窗口起止日期，说明入口可展示准确范围。

- `stats.low_sample` 为真时写「样本少 · N 个区间」，保留已有数字；数据不足与低样本量分别处理。
- 负储蓄保留负数，可补「近期在动用积累」；零为有效结果，不写成待补充。
- 未知显示「待补充」及最直接原因。填写未来储蓄阶段不能让历史常态储蓄自动变成已知。
- 测算未设置储蓄阶段时，依据写「退休估算沿用历史常态储蓄」；如设置了阶段、空窗比例或职业路线，写「退休估算采用已设置的储蓄阶段／路线」，提醒它可能与旁边历史数字不同。
- 「历史常态」说明入口可注明：包含利息和投资涨跌等变化，不等同于工资结余；一次性变动排除与现有储蓄页一致。
- 首页不复刻完整储蓄阶段金额表、路线比较或储蓄率。

### 4.6 大额计划、心愿与养老金

- 首页主结论与目标页顶部退休结论使用同一基线：计入已启用的大额计划，未计入的设想不参与。
- 只有实际存在已计入事件时，依据说明才追加「已计入大额计划」；不新增总价或逐项推迟月份。
- 基线中应继续保留已保存的事件与退休收支假设，不能为节省读取而只使用无事件的 `plan0`。
- **心愿按计划买下后的合计影响，目前是目标页中的单独情形。首页不把该情形偷偷并入主结论。** 不写「已包含全部考虑中心愿」；详细影响从目标页查看。
- 养老金、解锁资金、停缴与缴费年限沿用现行计算；首页不另算一个月养老金数，不填新政策默认值。
- 摘要只描述测算，不能扣减真实余额、改变心愿状态或创建购入记录。

## 5. 文案示例与内容规则

以下为虚构样例的展示示意，不是用户资料或财务承诺；不同模式与数据变化时必须重新计算，不能硬编码这些数值。

### 5.1 已具备输入的 FIRE 摘要

```text
规划
退休与财务自由 · FIRE

预计还需 14 年 4 个月
约 2041 年 · 50 岁 4 个月

当前可支配资产／今天退休所需      9.43%
━━━━────────────────────────────

常态月储蓄   ¥7,619.20／月
近 12 个月可比区间中位数 · 4 个区间

依据 2026-10-07 完整盘点
退休估算沿用历史常态储蓄 · 按当前假设估算

查看目标 →       储蓄与收入 →
```

上例中的月龄、年份与数值组合用于说明版式；验收夹具应由同一组明确出生年月、预算、假设与盘点计算得出，不将版式示例当作公式真值。实现时样本计数必须来自实际统计，不能硬编码「4 个区间」。

### 5.2 缺退休预算，但储蓄已知

```text
规划
退休与财务自由

先确定退休后的月预算
补齐后才能估算退休时间。

常态月储蓄   ¥7,619.20／月
近 12 个月可比区间中位数

补充退休预算 →       储蓄与收入 →
```

此时不显示预计年份、资产比例或假进度条，也不把历史推算支出自动填写成预算。

### 5.3 文字与数字格式

- 金额使用统一格式函数，保留整数分事实的精度；浮点测算值在展示边界按现行规则舍入到分。
- 日期使用统一 `YYYY-MM-DD`；若为估算年份，则明确写「约 YYYY 年」。
- 月龄与时长使用共同格式函数。首页与目标页不得分别取整，导致同一结果一个显示「50 岁」另一个显示「50 岁 4 个月」却给出相反的按期判断。
- 基准不足、未知、错误、预计缺口各有明确文字，不共用一个无解释的「—」。
- 主结论随模式变化，不同时显示 FIRE 年龄和传统目标盈亏。
- 说明文本先换行；只有不影响含义的辅助标签可简写。日期、金额、年龄与主结论不得省略成「…」。

## 6. 状态与降级要求

### 6.1 显示状态矩阵

| 状态／触发 | 退休结论区域 | 历史储蓄区域 | 行动与布局 |
|---|---|---|---|
| 输入齐全、FIRE 可达 | 预计还需多久与达成年龄 | 已知中位数或独立的缺资料提示 | 查看目标、储蓄与收入 |
| 已达到 FI | 当前资产已覆盖退休所需 | 正常显示 | 同上；仍标估算 |
| 当前搜索范围内不可达 | 明确搜索终点内尚未达成 | 正常显示 | 查看目标调整计划 |
| 传统盈余／缺口 | 目标年龄与盈余／缺口 | 正常显示 | 查看目标；异常诊断按 §4.3 |
| 负储蓄 | 继续使用现有引擎结论 | 显示负值，不能变成 0 | 查看储蓄依据 |
| 无个人资料 | 先填写个人资料 | 若历史储蓄已知仍显示 | 填写个人资料 → 养老金页 |
| 无退休月预算 | 先确定退休后的月预算 | 若已知仍显示 | 补充退休预算 → 目标页预算入口 |
| 无完整盘点 | 先完成一次完整盘点 | 待补充 | 查看账户与盘点；不给退休数字 |
| 只有一份完整盘点，未设置储蓄阶段 | 储蓄依据不足 | 待补充：需要可比区间与收入 | 储蓄与收入；左侧显示一份盘点金额、不画线 |
| 历史储蓄未知，但设置了有效未来储蓄阶段 | 其他输入满足时仍可算退休 | 待补充，说明历史依据不足 | 明确「测算采用已设置的储蓄阶段」 |
| 账户范围变化／没有收入／可比区间都被排除 | 依据现有 missing 与用户阶段决定能否估算 | 不伪造常态值，显示针对性原因 | 储蓄与收入 |
| 样本少 | 不因样本少强制清空合法测算 | 数字加「样本少 · N 个区间」 | 查看依据，不新增醒目风险卡 |
| 最新盘点不完整，有旧完整盘点 | 使用与左侧相同的旧完整盘点 | 显示统计的实际截止日期 | 顶部公共提示说明最新记录不完整 |
| 规划首次加载 | 正在读取规划… | 尚不显示数字 | 右侧局部加载，左侧可先用；可保留轻量占位减少跳动 |
| 个人资料读取失败，统计已读成功 | 退休估算暂时无法读取 | 保留已成功读取的历史储蓄 | 右侧局部重试；不报缺资料 |
| 储蓄统计／收入／必要盘点读取失败 | 不组合失败与旧输入算退休 | 只展示来源完整且成功的独立子区 | 规划暂时无法读取，重新读取 |
| 同库后台刷新 | 可短暂显示同一批旧结果，标「正在更新」 | 与该批结果一起保留 | 完整新批次成功后替换；部分新旧输入不得拼接 |
| 刷新明确失败 | 标「更新失败，以下为上次结果」或隐藏受影响数字 | 标明来源日期；不得冒充新结果 | 局部重试；若版本已变则隐藏受影响旧结果 |
| 切换资料库／恢复资料 | 立即清空旧结论，重新读取 | 立即清空旧值 | 禁止瞬间显示上一个库的内容 |
| 规划关闭 | 不渲染、不读取 | 不渲染、不读取 | 左侧恢复满宽，历史规划资料不删除 |
| 财富关闭、规划开启 | 开启账户与盘点后显示规划摘要 | 不展示依赖盘点的历史值 | 规划依赖提示满宽；前往设置；不自动启用财富 |
| 只看物品 | 不渲染 | 不渲染 | 不为本摘要读取或运行退休计算 |

多个缺项同时存在时，主结论区只展示最先可解决的一项，其他缺项留在目标页。建议优先顺序：依赖模块关闭 → 读取错误／加载 → 无完整盘点 → 无个人资料 → 无退休预算 → 缺储蓄依据 → 其他计算输入缺失。已成功读取且不依赖失败源的历史储蓄仍可展示。

### 6.2 新资料库

继续保留现有「从这里开始」提示，提供记录物品与建立账户入口。规划摘要使用简洁待补齐状态，不在空库中出现两套大型新手介绍，不用默认预算、默认工资或虚构个人资料补出退休年龄。

### 6.3 日期与提示

不以「盘点多久没更新」另造未批准的强制阻断规则。始终显示采用的盘点日期与现行距今天数；个人资料陈旧提示沿用当前养老金规则，详细核对在养老金页进行。日期过旧也不能替换成今天的余额或假定资产一直未变。

## 7. 导航、交互与无障碍

### 7.1 导航去向

| 控件 | 去向与行为 |
|---|---|
| 查看账户与盘点 → | 沿用当前账户与盘点导航与返回上下文 |
| 查看目标 → | 进入「规划 › 目标」，显示当前目标摘要；不自动打开编辑表单 |
| 储蓄与收入 → | 进入「规划 › 储蓄与收入」，展示真实区间与收入 |
| 填写个人资料 → | 进入「规划 › 养老金」，聚焦现有填写入口；仍由用户发起填写 |
| 补充退休预算 → | 进入「规划 › 目标」，定位现有「设置月预算与假设」入口；不在首页新建表单 |
| 前往设置 → | 进入功能模块设置；不自动打开依赖模块 |
| 重新读取 | 只刷新规划摘要需要的来源，不触发写入或刷新曲线时间范围 |
| 比例／储蓄说明入口 | 沿用已有 `Info` 交互，支持键盘阅读；不改变输入 |

规划卡片整块不作为按钮；文本可选择复制，进度条不可拖动。首页不新增专用快捷键；⌘N、⌘F、⌘⇧F 保持当前页语义。

### 7.2 返回与编辑保护

- 跳转沿用总览返回上下文，回到总览时保留综合／只看物品选择、所选年份、曲线范围与滚动位置。
- 需要将曲线范围从当前组件局部状态接入同库页面记忆或返回上下文，不能只承诺保留滚动位置。
- 页面记忆只属于当前会话与资料库；切换资料库清空，不把同库旧数据持久化成跨库缓存。
- 现有未完成编辑与保存结果未知的回执保护继续有效；不能用新导航绕过阻塞。
- 目标页内部的预算入口定位意图只消费一次；用户离开后迟到的定位或读取响应不再跳转。

### 7.3 无障碍与键盘

- DOM 顺序与视觉一致：先左侧，再右侧，接着下方结构与列表；上下布局不重排成不同阅读顺序。
- 区域提供语义名称「金融净资产」「规划摘要」；进度条提供标签和完整百分比文本，不可仅依赖颜色。
- 主结论、缺项与错误可被读出；加载使用局部状态说明，不反复抢焦点或播报整页。
- 曲线保留焦点、方向键与 Escape 行为；标签稀疏后仍能逐点读取日期、金额与变化。
- 所有链接式按钮可用 Tab／Enter 操作，并使用现有焦点描边；无需把非交互指标塞进 Tab 顺序。
- 导航落到目标页面标题或明确的现有入口，返回时采用当前焦点恢复约定。
- 在三种主题的浅／深模式验证文字、进度条、说明与错误；颜色不能替代文字判断。

## 8. 数据读取与计算一致性

### 8.1 所需数据与复用

| 内容 | 当前来源 | 实施约束 |
|---|---|---|
| 左侧净资产与曲线 | `review_overview` 中的财富摘要 | 保留现行投影与最近完整盘点选择 |
| 历史常态储蓄、样本、截止日期 | `plan_review` | 使用 `stats`，不从净资产曲线直接外推 |
| 公积金月缴存等输入 | `plan_income_list` | 复用现行退休计算选取规则，不首页取一个新平均数 |
| 个人资料、预算、模式、阶段与事件 | `plan_profile` | 使用已保存的输入；未知预算保持未知 |
| 最近完整盘点明细 | `wealth_snapshot` | 用与左侧相同的稳定 snapshot ID；不能用净资产总额代替公积金扣除计算 |
| 退休基线与结果 | `buildRetireCalc`、账本 `required`、现有结果函数 | 摘要与目标页共用计算及文案投影 |

`loadPlanContext` 现有实现一次读取多份数据，适合复用读取路径，但其整体失败行为与简单调用方式**不能直接满足本设计的局部降级、模块门控与跨来源一致性要求**。现采用 `review_overview(planning)` 的同事务只读聚合补足这些约束，不能在 `ReviewView` 里复制大量计算。

### 8.2 一致性与并发

- 把当前 `generation`、本地 `today`、模块开启状态、写入失效版本／票据作为摘要的读取上下文。
- 规划结果、收入与盘点若回显 generation，应核对一致；不回显的来源也须由整个批次的上下文、资料库切换失效与现有后端保护约束。
- 左侧选择的完整 snapshot ID、右侧明细 ID、统计截止盘点必须相符；不符时废弃退休组合并重读，不能把不同日期拼成同一个「当前」结论。
- `generation` 只证明资料库身份，不能单独证明同库的收入、个人资料与盘点来自同一个写入版本。批次在途发生写入时应失效并重读。
- 若现有命令不足以保证同一读取版本，补充受保护的只读聚合读取或可校验的读取版本；无需新数据库表或持久化退休结果。
- 读取保留存活与请求票据保护。旧请求迟到、组件卸载、模块关闭、库切换、日期变化时，旧响应不可覆盖新状态。
- 规划数据从共享读取层交给纯计算，成功结果一次性提交。不能在每个收入响应到达时重算一个临时混合结果。

### 8.3 更新触发与成本

在进入综合总览、同库相关写入成功、删除／恢复相关资料、完成整体恢复、模块变化、跨自然日及应用重新获得焦点时刷新。相关写入包括盘点、账户计入范围、收入、一次性变动标记、个人资料、退休假设与大额计划。

- 不依赖“物品列表页对象变化”间接刷新规划，必须覆盖没有物品写入的规划编辑。
- 普通渲染、鼠标移动和图表范围切换不重复请求或运行退休模型。近期记录年份切换沿用现有综合回顾的整批读取，以保持左右同一快照；不增加独立规划请求，不运行假设分析。
- 只运行目标基线计算；首页不运行压力测试、市场路径模拟、路线矩阵或读取全部考虑中心愿。
- 可复用当前批次的财富摘要，避免为了摘要重复读一个独立日期的 `wealth_summary`。
- 关闭规划／只看物品后取消或废弃在途请求，并停止本摘要计算；不启动隐藏的后台分析。
- 不新增网络请求、定时后台轮询或持久化结果缓存。

## 11. 验收标准

### 11.1 必须具备的虚构场景

| 编号 | 场景 | 通过条件 |
|---|---|---|
| A01 | 正常 FIRE、至少四个可比区间 | 与目标页同一达成月龄／日期，历史储蓄与储蓄页相同 |
| A02 | 传统模式、分别有盈余与缺口 | 主结论随模式正确切换，首页无独立模式编辑 |
| A03 | 已达成／搜索范围内不可达 | 正确文字与限幅比例；不可达不是未知或永久失败 |
| A04 | 零储蓄／负储蓄／负可支配资产／所需为零 | 已知值不当未知；比例按现有函数边界处理 |
| A05 | 无资料／无个人资料／预算为空 | 不出现假的退休年龄或 0%；显示具体下一步 |
| A06 | 单次完整盘点／全部不完整／较新不完整 | 一点不画线；较新不完整时两边用同一旧完整盘点 |
| A07 | 账户范围变化／收入缺失／区间都排除／样本少 | 未知与低样本分别处理，缺项原因准确 |
| A08 | 历史储蓄未知但阶段已填／阶段与历史相差很大 | 退休可算与历史未知可并存；首页不误称阶段值为历史常态 |
| A09 | 已计入与未计入大额事件，另有设日期心愿 | 主结论与目标基线相同，不额外合并心愿情形 |
| A10 | 统计、个人资料、盘点明细分别读取失败 | 错误局部处理，已知独立数据保留，不当空库 |
| A11 | 慢读取、失败后重试、保存后返首页 | 新结果正确刷新，旧票据无效，无混合批次结果 |
| A12 | 读取中切换库／恢复／关闭模块 | 旧结果立即清空或废弃，不污染新库或隐藏模块 |
| A13 | 长金额、长结论、跨年与多年曲线 | 无横向溢出、无主结论省略；所有点可访问 |
| A14 | 曲线范围与年份切换、跳规划后返回 | 曲线控件不改规划结果；返回保留同库页面选择与滚动 |
| A15 | 财富／规划分别关闭与只看物品 | 布局与请求门控符合 §2.2、§6，无自动开启模块 |

### 11.2 同尺寸视觉对照

- 默认风格浅色提供改前／改后同尺寸对照，建议窗口 1440×1000 CSS px；正式证据记录实际窗口、视口、内容 W、缩放、主题、夹具与 `today`。

- 缺资料、错误、长金额在断点两侧可读，按钮无重叠，顶部区域没有固定高度裁切。

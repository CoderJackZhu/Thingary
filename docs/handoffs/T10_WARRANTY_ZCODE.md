## 3. 交付范围与业务规则

交付：资产详情添加／同 ID 更正多份保障；分别展示类型、提供方、起止日、备注与图片；有效保障摘要及资产保障筛选；日期变化刷新；草稿、失败与重开恢复。现有 Active/Retired/Sold、购入／维护／售出金额和成本公式保持原语义。

- 必填关联资产、保障类型。类型采用产品已列的厂家保修、延保、AppleCare、商店保修、其他保障；提供方、日期、备注可空。已知日期严格有效，结束不得早于开始；不把未知当今天或无限期。
- **不要复制维护的日期限制**：保障可以未来开始／未来到期，不要求结束日不晚于今天，不自行增加购入／售出日期钳制。保障和生命周期独立，退役／售出不自动删除保障或停止按当前自然日计算保障状态；不能把保障费用重复计入成本，T10 不新增费用口径。
- 完整日期且 `start <= today <= end` 才能确认当前有效；剩余自然日 0–30（含两端）为即将到期，31 及以上为保障中；`start > today` 尚未生效，`end < today` 已到期。任一日期缺失为待补全，不推断当前有效；起止同日合法。
- 多份分别保留。存在超过 30 天的有效保障，摘要可显示保障中，同时保留其他近到期提示；只有近到期有效保障时提示即将到期；无记录与有记录但日期未知不能混为一谈。未来／过期／未知混合时呈现各类事实，不能声称当前已覆盖。筛选逻辑、摘要和详情采用同一套规则；明确混合状态的匹配语义并用例固定，不能前后端各算一套不一致结果。
- 状态查询接受测试用固定观察日，生产用既有本地业务自然日。跨日刷新列表、当前详情、保障摘要和筛选；不能靠重启或更改系统时钟测试，不能将所有天数按固定 24 小时毫秒差计算。
- 到期信息选择**查询时派生**，不增加常驻任务、通知权限、重复落库事件。AC15 在本阶段验证更正／重复读取／重启不重复；未来 T14 全局时间轴复用同一保障 ID 和最新结束日期，不预做全局时间轴。
- 不做保障独立删除／统一回收界面（T11），但保存独立删除语义的兼容设计；父资产删除后子记录隐藏，父恢复后原本有效的保障和附件可读。完整设置页备份归 T18，本阶段后端备份必须覆盖新增表和附件。

保存保障、关联图片、parent revision、审计和请求回执整体成功或整体回滚。重复同请求只产生一次业务事实；同 ID 不同 payload 拒绝。旧 generation／revision 不能覆盖当前数据。新增／更正不修改既有售出审计，不复活已删除父资产。

草稿必须持久保存输入、保障 ID、照片、generation、原 revision；发出写请求前持久保存原 request ID 与完整 payload。响应丢失先核对原回执；核对不可用冻结修改，重开仍核对同请求，不重发成新记录。恢复不能自动跳过版本冲突或把更正变新增。存储失败明确提示，不假装已保存；表单关闭、退出、继续编辑和保留草稿路径复用 T09 已修复实现。

保障图片复用托管附件、原图哈希、预览和重新选择同一原图修复。不可复用其他实体的附件关系 ID；相同内容共享文件字节可以，但所有权与引用独立。当前保障使用实际图片附件即可，不把 U01 示例素材自动塞入保障。文件移动／缺失不能破坏保障文本；不能通过直接写 SQLite 来模拟 UI 成功。

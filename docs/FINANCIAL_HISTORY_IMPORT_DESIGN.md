# 金融历史 CSV 导入设计

状态：**P1-3A 的账户 + 完整盘点已接入当前源码，尚未发布。** 月度收入（P1-3B）、历史总额参考、收入覆盖声明仍未接入。本文保留完整目标规格；当前入口仅接受 `accounts.csv` 与 `snapshots.csv`，不提供列值清理、Excel、OCR 或银行格式转换。总入口见 [整体设计](PLANNING_LIFECYCLE_DESIGN.md)，数据语义见 [资金与方案](PLANNING_DATA_SCENARIOS_DESIGN.md)。

当前 P1-3A 使用“账户”页的“更多 → 导入历史”，复用纯解析器与账户／盘点事务内校验。预览在私有 SQLite 内存副本中模拟整批，真实资料库只读；提交重新验证 generation、文件指纹、标准化摘要、上下文摘要及所选对象修订。辅助 IPC 提供原生选文件、模板、进度、独立取消与回执查询；取消不排在串行 Worker 后。

schema 34（`x10.sql`）新增外部键映射与成功回执。来源名称 + 映射集合 + 对象类型 + 外部键唯一，同名不自动绑定；永久清除映射保留墓碑，不重绑稳定 ID。失败事务不留回执，同一 request_id 可重试；已提交结果未知仅保留请求 ID 与 generation，先只读核对，不持久化 CSV。完整备份携带两表。

实际限制为每批合计 20 MiB / 50000 数据行，超过即拒绝；对象、组内账户、问题和回执每页最多 50 项，账户候选每次最多 100 项，分页不减少整批验证。非法货币符号、千分位、分单位、负债负数须在原文件修正，当前没有清理转换选项。显式历史覆盖仅写历史条目，受支持类型与账户方向必须一致；空覆盖用映射账户当前资料。全部所选写入后再复核有效期与停用前最后余额为零。普通账户／盘点命令保持原语义。

P1-3A 已有 I01/I04/I05/I07/I08/I09/I10/I11/I12 的临时 Store／解析回归；独立原生身份验证了中文路径选文件、24 个月提交回执、重启、旧 schema 33 备份恢复、新备份往返与最大文件取消。失联回执与切库冲突的故障场景由 Store 回归证明，未逐一通过原生 UI 注入；浏览器四状态对照仅证明界面展示。复现入口与未验边界见 [开发与测试](DEVELOPMENT.md#金融导入解析与报告组件)。

## 1. 范围与入口

支持账户、账户级完整盘点、月度收入和仅有净资产总额的历史参考。只解析模板化 UTF-8 CSV，不解析 Excel 文件、OCR 或银行格式；用户可在表格软件导出模板 CSV。

“账户与盘点”更多菜单提供“导入历史”，收入页提供同一工具的收入模式。导入不要求填写退休或社保资料，不自动启用其他模块；模块关闭需用户明确启用相应事实模块。

模板下载附简短说明与虚构样例，说明金额为元、最多两位小数、日期格式、负债正数、空白与零区别。用户不必理解数据库 ID。

## 2. 文件与字段

### 2.1 账户 accounts.csv

| 列 | 必填 | 含义与校验 |
|---|---|---|
| account_key | 是 | 文件内稳定外部键，1–100 字符；不等于账户名 |
| name | 是 | 显示名称，复用现有名称长度校验 |
| kind | 是 | 模板给出当前支持类型的规范键和中文对照；非法值报错 |
| enabled_from | 是 | `YYYY-MM-DD`；不得晚于引用它的首次盘点 |
| disabled_from | 否 | 明确停用日期；不得早于启用；停用之后不要求盘点 |
| counted | 是 | `true/false`；不得由空值猜测 |
| platform | 否 | 可空，不接收卡号或登录凭据 |
| note | 否 | 可空，复用现有备注约束 |

资产/负债方向由类型决定，不再单独允许冲突方向。已有账户可由映射选择复用；同名只产生候选，不自动合并。参与规划和资金可用性由规划确认，不在导入时推定。

### 2.2 完整盘点 snapshots.csv

| 列 | 必填 | 含义与校验 |
|---|---|---|
| snapshot_key | 是 | 文件内盘点组键，同组日期一致 |
| date | 是 | `YYYY-MM-DD`，实际历史日期，不接受未来 |
| account_key | 是 | 对应已映射账户 |
| amount | 是 | 非负元金额，零明确写 `0`；负债填欠款正数 |
| note | 否 | 同组非空备注须一致，保存为一次盘点备注 |

账户类型/计入范围历史若与当前不同，模板可增加 `kind_at_date`、`counted_at_date` 两列作为显式覆盖；空列采用已映射账户的对应有效资料。预览展示其历史含义，不改当前账户类型。实施需纳入现有历史条目规范校验。

同一盘点组一个账户只能一行；同一日期只能对应一个盘点组。依启停日期与映射范围核对所有应盘点账户：缺行/空金额报该组不完整，不能复制前值或补零。其他日期的有效组可以在用户明确移除错误组后作为新提交集合。

首次导入到已有库，完整性按真实账户有效期核对，不能把导入文件当时只列出的账户默认为全部账户。无法核对的旧数据可改为 §2.4 总额参考，不冒充完整盘点。

### 2.3 收入 incomes.csv

| 列 | 必填 | 含义与校验 |
|---|---|---|
| income_key | 是 | 稳定外部记录键；同日工资/奖金可各一行 |
| date | 是 | 实际到账日 `YYYY-MM-DD`，不可未来 |
| net_income | 是 | 非负税后到账元金额，0 是明确零 |
| hpf_deposit | 否 | 单位与个人合计，非负；空表示未掌握，不能自动填0 |
| note | 否 | 可空，复用收入备注校验 |

公积金未知需要事实模型支持空值；不得为了兼容当前必填字段擅自变零。该模型是导入写入的前置依赖。它不阻碍展示已知到账收入，但相关缴存汇总标不完整。

多条同日同额收入合法，只有同一外部键/指纹或显式关联才作为重复候选，不能据金额相同自动吞掉一笔。

收入完整性独立可选模板 `income_coverage.csv`：`from_date`、`to_date`、`state`（complete/partial/unknown）、`note`。区间表达 `(from_date, to_date]`；有实际零收入且用户确认完整时可以不制造零金额行。与现有覆盖确认冲突在预览中处理，不按收入条数判断。

### 2.4 历史总额 net_worth_history.csv

字段：`history_key`、`date`、`net_worth`、`note`。总额允许负数；金额未知行不能形成趋势点。

保存为“历史总额参考”，与账户级完整盘点分开。只用于注明来源的历史趋势，不提供账户结构、不参与现金可用性/缴存推导、不成为正式规划起点。

同日已有完整盘点优先使用完整盘点的点；总额参考仍可查看但不加成另一笔资产。补齐真实账户明细后关联替代参考点，不把总额拆成虚构账户。导入参考不意味着完善了此前缺失的账户事实。

## 3. 四步交互

1. **选择类型与文件**：允许组合账户/盘点/收入文件；模板入口常显。只读文件、解析内容，不写资料。
2. **对应账户与列**：标准列名自动匹配，非标准列允许选目标列；显示样例和金额/日期解释。外部键对应新账户或明确选择已有账户。
3. **预览与核对**：按账户、日期组、收入分别列新增/相同/冲突/错误数；行错误可定位。明确列缺少的应盘点账户、未知缴存和完整性范围。
4. **确认导入与回执**：一次事务提交所选有效集合，显示实际创建/更正/跳过数量及入口，支持查看本次回执。

选择文件即解析，不持久化上传副本。取消/关闭普通预览不保存草稿；提交后未知结果保留请求元数据并查回执。

## 4. 解析与限制

接受 UTF-8/BOM、标准引号/逗号及引号内换行。所有金额使用十进制字符串解析为整数分，禁止二进制浮点累计、指数记法、NaN/Infinity、静默四舍五入超过两位小数。默认不接受货币符号和千分位；用户在预览显式选择清理规则后显示转换前后样例。

日期仅支持明确的 `YYYY-MM-DD`；不猜 `01/02/2025` 月日顺序、Excel 序号或时区。金额单位固定元，若外部为分需明确选择转换；负债负数必须修正/确认转换，不能静默翻符号。

首版每批文件总大小上限 20 MiB，数据行总数 50000，单元格/名称/备注再受对应领域限制；这是拟定上限，实施需验证可响应取消与内存占用。超限清楚提示拆分，不读到中途静默截断。

CSV 内容作为数据；列值不执行公式、脚本或路径。后续 CSV 导出对可能被表格软件执行的公式前缀处理，同时保持实际数字列正确，不能用壳命令解析单元格。

## 5. 重复与更正

| 情况 | 默认动作 |
|---|---|
| 同一批次指纹与已完成回执相同 | 展示原回执，不再写入 |
| 同一外部键、同一映射、值完全相同 | 标相同，跳过 |
| 同一外部键/已有事实 ID，值不同 | 冲突；明确选择保留现有或更正 |
| 同日已有盘点，输入完整组完全相同 | 跳过 |
| 同日已有盘点但金额/范围不同 | 整组更正或保留，显示差异，不逐行合并 |
| 仅账户同名、同日收入同额 | 候选，不自动合并/跳过 |
| 旧不完整盘点与完整导入同日 | 显式整组更正，按现有完整性约束补齐 |

更正带已加载的修订；现有资料在预览后被修改则整批失败、要求重新预览。不能用“导入优先”覆盖其他窗口新改动。

外部键命名空间采用用户确认的来源名称及映射集合；不同表格的同一键不能自动认同一事实。重新导入可复用映射，名称/平台修改仍展示差异。

## 6. 原子提交与恢复

后端提交请求包含 generation、request_id、文件内容指纹、标准化数据摘要、账户映射、所选动作与 expected_revision。预览可用一次性校验令牌，但提交必须重新验证领域约束与修订，不能信任前端预览。

创建账户、盘点、收入、完整性声明、外部映射与导入回执在一个事务内完成；任一失败全部回滚。用户选择跳过错误数据形成一个新的明确集合，不能系统自行部分提交。

库切换/恢复/模块关闭令旧预览失效，不能把旧文件写到新库。提交结果未知先查原请求，不重新提交新 request_id。

成功后统一失效财富/收入/规划读取；显示盘点起点是否改变和需要复核的来源，不能自动改变未来净投入或原冻结基准。

导入不是备份恢复：不替换资料库，不带入图片/物品事实，不恢复全部关系。保留完整备份入口。本次导入回执列对象身份和动作，不存整份原始文件或敏感整表日志。

首版不提供危险的“一键撤销全部”：新增可通过现有最近删除处理；更正展示原修订与恢复入口，涉及整体回退使用导入前备份。导入前提醒建立保护备份，备份失败须明确处理，不能表示已完成保护。

## 7. 界面与错误

预览显示数据概览与第一批行，分页/虚拟展示不会减少后端校验。错误说明文件/行/列、原因及如何修正；不在日志打印整份账户内容。没有有效行时不允许确认。

“新账户3个、盘点24次、收入48条、冲突2组”与最终回执数字可核对；总额参考单独计数，不能混成完整盘点。

大文件解析提供进度和取消，取消只在写入前生效；已提交阶段显示正在核对结果，关闭后按回执恢复。不能中断事务后显示成功一半。

## 8. 验收

| 编号 | 场景/通过条件 |
|---|---|
| I01 | 带入24个月、跨启停账户历史：日期组完整，映射稳定，金额分准确 |
| I02 | 空缴存与明确0：保存两种状态，到账汇总不被未知缴存清零 |
| I03 | 同日两笔同额工资/奖金、不同键：保留两笔；同键重试只计一次 |
| I04 | 同日盘点冲突：显示整组差异，未确认不覆盖；预览后修改导致冲突 |
| I05 | 缺账户/空余额/重复组行：该组报错，不补0或复制前值 |
| I06 | 只有总额：参考曲线可用，但不成为完整盘点或现金起点 |
| I07 | 字符引号/换行/BOM/中文、非法日期/指数/超过两位：解析或明确报错，无静默截断 |
| I08 | 新账户成功后收入失败的故障注入：整批无写入，回执失败可核对 |
| I09 | 提交未知、重启、查回执重试：没有重复账户/盘点/收入 |
| I10 | 预览时切库/恢复：旧上下文拒绝，原文件不自动重写新库 |
| I11 | 备份恢复新导入资料：身份、映射、完整性和回执保留 |
| I12 | 超限与最大合法数据：明确拒绝或可完成，取消与分页可用 |

原生验收覆盖选文件、中文路径、解析取消、事务回执、重启与备份恢复；浏览器内存桩不能证明这些通过。完成后同步模板样例、USER_GUIDE、实际限制与 CSV/完整备份区别。

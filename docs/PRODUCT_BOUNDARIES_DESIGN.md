## 1. 产品承诺

物谱帮助用户低频维护物品、资产负债与生活计划，并在后续盘点时复核变化。主要价值来自资料持续积累、复用与核对；不以独立计算器的数量作为产品完整度。

官方已有复杂测算工具的事项，物谱只提供外部链接，不内嵌、不复制公式、不维护地区参数，也不要求用户把官方工具的整套输入再填一遍。官方结果仍须按其适用条件理解，链接不代表物谱验证了结果或取得了官方授权。

一次性试算可以作为已有计划的辅助操作，但必须复用已维护资料、回答具体资金问题，不能成为新的专业政策工具或独立导航。使用频率低不等于没有价值；判断的是下次回来能否接续，而非是否每天打开。

## 2. 功能进入标准

新增或继续扩展的能力应同时满足：

1. 用户知道如何取得和更新主要输入，不需要研究政策公式或填写大量专业参数。
2. 输入能随盘点、实际到账、支出发生或计划调整继续维护，结果服务于明确的下一步决定。
3. 计算关系可以解释；未知与假设可见，不能依靠叠加难以核实的假设制造精确结论。
4. 与已有档案、账户、时间线或计划复用同一事实，不再建立重复资料体系。
5. 若外部权威工具已承担复杂核算，只链接该工具；仅在整体资金规划确有需要时接收用户明确录入的结果。

不能满足时优先删除入口、收缩职责或使用链接。放入“高级设置”、添加免责声明、把默认参数改成用户自填，都不能代替范围收缩。

## 4. 入口与最少填写

### 4.1 官方链接

移除独立养老金测算页及其常驻页签，目标与收入／复盘保留既有职责；不借此次重排其他主导航。旧页签标识应安全回到目标页，提供一次可理解的调整说明，不恢复旧表单。

用户编辑未来养老金收入时，按需显示一条“到官方工具测算”外部链接；优先使用经核对的稳定官方服务入口。法定退休时间或医保问题只在相关帮助处给相应链接，不新建链接列表页或强制查询步骤。

外部链接由用户主动打开，不自动传出生日期、金额、账户等资料，不嵌入登录、不代理办理。链接失效不阻断本地记录或规划，实施时核对目标地址与服务名称。

### 4.2 未来收入

主流程只要求选择“本次暂不计入”或“填写预计收入”。养老金是一种收入名称／角色，不再出现“职工自动估算”“北京参数”“补齐社保资料”等分支。

用户可以按“从多少岁起，每月预计收到多少钱”理解和填写，也可直接填写开始年月。若使用年龄，需要在通用规划中重新确认当前年龄及其截至时间，再映射到月份；不继承旧社保出生年月，不要求完整生日，也不据此推断法定年龄。内部只保留一种明确的时间依据，不同时维护年龄与年月两份互相冲突的事实。停止工作目标和收入开始时间独立。

计入一项收入所需的最小内容是每月预计净到账金额和开始时间；结束时间可选，未填表示按假设持续至规划终点。年份很远的金额明确区分今天的购买力与领取当年的名义金额；有条件时可按已确认通胀假设换算，不能偷用缺失参数。来源、测算日期与备注为选填，不另起一套专业问卷。养老金链接使用[国家社会保险公共服务平台](https://si.12333.gov.cn/)；该平台提供待遇测算和法定退休年龄查询，部分服务需要登录／填写资料，不能承诺点击即可取得个人结果，第三方表单可能随时间变化。

领取后的增长不声称跟随实际政策。沿用可解释的通用收入假设，固定名义金额或保持购买力须可见可改；不自动预测年度养老金调整。

金额或开始时间未知可保存为不完整安排，但不计作已知收入；仍可展示“未计入这项收入”的条件结果，不声称完整退休结论。主动选择本次不计入后不持续催补。明确零、未知、不计入与读取失败保持区分，读取失败不能伪装成主动不计入。

来源备注只供用户理解，不标为系统已核验。外部金额是特定条件下的估算；用户需要时自行更新，物谱不监听缴费路径、不生成停缴／续缴核对任务。已实际领取时可以改用实际到账作为参考，不自动把预测写成真实收入。

### 4.3 费用与受限资金

未来费用只问金额、起止／发生时间，以及是否已包含在预算或净投入中。不问缴费基数、地区比例或年限缺口，不预置社保续缴／补缴任务。税后到账已经扣除的个人缴费不再重复扣；离开工作后由本人支付的保费等，由用户在普通预算内安排。删除专项模型不等于这些现金支出不存在。

医保不能简化成固定的自由支配月收入：实际待遇与医疗费用、支付范围、起付线、比例等有关。退休职工医保免缴基本保费有适用条件，不能等同医疗费用为零。产品不计算资格、报销或“终身医保价值”；保留普通预算中的医疗自付与保险费用，并可使用现有一般压力情景检验较高开销。参考[国家医保局参保说明](https://www.nhsa.gov.cn/art/2024/9/30/art_14_14051.html)与[医保自付／自费说明](https://hsa.sz.gov.cn/gkmlpt/content/11/11952/post_11952753.html)。

被删除的社保测算账户余额字段不转换成金融账户。个人养老金与公积金的既有金融账户、真实余额及实际缴存记录继续保留，无需建立退休目标。规划只通过通用资金规则引用：不确定可用时间时继续作为受限资产，不自动加入可花资金；若确需规划转出，由用户明确给出时间与可用净额，不根据退出的法定年龄函数推断。不为本次退出另造领取管理模块。

不新建税率计算器。对个人养老金等使用用户明确的可用净额时，不再重复扣既有默认税费。转入、转出及余额只能计入一次；受限池到可用池是资金转移，不是新增收入或额外资产。退出与解耦必须包含旧税费、自动缴存及解锁依赖，不能只移除界面。

## 5. 长期使用闭环

用户下次回来主要维护发生变化的少量资料：新盘点、实际到账或发生的支出、预算与目标调整、外部结果更新。资料沿稳定 ID 复用，不为每次计算重复建档。

已保存计划从新的事实起点重算，显示“截至何时的资金、采用哪些收入和支出、覆盖到何时、哪些未计入”。净资产变化不能冒充投资收益或实际储蓄；未来安排不会改写真实余额。已发生支出由既有发生核对接续，不能再扣一次。

先利用现有保存、盘点和复盘能力完成这一闭环。不新增每日打卡、通知体系或自动催填；不为保留一次性试算强行增加历史表和管理页面。没有旧预测存档时，只比较真实历史资料，不能重算一个“当时预测”冒充历史基准。

## 6. 旧资料与计算过渡

本节取代上一版“保存旧社保输入与专项回执、逐项迁移旧假设”的要求。兼容工作仅服务于客观事实的安全保全，不服务于重现旧测算。

1. 必须保全物品及图片／附件、账户、资产负债盘点、真实收入／缴存、重要支出、周期付款、负债与已发生记录，以及其稳定 ID、日期、备注、引用和可导出内容。个人养老金、公积金账户及其余额历史在此范围内，不因同名而与政策字段一起删除。
2. 删除旧社保出生年月、性别／职工类型、地区、基数、缴费指数、累计年限、社保测算账户余额、弹性退休选择、医保门槛及缴费排期等专用输入。旧待遇结果、专用未来缴费／税费／解锁假设、补缴安排不迁移、不归档、不建只读展示，也不要求用户逐项确认。
3. 独立的通用预算、目标、普通手填收入和一般安排能与政策资料分离时可保留，不为其复制旧政策字段。旧国家养老金专项输入没有兼容承诺；按新通用收入入口重新填写。已实际到账的养老金属于真实收入，必须保留。
4. 依赖被删除资料的旧计划统一标为需重新设置相关条件，暂停完整达成判断；不把旧待遇默认为零后发布更乐观／更悲观的正式结论。不要求保留旧测算数值或为其制作前后对照。通用年龄如仍需使用，应重新确认，不偷偷由旧生日派生保留。
5. 旧备份需能提取和恢复保全清单中的事实；允许丢弃旧政策区段，给出简短摘要，不为被丢弃字段保留新的 schema、适配模型、查询入口或回执执行链。旧备份文件本身不改写，恢复事务仍须校验事实及引用完整性；失效的旧专项请求不执行、不恢复删除字段。
6. 保留业务的修订、资料库身份与回执机制照常工作。若混合旧请求已经写入了真实事实，保全这些事实及防重复记录；仅用于退休预测的旧请求无需兼容。不得在还有结果未知的混合写入时假定没有事实发生。
7. 普通表单取消不保存；写入冲突不覆盖后来的修改；失败不能损坏客观资料。代码阶段用虚构旧库验证升级／导出／恢复，不能通过打开或改写正式资料库证明兼容。

## 7. 实施顺序与完成条件

按依赖顺序交付，不能把“隐藏页签”当作完成：

1. 冻结客观事实保全清单、旧政策字段删除清单，以及未来收入和通用时间的最小输入；个人养老金和公积金账户继续由财富模块拥有。
2. 打通简化填写与官方链接，替换目标 Q4、精修卡和补资料入口，收掉专页；不要求用户先访问外部工具才能使用本地功能。
3. 从通用能力、首页、目标、心愿影响、临时试算和受限池中移除旧政策计算依赖；删除医保、停续缴和职业政策联动及其公式、参数、表单和旧模式适配。保留市场模拟与现有深入分析，以通用收入／支出替代旧依赖。
4. 完成旧资料与备份恢复验证，同步当前规则、指南、架构和开发说明，再按维护者安排发布；本文不预占版本或授权安装发布。

## 8. 金融增强：区分资金移动与投资损益

**状态：维护者认可方向，本次细化为第二批交付设计，尚未实施；不扩成完整投资账本。** 当前只有余额变化及不完整收入资料，不能据此精确拆分投资收益和生活支出。

建议增加少量可按月／盘点区间汇总的可选事实：投资范围的投入、取回，以及已收到的利息／现金分红。每条绑定明确账户或范围、期间、金额和来源备注；完整性单独确认，空白不当零。同一期间只用一套汇总，修改原记录而非反复叠加；未来如支持逐笔数据，必须与区间汇总互斥或核对去重。

| 展示内容 | 口径 |
|---|---|
| 工作等非投资到账 | 与投资现金收入分开，既有无分类收入保持未分类，不自动归成工资 |
| 利息与现金分红 | 已收到的投资收入，区别于账户余额上涨；再投资仍是投资收入，但没有额外流出投资范围 |
| 投入／取回及本人账户转账 | 资金移动，不等于赚到或花掉；投资范围内账户互转合计抵消，流向范围外的本人现金账户也不是个人收入／消费 |
| 区间投资损益金额 | 同一范围内：期末总值 − 期初总值 − 外部投入 + 对外取回；对外取回含已分配到范围外的现金收益，不含已扣且应计入净损益的投资费用 |
| 生活支出 | 来自已记录支出或明确的预算；提款不自动归为消费，资产下跌不归为支出 |

区间损益含已实现／未实现变化、现金收益及已反映在账户中的费用，缺少交易成本资料时不再拆成“已实现赚多少／浮盈多少”。它是金额，不是收益率；暂不加 TWR、IRR、逐笔买卖、持仓成本核算、行情或税务计算。实际收支与盘点余额仍是两份不同用途的事实，录入现金收益不自动修改账户余额。

示例：同一投资范围从 100,000 元变为 112,000 元，完整核对期间新增投入 10,000 元、取回 0 元，区间投资损益为 2,000 元；不能把 12,000 元全部叫收益。若投入未知，只显示余额增加 12,000 元与“损益无法区分”，不倒推出收益。

分红／利息已包含在期末余额或上述对外取回时，不再加到区间总损益。资金转出与利息／分红明细引用同一现实发生，不能重复加钱。未来规划若已用总回报率表示含分红／利息的资产增长，不能再把同一资产的预计收益作为额外收入叠加；拆分使用时必须采用不含分配收入的收益口径。社保养老金作为外部收入，不与自有投资总回报混淆。

损益计算仅对起止范围一致、金额完整、期间流动完整确认且无未解释本金更正／实物转入的区间开放。资料不全继续显示余额变化。该增强不自动改写现有“估计存下／推算花销”，更不因投资流动齐全就声称生活收支完整；若后续调整这两项口径，必须单独定义覆盖条件和验收。

最小验证需覆盖：纯投入无收益、纯上涨无投入、提款未消费、内部转账抵消、分红留存／转出／再投资、费用、未知投入、账户范围变化、期间重叠及总回报与分红不重复计入。

## 12. 通用时间、金额与模拟契约

### 12.1 年龄转换与起止月

选择年月可完全不填年龄。年龄模式要求新确认“截至本月的年龄”；可填岁和月，只填整岁时明确按本月达到该整岁换算，展示对应年月供确认，不冒充真实出生时间。转换为计划年月后保存该年月；下个月打开不会把收入或目标自动顺延。

新改年龄参考只影响显示与当前编辑的换算，不悄悄改所有已保存时间；如用户希望同时调整，必须看到将改变的月份再保存。年龄未知时直接填年月即可，图表使用年份／月份，不伪造年龄。

收入从开始月的月末首次进入月账本，结束月为最后一次到账；未填结束月持续至规划终点。这是通用计划规则，不表示官方实际发放日。开始月在资金起点之前表示已进入领取阶段，只向前续算，不补发历史收入。首月不足整月、月初支出先于月底收入等沿用当前账本规则，不能以月底收入抵消月初资金不足。

### 12.2 金额基准

保存用户原始金额及其明确基准月，不因打开页面或更改通胀反复改写金额。计算时统一折算到本次计划基准；选“今天的钱”时保存确认当月，之后显示“按 YYYY-MM 购买力”，不能永远称今天。

设原始金额为 A、其价格基准月为 S、计划金额基准月为 T、开始领取月为 L、年通胀假设为 i；月份之差按整月计算。“领取时的名义金额”对应 S=L，“按某月购买力”对应明确保存的 S。开始月名义到账为 `N = A × (1+i)^((L−S)/12)`。对账本月 M：固定名义模式的基准购买力为 `N / (1+i)^((M−T)/12)`；保持购买力模式恒为 `A / (1+i)^((S−T)/12)`。这两种是假设，不是官方待遇调整规则。不得把原始金额先改写为实际金额后又折算一次。缺通胀且确需折算时该能力不可计算，其他事实仍显示。

收入、费用输入和持久化为整数分；浮点仅用于既有预测过程，输出沿用约数展示，不回写事实。来源金额、起止时间或预算更改后，需求、预测、首页摘要、心愿影响及深入分析使用同批条件刷新。

### 12.3 保留的分析能力

保留固定目标反求、逐月资金覆盖、FI 等既有里程碑、收益／通胀／预算／投入压力、敏感性矩阵、市场路径模拟、收益顺序检查和逐年表。此次不新加模拟方法，不因删除政策公式缩减通用分析。

预计投入未知时仍可计算条件充分的需求；不输出依赖预计投入的市场资产路径、达成时间或成功比例。模拟中外部养老金按用户的金额和起止条件进入，不随机生成资格或待遇。样本比例只代表给定模型、预算和终点下的结果，标注种子／样本数及范围，保持与确定性覆盖的同一判据。

首版规划中的“收益率”明确为所选可用资产的总回报假设。未来收入编辑遇到“自有投资利息／分红”时，说明已由总回报覆盖，不额外加入；外部养老金、租金等普通净收入可独立设置。暂不增加让普通用户拆分资本利得率与分红率的问卷，历史投资收入分类也不自动生成未来收入。

### 12.4 受限资金的最小能力

不重建未来社保缴存、节税或个人养老金复利池。已有个人养老金／公积金余额属于财富事实；未来缴存不从工资或旧政策字段自动推演。基本计划默认不使用尚不能动用的资金。

如用户明确安排一笔未来可用金额，记录“哪一个已有受限账户、何月、预计可用净额”。金额未知则不计入；该金额为该月的名义净额并按规则转换，一次进入可用池，同时退出对应规划受限池，不能在起点已算为可用。大于当前余额的未来金额必须标为用户估计，不能改写当前余额或宣称增值已经发生；不为推导这个金额重建政策模型。此安排不影响账户日常维护，未录入也不催填。

该安排只表达现有受限资产预计可用的金额，不自动包含未来新增的本人现金缴存。若用户把尚未安排资金来源的未来缴存也计入，不能同时把这笔钱留在未来可用净投入中；首版不支持对此自行推导，需移除这部分或明确一般资金转出安排，否则给出未完整覆盖说明，不下完整结论。不能通过手填一个较大解锁金额绕过资金守恒。

## 13. 投资区间核对的最小实现

### 13.1 首版只核对一个组合范围

采用两次完整盘点中、同一集合的已计入投资类账户。类型沿用当前分类，按账户 ID 核对，不凭名称猜测；公积金、现金／存款和负债不自动变为投资账户。个人养老金账户若属于该投资分类，可在此范围内保留其余额，但不因此视为可花现金。

首版不提供任意组合、部分参与比例、逐账户收益率或逐笔买卖。仍可查看逐账户余额变化。两端账户集合或类型不一致时不给组合损益，先说明不可比较；不把新加入账户的整个余额当成收益，也不默认零期初。

### 13.2 两个金额和一次确认

“核对资金流动”显示锁定的区间 `(B0, B1]`、账户列表和两端金额，用户填写：

- 期间从范围外转入的资金合计；不含已留在范围内的利息／分红。
- 期间转到范围外的资金合计；包含取回资金及转出的现金收益，不含应计入损益的投资手续费／税费。
- “已核对这一期间全部转入转出”；零需明确填 0，金额可先留空保存但不能确认完整。

本人投资账户之间互转在组合内抵消，不填入这两个合计。投资账户与本人现金账户之间的移动跨越此投资范围，计入合计，但对全金融净资产不是收入或支出。期间借款加杠杆、证券实物转入转出、未解释余额调整等首版不建模，有这些情形时可保存备注但不能确认简单损益完整。

区间转出合计是唯一计算输入；已记录分红／利息仅在窗口旁作核对线索，不再自动加一次。提示“转到范围外的分红已包含在转出合计中”。只有明细存在并不代表流动完整；也不要求把金融收益明细记全才允许确认两个流动合计。

### 13.3 结果与去重

`区间投资损益 = 期末投资总值 − 期初投资总值 − 转入合计 + 转出合计`。

结果注明“含估值变化、已反映的利息分红与费用；不是收益率”。利息／分红显示为已记录构成，不要求与总损益同号，也不把“损益减分红”叫纯市场浮盈。未关联来源或去向的收入显示在未归属明细，不猜测属于当前投资范围。

实际收入表仍可显示全部已记录收入，复盘把非投资到账、投资现金收入、公积金缴存和未分类项分列；留在投资账户的收入不标成可用于日常花销的到账。未分类不等于工资，更不能用条数证明已记全。

旧“估计存下／推算花销”留在展开的历史参考，维持原有局限说明。新增投资收入类型不直接灌进原工资／普通收入推导函数；若某区间出现新增投资收入或分类更正且旧推导未有经验证的适配，则该两项标“此区间暂不提供旧口径估计”，不展示可能重复计入的数值。净资产事实、投资损益和已记录收入照常显示，不在此次顺带设计准确消费反推或储蓄率。

### 13.4 更正和区间冲突

起止盘点被更正、类型／集合变化、端点删除或引用失效时，保留原流动记录及原期间，撤销计算就绪状态，提示核对。备注更正等不影响金额或范围的编辑不无故作废确认。来源错误单独处理，不能显示为 0。

同一范围内不允许重叠的活动汇总同时参与统计。新增中间盘点后，旧大区间不会按天数摊开：原区间可继续作为单独历史区间查看；新子区间只能在用户明确替换旧汇总后录入，原汇总保留删除恢复语义。恢复会造成重叠时先解决冲突，不自动覆盖。

首版不把多个区间损益年化或自动拼接为收益率。跨区间查看只有在范围一致、区间首尾相接、无遗漏或重叠、各自完整确认时才可合计金额；否则仅并列单期结果和不可合计原因。

## 14. 数据退出、导出与恢复工作

第一批在虚构旧资料库生成“保全清单”：各事实表记录数量、稳定 ID、金额、日期、删除状态、备注、引用，以及托管文件内容摘要。升级后逐项对照，排除预期 schema／字段定义变化，不能仅比较总净资产或数据库文件是否能打开。

按 owning source 枚举待删政策字段，包含混存在 Profile、Core、退休收入选择、缴费安排、缓存／回执及导出中的字段；禁止按包含 pension／medical 的名字批量删除。通用规划中的付款／余债和真实金融账户必须按用途区分。旧社保余额不转换成新金融资产，实际个人养老金账户不误删。

迁移只保留通用计划中能独立解释的部分；需要旧生日或资格才能解释的年龄／时间一律待重设。应用首次展示给出一次简短说明“物品、账户和盘点已保留；退休政策资料已移除”，不用逐字段迁移向导。既有导出文件和用户旧备份不改写。

旧整库恢复先在隔离数据集中验证、提取事实并执行相同删除规则，再用既有完整恢复事务切换。删除政策区段不能成为跳过账户、附件和外键校验的理由；任何事实损坏仍中止恢复。实施需覆盖当前可恢复的旧 schema 范围，而不是承诺任意历史格式。

第二批新增收入分类和投资区间的 Excel 导出及完整备份必须随保存能力一起交付，包含未知／零、区间、范围和确认状态。收入导入增加可选分类与账户映射列，缺列按未分类，外部编号沿原导入去重规则；投资区间首版可只提供手填及导出／完整恢复，不扩展通用券商导入。旧模板继续导入事实，新列不支持时不得静默丢弃。

完整备份承诺保全新增资料；Excel 是可阅读分析／迁入格式，不声称替代完整备份。新版数据不可被不支持其 schema 的旧程序写入，不为实现降级安装而恢复旧政策适配。所有错误、取消、冲突、写后失联都复用现有事务与回执机制。

### 16.2 必须通过的验收

- **新用户**：从空库记录物品、账户和盘点，不填任何退休资料；能独立记录收入。进入规划用四问保存“不计收入”或简单养老金月收入，不见地区／医保／缴费参数。
- **旧资料**：不同旧政策模式、只有社保资料、混合通用计划、真实个人养老金／公积金账户，均按保全／删除清单验证；失败回滚。保留原事实 ID、字段、软删除状态、附件和导出内容。
- **时间与金额**：年龄参考跨月不漂移、年月模式无年龄也可用、收入开始前后及结束月、已在领取、名义／购买力、修改通胀不改原始输入、首月部分期、零与未知。
- **资金边界**：已含费用不重扣、受限余额不提前可用、计划转池只发生一次、不自动生成真实收入／资产、不双算总回报与分红。
- **分析保留**：简化前后用等价的显式通用现金流夹具比较需求、月余额、逐年表；保留市场模拟固定种子、样本数及覆盖判据，专项政策结果无须一致。
- **金融复盘**：§13.5 全部样例；分红明细有无不改变已完整确认的总损益；未分类、未归属、未知转入、账户变化、区间重叠、盘点中途插入／更正／删除恢复各状态。
- **保存与携带**：普通取消不写入，重复提交不重复记录，过期 revision 拒绝覆盖，结果未知可核对；新增字段 Excel 导出和完整备份恢复后语义一致。
- **界面与原生**：同为 1440×1000 的前后对照，另验窄窗口与明暗主题；正常、未知、空白、错误均可操作。原生保存、重启、备份／Excel 选择器、键盘焦点、Esc 与输入法、VoiceOver 单独记录。
- **检查和文档**：运行 `npm run build`、`npm run test:ui`、`npm run check`、`npm test`；更新 PRODUCT_RULES、USER_GUIDE、ARCHITECTURE、DEVELOPMENT 和 INDEX，移除仍引导旧政策输入的截图／文案，核对离线指南。未验项目如实保留，不以浏览器代替原生。

### 16.3 完成的判断

第一批完成意味着政策引擎、编辑路径、数据字段和消费者依赖均已退出，事实可用且可恢复，普通收入可参与全部保留的分析。第二批完成意味着用户只需维护真实到账和每期两个资金流动合计，就能区分余额变化与区间投资损益；资料不完整时诚实降级。新增填写负担不得扩散到只用物品或只做资产盘点的用户。

## 2. 共用页面结构与视觉规则

统一顺序为：**页标题与主要操作 → 页签和期间／范围 → 摘要 → 内容明细 → 依据与说明**。

- 复用 `HeaderSlot`、`usePageBar`、`Segments`、`SortHeader`、`DateInput`、金额输入、现有 SVG 及 `theme.css` 令牌，不另外建立一套卡片、弹窗或按钮风格。
- 账户与盘点的“显示账户”筛选与页签分开：概览放在账户清单内，账户页放在列表上方，并注明不改变净资产汇总。页面只注册一份顶栏操作。内嵌收入／支出／资金流动组件不再各注册旧一级页面顶栏；弹窗关闭回到实际触发按钮，触发元素消失时才回页标题。
- 金额右对齐、统一精度与等宽数字；变化显示正负号，不能只靠红绿传达。未知显示“待补充／待核对”，读取失败显示失败原因，模块关闭显示关闭状态，均不显示为零。
- 摘要最多一排四项；无适用结果时显示简洁说明，不摆一排无意义的零。依据与历史参考默认收起，影响结论的限制直接放在数字旁。
- 1440×1000 和 1600×1000 下采用同一内容边界；900×720 下摘要两列、操作换行；更窄时单列。详细表格可在自身容器内横向滚动，页面不得横向溢出。
- 三套主题及明暗外观均复用现有语义；不改全局导航宽度、窗口偏好或主题设置。
- 普通表单关闭不保存草稿，确定失败保留当前输入；提交结果未知保留原请求并提供核对入口，不允许通过换页产生第二次提交。

### 2.1 期间、搜索与记忆

收支记录共用“全部／年／月／自选日期”期间控件，默认全部，保留原重要支出的跨年回顾。选择有效期间立即刷新，不再提供“应用期间”；未完成或无效日期只留在本地输入中，继续展示上一有效期间并提示。当前会话内切页签保留期间；搜索、排序、展开项与滚动按页签分别记忆。只保存浏览状态于内存，不写入资料库或备份。

日期期间和明确的数据范围决定摘要；关键词搜索只过滤明细，摘要标注“期间合计”，搜索结果单独显示条数，避免搜索被误认为改写本期总额。不要在一个页签按搜索重算摘要、另一个页签保持全期而不作说明。

记录页日期包含两端 `[开始日, 结束日]`。本期复盘严格使用 `(期初盘点日, 期末盘点日]`。从复盘跳往记录页时传递真实排除起点的边界，显示“本期记录：期初次日至期末”；日期换算使用本地自然日，不用 UTC 毫秒运算改变日期。

普通侧栏切换收支记录／财务复盘不建立来源返回上下文；来源跳转在标题附近显示带明确页面名的轻量返回链接。从复盘带来的范围为一次明确的来源上下文。返回复盘恢复原区间、投资集合、展开项和滚动；从来源记录返回收支记录恢复页签及筛选。当前返回上下文只有一层，多步来源跳转时最近一次返回覆盖更早上下文，不承诺完整导航栈。主动改变筛选后说明已离开原复盘范围，不继续标成原区间。切库、恢复资料或关闭相关模块时清理失效上下文，迟到响应不得重新定位。

## 3. 收支记录

```text
财富 ／ 收支记录                                记一笔收入
收入    重要支出    资金流动
期间：全部／2026 年／10 月／自选日期               搜索收入
期间摘要
记录表格
资料范围与计算说明
```

首次进入默认选第一个启用的页签，顺序为收入、重要支出、资金流动；会话内恢复上次页签。来源跳转明确指定目标页签，优先级高于会话记忆。不提供混合三种事实的“全部流水”页签，不合计收入、转账和支出为一个金额。

### 3.1 收入

摘要显示已记录到账、记录笔数、公积金缴存及其未知情况；构成沿用未分类、非投资收入、利息、现金分红、其他投资现金收入。公积金缴存单列，不并入可日常花用的到账。

列表保留到账日期、分类、到账金额、公积金缴存、备注；账户来源与去向按需展示。新增／更正复用原表单、分类及保存协议；来源账户选填，关闭账户模块时不可新选账户，但已有引用必须保留，不能被隐藏控件清空。

无收入记录显示“尚未记录”，不等同于确认本期无收入。普通新增不依赖目标、盘点次数或投资核对；日常“记一笔收入”只在业务记录流程出现，不放进设置。收入历史导入统一从设置的数据管理进入，继续使用原 Excel 工作簿协议，也不依赖目标；不新增 CSV 或资金流动回导。

### 3.2 重要支出

保留已记录支出、退款、净支出、售出回收四项摘要。主复盘摘要采用“已记录重要支出（退款前）”；退款和售出回收在本区单列，售出回收不混入实际收入分类或从消费额中隐式扣除。

原多来源支出投影继续作为唯一依据：物品购入／维护、独立支出、周期实付、虚拟资产相关实际支出。去重按已有来源规则及稳定引用进行，不按名称、同额或同日猜测同一笔。

- 已存在的物品购入与维护不再要求手填一笔支出；从明细打开原档案更正。
- 已关联虚拟订阅与周期付款沿用共享事实，不能把权益档案和付款各算一次。
- 未来排期、月均折算和累计估算不是实际付款，不进入已发生支出摘要。
- 全部期间保留年度柱状图，点年份进入月度图；月／自选范围显示相应明细与摘要，不强造日级图表。
- 日期未知的记录放在“日期待补”独立区，注明是所有可见但无法归期的记录，不计当期合计，也不强分配进某年某月；金额未知保留条数和局限。没有记录的中间年份不补成已确认零支出。
- 摘要与列表来自同一期间、同一来源范围。模块关闭时沿用来源可见性，见[开关与读取](#modules)，页面明确“仅包含已启用来源”。

### 3.3 资金流动

显示结算日、转出端、转入端、金额、用途、关联来源和需复核状态，提供日期／账户筛选。记录页仅保留顶栏新增操作，明细卡片按筛选、记录、折叠说明分区；金额右对齐，转出／转入分行展示，空状态与读取失败分开。发生日期复用共用日历，新增默认今天。默认只显示记录笔数及两端信息，不把所有转账金额包装成收入或支出总额。未选投资范围时不显示“投资净转入”之类依赖范围的指标。

保留原新增、更正、删除／恢复与来源关联能力；至少一端为可维护账户，金额必须已知且为正。记录流动不修改盘点余额、不生成收入／支出，不推导借款本金或利息。

核对方式、投资范围及完整性确认继续属于财务复盘。记录页可提示某次更正使相关区间待复核并链接该区间，但不能代替用户重新确认。原复盘中的完整列表移到此处；复盘只显示所选区间／投资范围的摘要与按需展开明细，复用同一列表展示能力。

## 4. 财务复盘

### 4.1 本期复盘

默认最近两次完整盘点之间的区间，选择器可回看其他相邻完整盘点区间。由来源跳入时优先选择指定期末盘点，不因重新读取悄悄回到最新一期。

```text
财富 ／ 财务复盘
本期复盘    盘点比较
盘点区间：2026-09-30 → 2026-10-31               共 31 天

净资产变化      已记录收入      已记录重要支出      投资损益
含估值变化      不代表已记全    退款前／可能不完整  已核对或待核对

资产变化       资产／负债变化；展开逐账户比较 → 原盘点
收支回顾       收入构成；重要支出去向；退款与售出回收 → 明细
投资回顾       投资范围、期初／期末、转入／转出、损益 → 核对
待核对资料     只列当前区间有关的事实缺项与失效依据
历史参考       保留旧估计与局限，默认收起
```

四项摘要相互独立，**不画“收入－支出＋投资收益＝净资产变化”的必然等式或瀑布图**。重要支出不是全部开销，资产变化还可能有未记流动、受限资金与范围变化。收入减重要支出不得命名为真实结余／储蓄率。

资产变化复用 `wealth_compare` 的逐账户变化、资产与负债方向及范围差异解释。详细表不重复本页顶层摘要与日期选择器；账户显示筛选不改变比较合计，标题附近说明当前显示范围。

收支回顾与收支记录使用同一来源投影与期间规则。点击摘要可展开该区间明细；“查看全部记录”带范围跳转，补记后回到原区间。收入分红可在收入构成中显示，但不能再加到投资损益。

投资回顾保留两种核对方式：直接填区间转入／转出合计，或由资金流动明细汇总。二者互斥；保留切换预览、完整确认、区间重叠、来源变更失效与审计行为。没有投资账户时显示一句“本期无适用投资账户”，不催填。

未来计划缺项不进入财务事实的必填清单。已启用规划时，可在页底显示独立的“与当前目标有关的安排”，跳到目标核对实际发生接续；关闭目标或目标读取失败不使财务复盘失效。原发生确认／撤回能力须在目标侧保留等效入口，不能因拆组件而删除。

### 4.2 盘点比较与单账户历史

原“变化”工具允许任意两次盘点和不完整历史记录，不能被只允许相邻完整区间的本期复盘替代。

保留“盘点比较”页签，可自选起止盘点、看逐账户影响、结构变化、未计入账户和单账户历史。不完整端点显示已知部分及缺项；不输出可比较净资产或投资损益。该视图仅比较余额事实，不同时展示另一套本期收支。

两种视图复用账户比较表与领域结果。相邻完整端点提供“查看这一期完整复盘”；其他端点显示“当前为自选盘点比较”，不伪造投资区间、不合并或摊分已有核对。账户页的单账户详情也能进入历史，避免只盘点一次时失去原历史能力。

### 4.3 起步与降级

| 条件 | 展示与下一步 |
|---|---|
| 没有账户 | 说明盘点需先建账户；收支入口按模块仍可用 |
| 零次／一次完整盘点 | 展示起步状态和记录入口，不放收益空表；盘点比较可读单账户历史 |
| 没有收入或支出记录 | 相应摘要“尚未记录”，资产变化与独立完成的投资核对仍可看 |
| 两端账户计入范围变化 | 不可直接比较的净资产明确标注；查看受影响账户，不把差额当收益 |
| 投资转入／转出未知或未确认 | 显示余额变化及待核对原因；不将空值补零 |
| 收入或支出部分读取失败 | 局部失败／重试，其他已读取事实保留；不给失败部分旧金额冒充最新 |
| 端点被删除或更正 | 原区间失效说明与重新选择；不把旧确认套给新端点 |
| 没有待核对项 | 一句状态，隐藏空清单；不显示“财务已完全核对” |
| 目标关闭／无目标／目标读取失败 | 财务事实照常；目标附加区关闭或局部失败，不读取隐藏规划 |

## 5. 账户、周期费用与目标的接续

账户与盘点保留“概览／账户／盘点记录”。概览保持净资产、资产、负债、最新盘点日期、曲线和结构；简短变化摘要链接财务复盘。盘点保存后停留保存结果，提供“查看这一期复盘”，不强制跳转或填写收入。第一期只提示“已建立起点”。

周期费用继续管理未来安排与实际付款。保存实付后可打开收支记录中的对应来源；不自动新增一条独立支出。虚拟订阅仍共用现有计费与付款关系，整组删除／恢复不变。

目标页只维护未来条件与结果：四问、可用资金、预算、预计投入、未来收入、房车与购买安排、资金续航及深入分析。移除收入新增、实际收入列表与整页财务复盘；已保存目标不因导航重组重新填写。

目标引用盘点及事实，但不会从历史收入自动写入预计投入，也不从重要支出自动推荐完整生活预算。未来养老金／固定收入不生成实际到账。目标“查看事实依据”跳往对应盘点或复盘并可返回原目标位置；保留预计与实际发生的核对、撤回入口及原请求回执。

<a id="data-management"></a>

### 5.1 导入与导出统一到设置

设置中沿用现有资料管理能力，名称统一为“数据管理”，不新增一级侧栏栏目。按用途分为三个区块，避免把日常记录按钮放进工具区：

```text
设置 ／ 数据管理

导入与导出
  导入资料…             选择：物品表／金融历史
  导出全部表格（Excel）…

备份与恢复
  创建完整备份…         从备份恢复…
  自动备份设置与已有备份

资料恢复
  最近删除
```

“导入资料”选类型后复用现有两个导入流程：物品表只新增不覆盖；金融历史使用一个工作簿的账户、完整盘点、月度收入工作表，可只填收入，也可组合三类。首版不宣称一个事务同时导入物品与全部金融事实。模板下载与虚构样例放在对应导入流程内，不在每个业务页重复摆放。

- 账户、收入、支出、复盘的常规顶栏与更多菜单都不放导入／导出按钮；需要帮助时只用说明文字指出统一位置。导入与导出不进入“新增记录”菜单。
- 设置提供一个完整金融历史宿主，取代原账户／收入两个模式入口；窗口标题和说明使用“数据管理／导入金融历史”，不再显示“规划／收入”。
- 导入完成先展示回执与新增／更正／跳过等实际结果；冲突在提交前处理。再提供“查看收入记录”“查看账户”“查看盘点记录”等相关操作，用户主动选择后跳转，不自动离开回执。
- 旧入口收到兼容意图时定位设置的对应导入类型，实际模块校验、系统文件选择、预览、取消、整批提交和回执保持原义。
- 样例库继续沿用现有限制；普通关闭取消未提交预览，不存草稿。设置中有导入预览或提交时，备份／恢复／切库等互斥操作受同一锁约束。
- 未知导入回执在设置里可直接“核对上次导入结果”；全局待核对提示链接这个恢复入口，即便关闭收入模块或旧业务页已移除也能只读查回执，不能被通用 blocked 状态挡在设置外。跨库只读核对仍遵守原请求与 generation 约束。
- 导出继续提供原完整分析工作簿，不冒充备份或新增“所有表可回导”的承诺。完整备份／恢复与 Excel 明确分开；本轮不新增当前筛选导出、财务 PDF 或银行格式导入。

业务模块关闭只控制业务使用与自动读取；用户在设置中明确执行的完整导出／备份继续覆盖原有完整资料，不因为隐藏模块丢掉历史数据。导入仍按所选工作表逐项检查实际模块能力，绝不自动启用模块或静默漏表。

## 6. 模块开关、旧设置与读取边界

不能只移动按钮。基线中 `planning_sources` 将收入和复盘与目标资料一起受 `planning` 控制；收入导入也检查 `planning`；资金流动检查 `planning && wealth`。独立财务页面必须解除这些耦合。

### 6.1 能力归属

| 能力 | 目标开关／可用条件 | 关闭影响 |
|---|---|---|
| 账户与盘点、资产比较 | 原 `wealth` | 不读该模块，不提供新盘点或比较 |
| 收入记录 | 新独立 `incomes` | 收入页签、摘要及新建／导入隐藏或标已关闭 |
| 重要支出 | 原 `expenses` | 支出页签及该复盘分区关闭 |
| 资金流动 | 新独立 `movements` 且 `wealth` 开启 | 不列明细或新增；不强制打开账户 |
| 投资区间核对 | `wealth` | 手填核对可用，不要求目标或收入开启 |
| 由明细汇总投资核对 | `wealth && movements` | 关闭明细时，不偷偷切到手填；原明细核对暂不计算并说明需启用来源 |
| 未来目标及发生接续 | 原 `planning`，界面名改“目标规划” | 只关闭目标与计划附加区，不关财务事实 |
| 周期费用、虚拟资产 | 原 `recurring`／`virtual` | 保留各自入口及来源可见性约束 |

收支记录在任一可用页签存在时出现；财务复盘跟随账户与盘点出现。只有收支、没有账户时仍可在收支记录中查看期间摘要；不新增无资产基础的空复盘页。空分组不显示。

收入来源关闭不影响只用盘点和流动核对的损益公式，但不能展示隐藏收入金额。资金流动中已关联的关闭来源显示“来源模块已关闭”，保留稳定引用；新增选择器不查询该来源。已有来源的事务一致性与删除保护仍须验证，关闭模块不是解除引用或改变事实的动作。

“不读取关闭来源”指面向页面的展示读取和候选查询：应在 SQL 来源分支执行前选择，不查询全量后仅在前端隐藏。写事务的最小引用校验、删除保护及完整备份验证可以内部检查必要事实，但不得把隐藏来源的标题、金额等返回业务展示。两类读取明确分开，不能用隐藏展示为理由取消引用保护。

支出投影统一尊重来源模块：独立支出／退款使用 `expenses`，周期实付使用 `recurring`，虚拟相关来源使用 `virtual`，物品来源沿用物品统计排除规则。重要支出页签关闭时不从复盘绕过它展示合计。关闭来源不会改写余额、投资公式或历史确认；仅影响可展示来源和可用核对方式。

### 6.2 旧设置转换与兼容

新增两个可选能力而不默默启用旧用户隐藏的内容：旧设置缺少独立值时，`incomes = 原 planning`、`movements = 原 planning`；资金流动实际可用性再与 `wealth` 组合。原 `planning` 留作目标规划，其他值原样保留。新安装沿用全部开启的默认策略。

建议将两个新能力保存为同一应用身份下的独立版本化偏好文件 `finance-modules.json`（版本 1），不修改旧 `modules.json` 的持久化字段结构。原因：旧版 `Modules` 使用 `deny_unknown_fields`，直接增加字段会使旧版解析失败并回退为全开。运行时 `modules_get/modules_set` 可返回合并后的能力，前后端类型同步。

- 初始化在模块设置拥有方串行执行；新文件缺失时由旧值派生，原子写入两个值及版本。正常读取不每次重新跟随目标开关。
- 必须在第一次修改旧模块偏好之前完成初始化；初始化失败则保留原设置并明确报错，不能先关闭目标再把收入也推导为关闭。
- 先成功保存继承值、随后旧设置保存失败时，能力仍等同于修改前，允许重试；不得以多文件写入假装一个数据库事务。
- 文件存在但损坏、版本不支持时提示设置读取失败；新能力暂不可用并提供修复入口，不以“全开”覆盖有效旧偏好。正常历史缺字段与坏文件分开处理。
- 旧 modules.json 不存在按原新安装默认处理；文件存在但损坏则不能从旧读取函数的“回退全开”结果继承新能力，新能力明确关闭并附配置错误状态。新偏好错误同样返回明确的 false 与错误状态，不用缺字段触发 T01 的 planning 回退。
- 修复在设置中由用户明确选择两个新能力后重建；重建前原样保留损坏文件为可定位的诊断副本，备份失败则不覆盖。未知较新版本不自动降级或重建，先报告版本不支持。旧模块配置的修复沿用其拥有方，不能借修复新文件覆盖原八项选择。
- 新偏好包含单调递增的修订，成功变更能力时递增；导入预览依据同时绑定有效能力、原模块文件变化及新偏好修订。收入或账户开关关掉再打开，旧预览仍须重新核对，不能只比较最终布尔值。
- 旧应用忽略新文件，原八项设置仍能正确读取；旧版改变目标开关不改新版已拆开的收入／流动偏好。偏好属于本机应用身份，不进入资料库备份，样例与个人资料沿用相同设置。
- 不新增业务表或预占 schema 版本；若实际实现需要持久化新业务事实，须先更新设计，不能借导航调整搭建第二套账本。

### 6.3 读取与保存

财务记录和复盘使用独立事实读取入口，不再借一个开启的规划开关取得数据。前端不能伪造 `planningEnabled=true`。Worker 在一次任务中读取实际模块偏好和当前资料库，聚合数据在同一读事务内保持一致，返回 `generation`、读取版本和分来源状态。

目标读取端只服务目标。收入、支出、账户与流动的单页加载可分别失败；复盘使用同一期间／快照的聚合读取，避免把前一次收入与后一次盘点拼成一页。已有保存命令、指纹、稳定 ID 和回执尽量原样复用。

关闭开关不取消已提交事务，也不能阻断未知回执查询；冻结重复提交，先核对原请求。正常写入、来源候选、导入预览与最终提交使用新能力归属，不能只在 UI 隐藏。混合工作簿任一参与工作表模块关闭则整批拒绝并要求重新预览，不默默跳过表。

收入的新写入包括保存、更正和通用删除／恢复端口中的 income 分支；内部导入／恢复验证不复用面向新业务操作的展示门控。投资核对的新旧读取入口都必须遵守流动开关：手填模式关闭流动后仍可计算且不查流动表；明细模式暂不可用，不改模式、不回写确认。单独改资金流动列表的开关不足以关闭旧投资读取里的明细计算。

## 7. 共用事实口径与接入契约

### 7.1 金额与去重

- 金融净资产始终来自盘点；实物购入成本不加入净资产，收入／支出／转账不再次修改余额。
- 投资损益沿用 `期末 − 期初 − 外部投入 + 向外转出`，同一已计入投资集合、可比较端点和完整确认是前提。内部转账抵消；分红与利息不再加一次，投资费用沿用原规则。
- 收入分类总额、支出及退款投影、期间流量分别有唯一领域拥有方。统一页面复用结果，不在三个组件各实现一套加减。
- 每笔展示来源使用类型加稳定 ID；派生支出可查看／打开原记录，不能另存可编辑的复制金额。
- 支出与流动的关联用于解释，不能把二者相加；暂不扩展原仅支持收入与独立支出的流动来源选择器。
- 未知金额、日期、完整性和范围变化保持显式状态；零必须是明确金额或空集合的已记录合计，不能表达全部事实已齐全。

### 7.2 只读模型

以下为逻辑契约；当前实现由 `finance-contract.ts`、`finance-service.ts` 及 Rust `finance_sources.rs` 承接，模型之间显式适配，不能直接混用客户端与原生形状：

| 模型 | 必需内容 | 约束 |
|---|---|---|
| 记录期间 | 模式、开始／结束自然日、开始是否包含 | 年／月只是明确日期范围的便捷选择；无日期另列 |
| 复盘选择 | 模式、起止盘点稳定 ID、投资账户 ID 集合 | 本期复盘为相邻完整端点；盘点比较不生成投资核对 |
| 来源状态 | ready／empty／partial／disabled／error；已知与未知条数 | 空记录不等于完整确认；关闭与错误不混用 |
| 支出期间投影 | 所选范围行、无日期行、支出／退款／回收与已知未知计数 | 列表、分类、摘要、图表由同一投影派生 |
| 财务复盘读取 | generation、write_version、模块能力、区间、逐来源结果 | 目标资料是可选附加区，不作为根加载依赖 |
| 导航意图 | 目标页／页签、来源 ID 或区间、返回上下文 | 携带 generation；来源失效不得匹配同名记录 |

现有 `expense_view` 只有全部／年度过滤，不能仅改控件就声称支持任意日期。实施须抽取共享日期范围投影并为新页面提供只读端口；旧 `expense_view(year)` 暂作适配包装，保留接口形状和全部相关模块开启时的数值。关闭来源后的结果按新可见性收缩，不把旧隐藏来源泄漏当兼容承诺；全量导出仍独立覆盖完整事实。`plan_interval_reasons(snapshot_id)` 使用相邻完整端点，不能假装支持任意两端；其范围逻辑与新聚合复用，原历史估计单独保留。

## 8. 分批实施与交付依赖

每批均是完整可验证路径，不一次替换全部页面再找回归。详细执行记录另行维护，公共构建不依赖私有计划。

| 批次 | 可交付行为 | 前置条件 | 完成出口 |
|---|---|---|---|
| A：能力与事实接缝 | 收入／流动独立于目标开关；旧偏好正确继承；共同期间投影可读 | 本规格、现行保存和模块边界 | 开关组合、旧设置、收入导入、期间边界、局部失败与旧回执测试通过；旧页面仍可工作 |
| B：收支记录与数据管理 | 三类记录统一入口、期间和返回；导入／导出集中设置；周期实付正确钻取 | A 的模块与查询契约 | 三类记录新增／更正闭环，设置导入→回执→查看记录可用；年度回顾和未知状态保留 |
| C：财务复盘 | 相邻区间摘要、收支回顾、投资核对及独立盘点比较 | A；B 的明细及来源导航 | 保存盘点→复盘→补记／核对→返回同区间闭环；任意比较保留 |
| D：目标与全局收口 | 目标页职责收敛、旧入口退出、总览／时间轴／搜索／设置／快捷键一致 | B、C；目标实际发生入口接续完成 | 无旧侧栏重复入口；全模块开关、恢复与异常回执可用；有效文档同步 |
| E：联合验收 | 同尺寸对照、自动检查、隔离原生核心路径 | A–D 整合 | 下表全部验收或明确登记未验项；没有原生证据不写原生已通过 |

A 的模块持久化与读取契约先于页面工作；主导航及共享返回状态集中接入，避免多个批次各改映射。A–D 已接入当前源码，E 已完成主审、自动检查、浏览器矩阵及隔离原生核心流程；不能以任务切片的独立检查代替联合结果。T03 按收入命令、流动与投资核对、导入三个顺序单元拆分；T05 先分离资产与历史收入依赖，再接原生聚合端口；T04 的真实来源门控依赖 T02 能力快照。不得让多个开发任务同时修改 Worker／IPC 注册或同一页面宿主。

## 11. T01 独立开发接缝

`src/finance-contract.ts` 和 `src/finance-navigation.ts` 提供纯类型与函数，现由真实页面、主导航与原生服务接入层使用，同一日期、能力及导航语义不另起一套。纯契约仍不负责持久化或后端授权。

| 导出 | 责任与调用边界 |
|---|---|
| `FinancePeriod`、`normalizeFinancePeriod` | 全部／年／月／自选范围；严格校验自然日，非法值抛 RangeError，调用表单必须转为字段提示 |
| `financePeriodContains`、`reviewRecordsPeriod` | 日期待补不归期；复盘采用排除起点的范围，不按 UTC 毫秒加减日期 |
| `financeCapabilities` | 推导页面能力；新字段缺失仅用于可信旧配置的一次继承，T02 完成后总是传明确值；不持久化、不授权后端写入 |
| `FinanceSourceState<T>` | 客户端状态为 ready(value)、empty、partial(value/knownCount/unknownCount)、disabled(reason)、error(message)；empty 不生成数字零 |
| `FinanceRoute`、`legacyFinanceRoute` | 固定业务目标与旧意图映射；保留稳定 ID，批量导入／导出只去 data-management |
| 页签选择与 `financeRouteAvailable` | 会话默认页签与明确来源意图区分；能力判断不承担来源存在性、来源授权或后台校验 |
| `FinanceReturnContext`、`validFinanceReturn` | 同一 generation 且原路由仍可用时保留浏览上下文；数据库实际来源仍须重新校验 |

原生 `finance_sources` 由 `finance-service.ts` 显式适配为客户端状态；原生 wire shape、错误码及整数分金额结构仍以真实后端端口为准。记录来源与页签匹配、区间 ID 的实际可比较性、回执与模块权限由真实接入层负责。

针对性测试：`node --test tests/finance-workspace-contract.test.mjs`，覆盖自然日、闭开区间、能力组合、旧入口和返回失效。该验证不代表新页面、模块偏好迁移或原生功能已验收。

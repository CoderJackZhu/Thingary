## 产品范围

个人物品档案与金融净资产盘点并重，关注低频记录、长期回顾。重要支出、周期费用与虚拟资产是可开关的辅助模块；关闭模块不删除资料。当前不做日常流水、账号／云同步、AI、行情与交易、按量或按使用时长的成本模式。

## 金额、日期与未知值

- 当前以人民币 CNY 记录，不提供汇率或多币种计算。金额用整数分保存，展示时舍入；不能用浮点数累计金额。
- 未知金额／日期保留为空。零金额是明确事实，例如赠品或没有欠款；未知不能填成零，汇总须表达不完整及未计入数量。
- 日期使用本地自然日和 `YYYY-MM-DD`。新增物品购入日期默认今天，可改或清空；购入与生命周期事实不使用未来日期，未来计划放在心愿中。
- 同名物品可以存在，保持各自稳定 ID；名称不能代替对象身份。

## 物品与生命周期

名称是物品的最小必填资料。价格、日期、分类和封面可缺失。使用中与退役都属于仍持有；售出后不再属于当前持有。保障是否有效与物品状态分别判断，不用“保障中”覆盖生命周期。

不用、送人或丢失记录为退役；卖出记录为售出；录错、重复或退货记录使用删除。售出需要实际售价和日期，售价允许为零，未知购入价不阻止售出。维护费用、保障和生命周期日期须与已知持有区间一致；未知日期不伪装为有效保障。新建物品时开启保障，默认从购买日期起一个自然年，购买日期未知时从今天起，结束日期可修改；闰年 2 月 29 日顺延到次年 2 月 28 日。新建表单更改购买日期时，默认保障日期随之更新，手动修改的结束日期保留；此默认值不改写已有保障。

维护类型包含“配件”：Mac mini 底座、灯光透镜等依附主物品的配套花费按维护费用计入总投入、日均成本与重要支出。已单独作为物品记录购入价的配件不重复记维护费；需独立管理或可在多件物品间共用时，可单独建档。

心愿清单是大额购买的考虑清单与决策记录。新心愿默认“考虑中”，名称为唯一必填；预计价格、考虑理由（复用备注，界面标签为“想买的理由与顾虑”）、链接与计划日期均可空；新心愿表单不提供分类、渠道与置顶，添加日期自动记录且不可改，旧记录已有的分类、渠道、置顶值仍可见、可改可清除。购买必须明确确认：“已买到，记录购入”以实际输入创建物品（预计价格仅作参考，不当作实付金额），或显式关联一件已有物品；一次确认只建立一个稳定关联，重复请求与结果未知的回执只对应同一件物品。“不再考虑”保留档案与图片，可“重新考虑”回到考虑中并更正决定备注；已购入不通过改备注撤销，误记购入须到关联物品核对。心愿可在“更多资料”中选择一件在册未删除物品作为“考虑替换的物品”：此关系与购入关联是两条独立关系，设置或清除不修改该物品的任何资料；新物品购入不自动退役、出售或删除旧物品，不推断二手价值，也不从预计价格中扣减。原物品退役或售出不自动取消这条关系；物品进入最近删除时显示“原物品在最近删除”并提供恢复入口；永久删除后有效关系清除，仅保留该物品的名称作为失效关系的展示历史，可在编辑心愿中明确清除，不按同名重新绑定；仅编辑其他资料时保留失效名称。原物品已在最近删除时，保留原关系不阻止编辑心愿，新选目标仍须未删除。计划日期到达不改变状态；提醒为当日 9:00 单次通知，考虑中以外状态与删除、关闭模块时撤销，重新考虑不自动恢复。删除心愿不删除已购入或旧自动生成的物品。

旧攒钱兼容：`decision_state` 为唯一权威状态（考虑中／已购入／不再考虑／历史待核实），旧 `status` 只是兼容投影。攒钱写入已停用，旧 `saved_cents`、模式与来源保留为只读历史；攒钱自动实现与来源不足的旧已实现记录迁移为“历史待核实”，原自动生成物品转为只读的历史生成关系（不删除、不重复生成、不回退用户编辑）。手动／转换实现但缺少关联物品的合法旧记录同样转为历史待核实，保留旧实现日期并提供显式补录入口。核实表单加载原物品现值后才开放输入；未改字段不写回，修改以加载时的物品修订校验，冲突不得覆盖后来更正。历史待核实经三种核实处理：确实已购入（明确复用原物品，可补录实际价格／日期，原物品在最近删除时先恢复）、尚未购入继续考虑（清空有效购入关系，保留历史关系）、不再考虑。升级不自动清理旧版生成的物品，旧请求回执只核对不补执行。

## 成本与售出保值率

| 指标 | 口径 |
|---|---|
| 当前持有数量 | 未删除的使用中与退役物品 |
| 当前持有物购入金额 | 当前持有物已知的实付购入价合计，不是二手估值 |
| 历史购入金额 | 所有未删除物品的已知购入价，包括售出与退役 |
| 期间购入金额 | 按已知购入日期归入期间；日期未知不归入某个月 |
| 总投入 | 购入价＋维护费用（含升级、配件） |
| 净生命周期成本 | 总投入－售出回收金额 |
| 日均持有成本 | 总投入÷持有天数 |
| 首页物品日均成本 | 当前持有物品的已知日均成本逐件合计，不含金融账户与周期费用 |
| 售出后净日均成本 | 净生命周期成本÷截至售出日的持有天数 |
| 按次成本 | 按已记录的使用次数计算；缺少有效次数不计算 |
| 售出保值率 | 售出价÷购入价；不含维护费，购入价未知或为零不计算 |

持有天数＝`max(1, 截止日与购入日期的自然日差＋1)`；截止日为售出日或今天。购入当天算一天，售出后天数固定；退役仍持有，因此持有成本继续摊薄。购入日期未知不展示天数或日均成本，成本资料不完整须明确提示。

首页日均合计只取未删除的使用中与已退役物品。每件复用现行日均成本（四舍五入到整数分）后相加，维护费计入；售出后不再参与当前合计。遵守“不计入日均成本”，总金额／统计页的排除选项独立，不连带排除日均；按次计费另列未参与件数。缺少价格、日期或有未知维护费的物品不当作零；显示已计入、资料不全、按次与排除数量。有物品但没有任何可计算日均时显示未知；空资料库显示零。存在未知项且已有可计算值时明确显示“仅已知部分”。此指标是历史成本摊算，不代表每天实际支出，也不是总购入金额除以平均持有时长。

例如购入 ¥16,999、维护 ¥300、售出 ¥5,000、持有 1,000 天：总投入 ¥17,299，净成本 ¥12,299，毛日均 ¥17.30，净日均 ¥12.30。售价超过总投入时净成本可以为负，不截断成零。

售出统计区分每件同权的平均保值率与按金额加权的总回收率。已删除、不计入统计、购入价未知或为零的物品不参与保值率计算，并说明未参与原因。累计购入曲线出售后不回减；它不表示当前财富。

## 账户、盘点与金融净资产

只记录账户名称、类型、方向、日期和余额，不需要卡号或登录凭据。负债填正的欠款金额，计算净资产时扣除；可将贷款等账户排除于净资产。账户有盘点历史时按停用规则处理，不删除历史事实。

金融净资产＝计入账户的资产余额－负债欠款。物品购入金额不加入金融净资产；已经反映在账户余额里的购买，不再次扣减。

一次盘点一个日期，同一天再次盘点更正原记录。对照各平台逐行填写本次金额，所有应盘点账户都填齐才可保存；零余额明确填 0，差额由系统计算。没有“未变”“未知”按钮、状态选择或批量确认，不按前值自动填入。停用账户通过账户资料中的停用日期处理，不用空金额代替停用。更正加载原记录金额；直接改金额即保存新数值。盘点备注随同一次保存请求提交，最多 10000 字，可空；只更正备注时保留已填写的原条目金额、分类与计入范围，旧“未变”行沿用已记录金额，不从更早盘点重推导。旧版不完整盘点继续可查看，进入更正后需补齐缺失金额再保存，缺失不转换为零。切换日期加载所选日期自己的备注，未保存的备注修改切换前需确认丢弃，取消保留日期、金额与备注。

旧版不完整盘点不画入完整净资产趋势、不冒充完整比较；概览采用最近一次完整盘点并提示较新旧记录是否缺失。综合总览在净资产金额旁固定显示“截至 YYYY-MM-DD 完整盘点 · 距今 N 天”；期间控件旁常显“所选期间用于重要支出与近期记录；持有物品与固定负担为当前资料，净资产取最近完整盘点”。

盘点记录表显示备注摘要，点击日期或摘要按稳定 snapshot ID 打开只读盘点详情（含日期、完整性、记录时账户金额与状态、全文备注与“更正这次盘点”入口）；时间轴与来源跳转同样进入只读详情，原记录已删除时提示而不是打开同日替代记录。两次盘点比较在各端点分别展示日期和各自备注。财富 CSV 在行末增加“盘点备注”列，同一盘点的每个账户行输出相同备注；金额列、行粒度与排序不变。

两次盘点比较要求起点早于终点。负债的欠款增加对净资产是负影响；区间新增账户起点按零处理。账户是否计入、金额完整性等条件无法对齐时，显示原因和已知部分，不能声称合计已对账。净资产变化包含存取、消费与估值变化，不等于投资收益。

综合首页规划摘要与目标页共享 `buildRetireCalc`、`goalHeadline`、`coverageNow` 和月账本。默认复盘展示金融净资产变化（含估值）、已记录到账收入与公积金；没有收入仍保留可比资产事实。收入条数不证明覆盖完整。历史月均变化按区间天数加权，中位数每区间一票；不默认展示反推消费、真实储蓄或储蓄率，也不自动作为未来净投入。缺独立保存的净投入阶段时只提示待确认，旧显式零／非零阶段原值和 ID 保留。

规划以最近完整盘点的收盘日 B 为起点，金额基准 T 单独保存且首次确认后固定。可用、受限、排除规则按稳定账户 ID 与参与比例明确确认；猜测规则只用于缺项展示，不给完整可行结论。债务本金单列，不先扣可用现金；已发生贷款按截至 B 的本金与剩余月数接续。资金规则、付款范围或余债未核对时阻止完整结论。首月净投入与普通预算按 B 后剩余天数折算；计划一次性付款、月供和持有费先检查已有资金，后续月末净投入不能消除月初不足。

净投入对费用的包含关系以阶段 ID、费用来源 ID 和参考额保存。先加回已含参考额（再作空窗折算），再扣实际月供／持有费；月供结束只停还款，维护费继续。未发生计划的费用只能额外计入，不能凭空加回参考额。个人养老金现金转入从可用池扣一次，已有余额通过独立受限账户关联且需确认；领取时只转池，现有养老金税费假设仍适用。公积金工资扣缴／单位缴存只增加受限池，不再次扣税后净投入；未来缴存独立确认，历史零不向前回找非零。其他受限资产暂无通用解锁。

预计月已过的纳入计划显示“日期已过，待核对”，不移到当月。实际发生核对保存实际日期、一次性付款分项及账户、全部付款是否已核对、吸收盘点 ID／修订，以及余债截至日／剩余期。已发生事实不随方案开关撤销；B 前且明确属于同范围盘点的已吸收付款不重扣，B 后付款只扣一次，未知／部分付款保留缺项。可关联既有物品、重要支出或已购入愿望的稳定 ID，核对日期和金额，不新建物品或复制支出。付款关联按事实稳定 ID 去重：物品购入、关联到该物品的已购愿望与已关联支出属于同一事实，不得在发生核对中重复计入。独立购入／独立支出即使日期和金额相同也不合并。旧库及备份保留原始资料；读取时若存在重复关联，返回待核对缺项并阻断完整结论，修正关联后方可继续。 来源更正使读取状态带 `reference_issues` 并阻止完整结论；被引用来源的删除／永久清除需先解除规划关联。保存、请求回执、冲突、重启与备份沿用个人资料事务。完整收入覆盖声明、冻结基准、导入和报告事实适配属于后续目标规格。

两块摘要使用同一次只读事务中的最近完整盘点、收入、个人资料与复盘统计，不把不同批次组合成当前结论。读取错误单独提示，历史资产统计可独立显示。规划关闭或只看物品时不读规划来源；财富关闭而规划开启不读取隐藏财富；明确保存模拟起点可计算独立需求，实盘依赖则提示缺项。布局与交互见[首页设计](OVERVIEW_PLANNING_DESIGN.md)。

## 通用规划基础的当前 core 边界

core分支已实现计算、输入和保存，待独立Review及UI联合原生验收；下方旧阶段界面说明在UI分支整合前保留。实际契约见[数据规格](PLANNING_DATA_SCENARIOS_DESIGN.md#第一批实际共享契约p1)。基础保存无需北京社保事实，未知保留null。实盘与模拟起点显式替换，金额不相加；关闭财富不取隐藏账户。所有分区共用一个Profile/revision/core与事件事实；明确重设在同一事务保留原假设只读定义，不自动转换旧阶段或复制事实。

基础退休预算为完整总额，已含明细/租金先扣参考额再加实际来源，额外费用另加；完整预算不足不能以必需部分已覆盖称成功。退休前净投入单独核对费用作用域。收入按本次不计/手填/北京估算及选定来源计入，北京国家养老金不与同一手填项叠加。未来缴费起止明确独立，不以零/负投入或35岁推定停缴。

预计投入未知时仍可反求固定目标需求；所设收益及两段实际收益各降低／提高200 bps分别求解，超出合法范围的对照不计算。候选不保存、不变成预计投入、不输出FI日期，也没有对应概率保证。明确正/零/负投入才形成预测/风险/心愿数值上下文；临时预览不改变首页和心愿。无缺口且终点0为有限期间覆盖、无余量，不外推终点之后。本批不含完整报告入口、导入写入、职业扩展与完整当前承受能力。

## 规划：收入与复盘

规划是可开关的独立模块，关闭只隐藏入口，不删除资料。它不记逐笔流水，不分类收入来源，也不要求记录支出。

目标、收入与复盘、养老金各自进入自己的任务，不自动弹出统一表单。目标的四步设置为「想过怎样的生活」「用哪些钱来准备」「看看每月要存多少」「确认计划」；界面把净投入称为「每月能存的钱」，默认收起且选填，计算出的所需金额明确为结果、不让用户填写或自动保存。每月存0元只是可修改的本次假设。已有费用核对独立可见，缺项动作直接进入相应步骤；最后一次确认原子保存，关闭或跳过不写草稿。养老金可以只保存已知事实，收入记录不要求目标已设置。基础模型不要求职业、储蓄阶段或复工日期。原规划继续兼容，明确重设才替换原假设；账户、盘点、真实收入、已发生付款和余债不重写。

**当前资金承受能力**是目标页的可展开临时工具，无目标也可手填可动用资金与截至日；已确认的基础资金可复用，也能明确切换手填模拟。当前可靠到账留空为未知，明确没有才取零；必要开销需包含当前房租、月供、社保等合计，不自动追加退休事件或费用。底线选填，默认检查60个月，可选12／24／120个月。复用月账本步进，按起点后完整月、月初支付和月底到账检查；底线以付款后最低余额判断，月底到账不抵消触底。付不起下个整月会给出剩余资金，不称余额已经耗尽，不捏造其后触底时间。旧起点显示截至日及未覆盖变化；固定当前收支，不计投资收益、通胀、未来大额事件及月供结束。输入不持久化，不接回预计投入，不产生退休达成时间，不改首页与心愿。完整事件／贷款接续及输入保存不属于此临时工具。

- **月度收入**：每月一行，记录到账日期、税后到账与公积金缴存（整数分，必填，0 是明确事实，日期不晚于今天）；同一天可有多行，备注最多 500 字。编辑使用修订号，删除进入最近删除并可恢复，永久删除后无法恢复。公积金提取是账户间转移，不需要记录。
- **区间**：只取相邻两次完整盘点，复用盘点比较的可比判定，不假设每月盘点。不完整盘点不能结束区间；范围变化时保留缺项。没有收入记录仍显示可比净资产变化，已记录收入按起点之后、终点当天及以前归入区间，记录数不证明覆盖完整。
- **口径**：默认展示金融净资产变化 ΔNW（含估值变化）、已记录税后到账 I、公积金缴存 H 与公积金账户变化 ΔF；不把 ΔNW 命名真实储蓄，不由 I−ΔNW 反推消费或储蓄率。旧 saving/spend/rate 字段仅保留在兼容投影，不能用作新界面或未来净投入。完整归因和收入覆盖声明尚未实现。
- **历史资产参考**：取终点晚于最新完整盘点往前12个月的可比区间，排除一次性变动；月均净资产变化按天数加权，中位数每区间一票，均标含估值变化。没有收入不剔除资产事实。一次性变动标记只影响历史参考，不改盘点事实；永久删除盘点时一并清除。
- **复盘**：现状显示资产变化、已记录收入和公积金；变化显示本期金融净资产变化与一次性标记；原因显示盘点备注及区间来源记录。来源记录只用于解释，不调整资产数字，不据此声称归因或收入完整。

### 养老金估算

个人资料（出生年月（界面用日历选日期，只取年月）、性别与职工类型、累计缴费月数、个人账户余额、当前月缴费基数、可选的历史平均缴费指数与弹性领取月数、个人养老金年缴额与边际税率、三项假设）只存本机；估算结果每次重算，不存库。**估算不是事实**：内部用浮点数计算，金额在显示时取整到分并标注，不得写回或冒充已记录事实。个人资料不会自动更新：保存时间超过 6 个月时养老金页提醒核对累计缴费月数与个人账户余额。缺必需项显示「需要补填」，不当零；假设项标「这是假设」，出厂预填值只是占位。

- **法定退休年龄**：按国务院《渐进式延迟法定退休年龄的办法》：男职工自 1965-01、女干部自 1970-01 出生起每 4 个月延 1 个月，分别至 63、58 岁；女工人自 1975-01 起每 2 个月延 1 个月至 55 岁；延迟月数 = min(上限, ⌊出生月与起算月之差 ÷ 步长⌋ + 1)，早于起算月的不延迟。可弹性提前或延后最多 36 个月，提前不得早于原法定退休年龄。按月领取的最低缴费年限从 2030 年起每年加 6 个月，到 20 年（2030 年取 15.5 年，为解释性取值），不足时提示，养老金页的数字仍按公式计算；退休规划的账本在不足时不计月养老金，个人账户余额按一次性领回计入，并在收入卡提示还差多少个月。
- **基础养老金** = (退休时上年度社平工资 + 社平 × 平均缴费指数) ÷ 2 × 累计缴费年限（按月）× 1%；指数限定在 0.6 至 3，社平按工资增长假设外推。**个人账户养老金** = 领取时个人账户余额 ÷ 计发月数；余额 = 现有余额按记账利率增值，加缴费期每月基数的 8%。计发月数按国发〔2005〕38 号附表，非整岁按月线性插值，并标明是官方修订表出台前的近似。
- **随停缴年龄重算**：辞职后缴费停止，缴费年限、个人账户与公积金余额都变少，因此对每个候选停缴年龄各算一次；停缴不改变法定领取年龄。
- **个人养老金与公积金**：沿用既有年缴额上限、领取税费和利率假设。已有个人养老金余额通过独立、100%参与的受限账户关联；明确无余额也需核对，未来现金转入扣可用池一次、增加个人养老金池一次。公积金起点仅采用已确认受限账户，未来缴存单独确认且不再扣税后净投入，按通胀增长维持所填实际缴存金额；不回找历史非零。两池只在领取时转回可用资金，缺规则时标部分估算；其他受限资产不自动解锁。首期缴存和收益使用盘点后剩余天数。
- **口径**：养老金按名义计算，另按通胀假设折成今天的钱；替代率 = 养老金（今天的钱）÷ 停缴时月缴费基数（今天的钱）。
- **参数表**：先只提供北京。每项参数带可点击来源、生效日期与核对日期，区分官方原文、据官方值推算和测算假设（兼容媒体转述／未核对），用户可在个人资料里覆盖，覆盖值优先。北京 2026 年缴费基数上下限与公积金 1.5% 已核对官方依据；12116 元社平参考值由上限除以 3 推算，不等同于已核对的养老金计发基数；个人账户未来记账利率 1.5% 仅为长期假设，没有对应年度官方值的确认。覆盖值显示“用户自定值”，官方来源只说明内置参考值，不背书覆盖值。参数依据统一维护在 `src/plan-params.ts`。不处理 1996 年前视同缴费的过渡性养老金。

### 退休与 FIRE 估算

通用基础已接入：新计划没有职业／储蓄阶段或路线，FIRE搜索沿用所选规划终点，不保留原模式70岁上限；目标、完整退休预算、资金起点、退休收入选择与收益假设支持固定目标反求，预计每月投入为有符号整数分或 null。null 不编译预测、不输出达成时间，求解候选不回写；0 与负值为明确假设。两段收益各降低／提高200 bps为对照条件，不是分位或现实概率。实际／模拟资金互斥；北京缴费节点与投入符号、FIRE触发分离，受限池按确认节点到账一次。

费用的积累／退休作用域分别用于对应区间，保留已含参考额；月初付款先于月末收入。完整预算可支付且终点非负为覆盖，终点0须说明没有余量。目标、收入记录、养老金任务没有全局资料门控。引导最终以setup分区一次提交全部所选字段，分区共享revision／回执，不覆盖账户、盘点、付款或余债；结果未知禁止覆盖原请求。明确旧模式转换同事务保留原假设，只读原定义不复制事实。仅养老金资料不视为原退休计划，不要求虚构目标；保存规划或实际收入均视为已开始个人资料，重启不因没有物品自动跳回样例。

以下阶段、路线、旧日常生活预算及职业预设说明限原规划兼容路径；通用基础的总预算、选填投入与收入选择以本段及[数据规格 §4.4](PLANNING_DATA_SCENARIOS_DESIGN.md#44-积累条件压力条件与时间线适配)为准。

全部按保存的金额基准 T 的实际购买力逐月推演，资金起点 B 为完整盘点收盘日。名义显示和固定名义付款使用同一 B/T 换算系数，首期按剩余天数推进。采用未来缺口反求，结果重算不存库；缺输入不给完整结论。界面现值／名义值切换只改变显示。借鉴 Wealthfolio 的页面结构与算法思路（来源及许可另行核对，功能相似不作为代码来源结论）。

- **计划类型**（用户选择，存在个人资料里）：**FIRE** 找资产第一次够用的月份（FI 年龄，可晚于期望年龄），年龄不到期望年龄时不开始退休；**传统**到期望年龄就开始退休，资金不够也照常开始，页面给出缺口或盈余。两种类型共用同一套计算，只有「何时开始退休」不同；切换类型不删除任何输入。成功的定义：完整预算全程可支付、终点非负（为零时没有余量），FIRE 另需达成 FI。
- **输入**：当前规划可用资金取最近完整盘点中明确可动用账户及参与比例，受限与负债单列；负债本金不作为初始现金扣款。未来净投入须保存显式阶段（最多30段，明确零和负值保留），不默认取历史涨幅。阶段内保持 T 实际金额，工资增长只用于养老金。已含费用先恢复参考额再作空窗折算，实际月供／持有费只扣一次；未发生费用不能标已含。负现金保留并记录首次不足，后续投入不抹去付款失败。离职后的房租、社保续缴、空窗停缴、预算、收益及终点年龄仍为独立假设；应急金是余额底线，不是额外支出。
- **支出**：「日常生活」是用户明确填写的月预算，必需，从退休当月到规划终点；留空不估算退休时间；历史资产变化不能反推预算，一次性医疗或大额购买不推断为每月重复发生。可再添加支出项（医疗、住房、旅行、其他）：每项有每月金额（今天的钱）、起止年龄（留空表示从退休／到终点）、必需或灵活、可选的独立通胀（医疗等可比总体通胀涨得快）。最多 20 项。
- **收入**：国家养老金不手填，由养老金页的个人资料按辞职年龄重算，随通胀；另可添加税后月收入项（企业年金、租金、返聘等）：金额、起止年龄、是否随通胀（否则是固定名义金额，实际购买力逐年下降）。不做提取税、账户占比与提前提取罚金：个人储蓄提取无税，个人养老金领取 3% 已内置。
- **所需资产** F(a)：在 a 月龄开始动用资产，需要覆盖此后每月「支出 − 收入 − 养老金（领取年龄起）」直到规划终点，且**此后任何一个月资产都不能为负**；公积金与个人养老金在领取年龄一次性解锁（税后）计入，按退休后实际收益率折现，下限为 0。养老金与解锁额对每个辞职年龄各算一次，辞职越早越少。所需资金下滑曲线：目标年龄之前折算剩余储蓄（仍能在目标年龄达标），之后是此刻退休所需。
- **达成年限与逐年快照**：从当前可支配资产出发逐月推演（退休前加储蓄并按退休前收益率增长；退休后按收益率增长并取出「支出 − 收入」，不够的部分计为无资金支持，必需支出没钱付即「支出缺口」），第一个资产 ≥ 所需资产的月份是 FI 月份；FI 搜索到 70 岁，达不到显示「不可达」，不给假日期。页面按年汇总：年龄、年份、阶段、期末组合、供款、退休收入、一次性解锁、计划支出、提取。
- **概览**：判词与徽章（FIRE：已实现／进展顺利／晚 N 年／无法达到；传统：进展顺利／盈余／缺口／资金不足）、总结句、当前组合与目标年龄所需的进度条、投资组合轨迹图（实线为预计，积累与退休分色，虚线为所需，标出目标、FI、退休）、Coast／Lean（支出 70%）／FI／Fat（支出 150%）四个里程碑（都是目标年龄时所需，Coast 为现在至少要有多少、之后不再存也能达标）、覆盖情况（某年龄每月支出由收入、养老金、组合提取与无资金部分支撑，支出与收入计划表，随时间变化的堆叠图）与逐年快照表。
- **35 岁以后的路线**：保留旧路线选择、参数和显式阶段原值；路线均为未核对示例假设，不是收入事实。未保存显式净投入阶段时不恢复历史中位数。路线与费用包含关系暂未联合核对：同时存在费用来源时阻止完整结论，需改用明确阶段；不静默加回费用或补建事实。路线影响养老金缴费基数的既有机制保留。
- **大额计划（买房、买车、其他）**：未来设想拆成首付／杂费与月供／持有费，共用退休账本；实际价格按 T，未来贷款本金换算至购买月名义值一次，名义月供逐月折算。价格报价模式尚未实现。已发生记录按实际付款、吸收盘点与截至 B 的余债接续，不重新开原贷款期限；月供结束维护费继续。纳入开关只控制未来设想，已发生事实固定保留在 plan0 比较基线，不能通过删计划撤销。只计算未来单件影响；存在已发生安排时不显示“全部不发生”的合计比较。买房后的实际省租不再额外增加明确净投入，退休后房租取消仍按预算处理。公积金贷款／提前提取、通用引用选择器、贷款下一到期日均未单独建模；已知月供与持有费在每期开始先付，不靠月底投入。
- **结果区间与 Coast 检查点**：概览把基准与上行情形（「五年后起收入翻倍」「三年后起跳槽涨薪 30%」）和下行情形（「三年后起储蓄减半」「一年后失业一年（每月动用日常生活预算）」「缴款减少 25%」）并排给出 FI 年龄（传统类型给目标年龄时的盈亏），收入是最大的不确定因素，涨薪与降薪都说不准，所以主结论保持保守（不预设涨薪），把涨薪上行与降薪下行并排给出区间，这不是预测；并按储蓄阶段里每一次下降的起点（没有下降时给 35 岁参考）给出「到那时至少要有多少，之后不再存钱也能按期退休」与按计划那时预计有多少。
- **反推**：不预测收入，反过来问目标需要什么：在期望年龄达标，从现在到那时每月至少存多少（恒定金额，二分求最小、精确到分，对照你有收入时的储蓄），储蓄阶段里有下降时再给「只在下降前集中存、之后沿用你设的更低储蓄」前期每月至少存多少；已经够了显示不用再存，每月存到 100 万也不够显示不可达。达标的判定与结论相同：目标年龄时资产不低于所需、没有支出缺口、没有资金耗尽。
- **假设分析**：基准情形；十项压力测试（其中两项是上行情形，不参与「影响最大」的排序），每项只改一件事（收益率 −2 个百分点；通胀 +1.5 个百分点，名义收益与名义工资增长不变，因此实际收益与实际储蓄增长相应下降；支出 +10%；提前 2 年退休；缴款 −25%；三年后起储蓄减半；一年后失业一年；三年后起有收入阶段储蓄 +30%；五年后起翻倍；退休第一年市场 −30%），按严重程度排序；市场路径模拟（固定种子，同一计划每次结果一致；实际收益取对数正态、中位数等于假设值、每年抽一次，不模拟通胀的随机波动；可运行 1 万或 10 万条，给资金充足占比、中位数 FI 年龄与第 10／50／90 百分位的终点余额，扇形图为第 10–90 与第 25–75 百分位区间和中位数）；两张矩阵（通常 5×5，年龄边界裁剪去重）（缴款 × 收益率、期望年龄 × 支出）；收益顺序检查（基准与同一段年率 −30% 的下跌分别发生在退休开头／末段，持续时间相同且最多一年，首月与末尾不足一年按实际经过时间计算）。这些是模型结果，不是现实概率，也不是承诺。
- **心愿作为一次性支出**：读取「考虑中」的心愿，**不为此增加心愿字段、不改变心愿状态**，也不替代「已买到，记录购入」确认。这只是「如果按计划买下」的估算：**不扣用户真实的资产**（真实资产只在买下并盘点之后才变），也不预测买不买、在哪买或涨价后是否放弃。填了计划日期的心愿表示「打算买」，在计划日期所在月从推演的可支配资产里扣减，并计入合计；**没填计划日期的只作单件「如果今天买下」的假设，不进合计**；计划日期已早于今天的**不计入**，页面列出「已过，未计入」，不自行猜日期；没有预计价格的无法估算，只列出。每件心愿的影响以「其他考虑中心愿都不发生」为基线，只加入这一件，比较 FIRE 日期：推迟约 N 个月、几乎无影响，或 70 岁前达不到；同时给出计划日期时可支配资产（按当前储蓄）和是否低于应急金线。有计划日期的多件同时买下的总推迟另行给出。还没决定的心愿不应填计划日期，预计价格建议填偏保守的。购入后盘点余额已反映该支出，心愿退出考虑中，自然不再计入。
- **目标页**：规划首页按目标显示卡片，目前只有「退休」。卡片的进展 = 当前可支配资产 ÷ 今天就退休所需资产（限 0–100%）；FIRE 类型的「还要多久」取 FI 日期，传统类型显示期望年龄时的盈余或缺口；不为目标划拨资产、不保存已储蓄金额，进展每次由盘点与收入重算，缺输入时只提示缺什么。
- 不预测裁员、跳槽或涨薪；只使用明确保存的净投入与独立风险假设，估算不是承诺。

## 支出、周期费用与虚拟资产

| 模块 | 去重与时间规则 |
|---|---|
| 重要支出 | 汇入物品购入、维护、已确认周期付款、未关联计划的虚拟资产价格和储值充值实付；独立支出关联物品后不再重复计算 |
| 退款与售出 | 退款按退款日期入账，原支出期间仍按原额；售出回收单列，不直接冲减重要支出 |
| 日期未知 | 单列待补充金额，不归入某个月；时间轴只展示事件，不再次累加金额 |
| 周期计划 | 每期填一次付款总额，服务开始与下一期付款日分开；界面默认用简易表单（任何分类）：开始日期、周期、每期金额、提前几天付款、到期日（不含当天，存为前一天的「最后使用日期」），不新增字段，结果与完整表单同一排期，需要固定天数、试用、分段价格时可改用完整表单；默认持续进行，结束日可空；历史开始不自动产生历史待确认，实际付款须明确确认 |
| 计划更正 | 修改计划不改写已记录付款；暂停不提示，恢复从当天计算、不补暂停期间的到期；月底按各月最后一天处理 |
| 关联虚拟资产 | 新订阅一次保存权益与付款计划，默认每月、持续续费；无指定结束日不因缺少付款判定到期，旧订阅也采用此状态解释；有限期按指定结束日提示，已付覆盖期另列；不存账号、密码或激活码 |

新计划按服务覆盖期限制固定期限：提前付款不生成期限外一期，最后一期可截断至结束日。付款日与服务期分别按原始月日锚点顺延，月底取当月最后一天，不逐月漂移。

订阅的单期服务默认一个自然月，下个周期开始前一天为本期最后服务日；这不是整项订阅的终止日期。未指定结束日的订阅在总览与侧栏不反复提示每期付款待确认，仍可在周期费用页主动记录实际付款。其他周期费用保留付款提示；订阅是否有限期均保持周期待办静默；未指定有效期的旧独立订阅显示持续使用，但其价格仍保持单次投入，不推断成月费。

历史订阅须明确服务结束日期，过去的下一付款日不推断为终止日；已结束不计入使用中，也不安排结束后的续费。已结束订阅不进入主页「待关注」，包含旧独立订阅和关联周期计划的订阅；档案、估算和付款事实保留，即将到期且尚未结束的权益仍正常提示，其他类型权益的到期提示保持原义。虚拟列表的累计费用显式标为估算，已记录支出只汇总单次投入与已确认付款；未补记显示为未记录付款。

累计估算按服务开始至今或已指定的结束日（取较早者）、按整期与价格记录计算；初次录入前的历史使用当前价格估算，保存后的调价从更正日起分段。期限预计包含完整期的总额，末期截断覆盖时间但不自动按天减价。估算、年化、月均与预计均不计入重要支出、账户余额或金融净资产。范围补记须用户明确确认确实已付，按填写的每期实付生成付款事实，既有记录保持原样；实付日期默认对应付款日，允许之后单独更正。

旧计划的付款日排期、旧独立虚拟资产的单次价格及已确认事实保持原义；未指定结束日的旧订阅只调整读取状态与提示，不写入续费或付款事实。

### 虚拟标签、计费方式与储值

| 概念 | 口径 |
|---|---|
| 虚拟标签 | 复用现有标签（稳定 ID）与管理；每条虚拟档案至多一个可空标签。标签有适用范围：实物、虚拟、通用；实物标签的既有引用与“标签投入分析”原义不变，通用标签不把订阅费用计入实物分析 |
| 计费方式 | 单次购买、订阅、储值，独立于旧业务类型字段；旧 `license/domain/subscription` 保留为业务类型，无计划的新档案采用中性类型。有计划的旧档案按订阅解释，无计划（含旧独立订阅）按单次投入解释，不推断月费 |
| 已有事实 | 已有付款或充值事实的档案不能更换计费方式；单次购买可明确标记“永久有效”，否则空有效期显示“未设置有效期”，两者用字段区分，不改写旧空值 |

单次购买的使用结束与权益到期分开：可明确选择“已结束使用”并填实际结束日期（允许过去，不早于购买日期、不晚于今天），复用既有 `stopped_on` 与保存回执，不新增计费方式或期限字段。结束后退出使用中，显示使用结束日期，原实付金额与购买日期仍参加历史支出；可撤回结束使用。购买日期过去不会自动结束，不把服务完成伪装成永久权益到期。一次性医疗等没有后续权益的消费可直接记重要支出，已经在虚拟档案记录的同一笔不再重复录入。贷款本金是偿债，由账户盘点同步减少资产与欠款；只将利息作为支出，不将整笔还款记成虚拟资产消费。

订阅默认新建为自然月、自动续费、无最终结束日、无试用、无提醒。自动续费与最后使用日期是两个独立设置：开启续费仍可指定最终使用日；关闭续费必须确认最后使用日，`today > 最后使用日` 才算结束，不加手动“已结束”状态。旧 `paused` 仍是暂停排期，与自动续费关闭是不同字段。周期支持自然月／季／半年／年（覆盖末日按原始锚点网格推算，1 月 31 日锚点的 2 月期为 2/28–3/30，不因短月漂移）与固定 1–3650 天（按自然日计数，年化按 365 天一次舍入折算）。周期长度、试用与覆盖锚点的修改按生效日期分段保存：历史期估算与补记沿用所属时段规则，新规则只影响之后的期；已确认付款、skipped、覆盖与价格历史不改写。免费试用从开始日计入第一天，计费起点默认为试用结束的次日且不得早于该日；试用期不计入付费期数、估算、固定负担或重要支出，也不是付款候选——试用内不能单期确认或范围补记出实付；试用内结束的服务保存为零费用已结束记录，不安排首笔付款。本期特殊到期按原始期始日保存，只影响未确认的目标期及后续推算；与下期相连时后续锚点顺延。后续续费价格保存为价格分段，取消只撤尚未生效的未来价格，已生效段保留；各期待付款金额、月／年折算与未来 12 个月预测都按所属服务期的生效价格计算，不把当前价格乘以期数，用户手填的补记实付保持独立。

储值档案按充值投入：每次充值独立稳定 ID，充值日、可空实付、赠送（默认无）、可修正的到账额度；实付是唯一支出来源并按充值日期计入重要支出，赠送与额度不进支出或金融净资产。实付未知不倒推；只有赠送且明确未支付时实付填零，与未知区分；未知充值日列入待补充。余额是带日期的手动盘点值，不用累计到账倒推，充值与到期不自动扣减或退款。档案删除带入最近删除，恢复原 ID 后同一事实继续生效。

备款提醒默认关闭；关联新版订阅可选择“每期提醒”（扣款前 0–30 天，默认 3 天）或“仅本次”的指定日期提醒，复用既有通知通道。每期提醒按当前及之后未记录的付款期推导，确认 paid 或 skipped 后撤销该期通知并转到下一期，付款事实与服务终止状态分开。备款／充值付款账户不等于订阅已扣款，不能直接记为订阅支出。每期提醒预安排未来 12 个月内的付款期，打开应用或修改资料时补充；自动续费关闭、排期暂停或没有可续费期时暂停。关闭、停用、到期、删除、模块关闭或切换资料库会撤销待通知，历史过期不补发。旧提醒迁移后仍是“仅本次”，不自动启用或改成每期。

虚拟订阅列表和详情可确认本期／下期真实付款，候选只取当前及之后未记录的服务期，不把历史漏记重新当成本期待办；付款后服务状态仍按实际终止日期判断。自动建议的最后使用日随开始日、周期和试用即时更新，手填或已保存的结束日保留；重新开启续费只清除本次表单未手改的自动建议。有限期订阅保留到期状态与日期，但不进入周期性待办。虚拟页筛选提供全部／标签（含未设置）／计费方式／状态，表头排序覆盖名称、开始、结束、状态与费用，未知置后；费用列按未年化原始金额排序。

总览分别展示金融净资产、持有物购入金额、重要支出和固定负担，不加成一个“总资产”。

购买趋势的柱状图与累计折线图支持悬浮查看准确起止日期、整数分金额、件数和未知金额提示，点击固定详情；左右方向键切换期间，Home／End 到首尾，Escape 关闭。切换粒度清除旧选中期间，表格保留精确明细。

## 表单、搜索与引用

- 普通表单关闭即丢弃未保存输入，不保存草稿，不新增退出确认；已经提交但结果未知的请求保留回执并核对，防止重复事实。
- 物品列表默认按购入日期降序，置顶优先；名称、日期、金额、日均、状态通过表头双向排序；「更多排序」仅补充没有对应列的添加时间和持有时长。持有时长从购入日算至今天或售出日，含退役后的持有期间，未知日期置后；状态按使用中、已退役、已售出分组，置顶组内未知值置后。排序在完整筛选结果中执行后再分页，同值按稳定 ID 排列，不改写物品记录。
- 心愿与财富记录列表共用表头排序操作，日期按早晚、金额用整数分比较，未知值不当作零。心愿列表为“心愿｜预计价格｜加入日期｜计划日期”，页头合计只统计考虑中的心愿（未知另列，历史待核实单列），历史待核实在“全部”和“考虑中”筛选中可见并带标记，不计入已购入数量或考虑中合计。
持续／永久权益按结束日期排序时置后，不拿已付覆盖期替代终止日；不完整盘点不提供已知净资产排序值。各列表的默认顺序见 USER_GUIDE，排序不改变金融汇总、付款事实或类型。
- 搜索为去首尾空白、英文不区分大小写的字面子串匹配；先筛选／搜索后分页，只作用于本页列表，关键词不改变金融汇总。
- 「搜索全部资料」（⌘⇧F 或菜单「编辑 › 搜索全部资料」）独立于本页搜索：⌘F 仍聚焦本页搜索、⌘N 仍是本页新增。全局搜索只查当前资料库已开启模块的未删除记录，覆盖物品、心愿（含历史待核实）、账户、盘点、独立重要支出、周期计划、已付／已跳过的付款记录、虚拟资产与储值充值的首批字段；物品购入等聚合支出投影、时间轴与统计不作为第二条结果，附件内容、OCR、序列号、保障／维护与退款子记录、余额核对历史、未确认付款候选和金额文本都不搜索。单个整关键词、无分词拼音模糊或通配符（% 与 _ 保持字面）；名称／盘点日期命中的结果排在其他字段之前，组内按添加时间降序、固定类型顺序与稳定 ID 排列，先搜索排序后按 30 条分页，总数与各类型计数来自同一读取快照。关键词最多 200 个 Unicode 字符且不能含空字符；超长输入保留原文并提示，不静默截断。固定账户类型、支出分类、计划类别和虚拟资产类型按界面的中文名称匹配。关闭模块的记录与计数不返回，也不为打开结果自动启用模块；点击结果先按稳定 ID 校验来源，删除或失效时提示并从第一页刷新，不打开同名记录；重试会重新发起查询，同一资料库内写入后再次查询也从第一页开始；关闭面板后迟到的来源校验不再跳转；编辑或回执核对未结束时沿用现有阻塞流程。最近删除仍走既有入口；正式库与样例库绝不混合，无任何网络请求。
- 分类、渠道、标签按稳定 ID 引用；改名保持关系，删除有引用选项前处理引用，不产生悬空关系。
- 来源跳转校验对象 ID 和资料库身份；删除后刷新并说明原因，不打开同名对象，不让旧响应覆盖新资料。
- 样例库与自己的资料独立；样例的修改与删除不影响真实资料。备份、恢复与导出在自己的资料中执行；开发测试始终使用虚构资料。

## 删除、备份与恢复

删除先进入最近删除，可恢复原 ID 及这次删除带走的关系与图片；最近删除不自动清空。永久删除不可撤回，需明确确认；子记录恢复遵守父对象关系，不制造重复事实。

完整 `.thingary` 备份包含资料、关系和图片，恢复是整体替换，不是合并。CSV 不能代替恢复备份；物品 CSV 导入只新增，先预览、默认跳过疑似重复，整批成功才写入。

### 规划风险工具

市场模拟通过随机收益回调复用生产月账本，付款先后、首月比例、解锁与完整预算成功判据保持一致。随机收益分布以所设实际收益为中位值，以年度波动为标准差，不给现实概率承诺。压力等级按预算覆盖、目标可达及缺口发生时间的变化区分；状态未恶化但金额、时间或余额变差时为中。矩阵保留基准金额，使用等步长比较；生活预算轴不改变固定事件付款，年龄轴以目标为中心每两年一档并按规划边界去重。收益顺序检查保持下跌持续时间及累计收益相同，比较发生时点；首月和末尾不足一年按实际经过时间计算，并显示准确终点。

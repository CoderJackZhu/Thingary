# 物志 Possio：P0 功能规格

版本：v0.2 业务基线 · 日期：2026-09-24 · 状态：关键业务边界已确认并补齐，技术设计提案已形成；尚未实现或执行应用测试。

## 1. 目标、来源与边界

为个人长期记录实物资产提供中文 Mac 本地应用。成功意味着：可以离线录入、更正、处置与回顾物品；退出重开资料仍在；误删可以恢复；完整备份能够恢复全部档案及图片。

- 产品范围和业务含义由 [产品设计](PRODUCT_DESIGN.md) 维护，本规格将其转成输入、可观察结果、失败处理和验收例；不复制另一套产品定义。
- D01–D12 为用户已确认规则；F01–F08 为产品设计第 16 节流程编号。
- 用户在比较两套原型后回复“a”，已选 **A「静序」**。视觉基线见 [UI 设计](UI_DESIGN.md)，交互参照 [原型](ui/prototype.html)。选择风格不等于所有原型简化行为都获批准。
- S01–S05 的关键取舍已依据用户回复收敛；第 7 节区分用户明确确认与详细设计补充，不能将默认细节描述为用户逐项批准。
- 完整 P0 范围仍以产品设计第 14 节为准。首批可用流程只是其中一部分，不能因原型只展示三页而删除其他要求。

本规格定义可验收行为，不选依赖版本，不建立工程脚手架、不新增应用代码或运行后台 Agent。

## 2. 通用交互约定

### 2.1 表单与操作状态

| 状态 | 用户看到的内容 | 允许的动作与结果 |
|---|---|---|
| 编辑中 | 当前输入及字段提示 | 更改输入；无改动直接关闭，有改动关闭时选择继续编辑或放弃 |
| 输入不合法 | 对应字段说明原因 | 定位首个错误，保留其他输入，不写入业务记录 |
| 保存中 | 明确正在保存 | 不接受同一动作重复提交；不先显示业务成功 |
| 成功 | 已保存对象和结果 | 所有关联页面更新；下一次读到的是已提交资料 |
| 保存失败 | 可理解的原因和重试入口 | 保留输入、图片选择；旧资料与统计保持可用 |
| 对象已删除 | 已移入最近删除 | 前往最近删除；不能当成新对象再次创建 |
| 对象不存在 | 找不到这条记录 | 返回来源页；不显示空白编辑表单诱导覆盖 |
| 加载失败 | 加载失败及重试 | 不冒充首次使用空列表 |

提交结果未知（例如写入后连接中断）必须先核对该次操作是否已提交，再决定重试；不能仅依赖按钮禁用防止重复。取消不生成购买、维护、售出或心愿业务事件。正式版不提供原型的“模拟失败”开关。

### 2.2 数据表达

- 金额统一人民币；已知零、未知、有效正数分别表达。实际输入非负，派生净成本允许为负。显示两位日均小数，排序依据未舍入的数值。
- 业务日期是自然日，不能按经过多少个 24 小时估算；创建/修改时间独立于购买日期。固定观察日只用于验收样例，正式应用随当前自然日更新。
- 总投入中任一已记录费用未知时，不得显示完整精确的总成本或日均；可以展示已知部分，并标明未知笔数。
- 没有任何维护记录时，维护费用合计为零；存在一条未知费用的维护记录时，合计完整性为未知。两者不同。
- 事件是业务事实的展示，汇总不二次累加事件金额。修改源记录会更新对应有效事件；不能靠另加一条事件掩盖错误。
- 原型与规格里的品牌、型号和金额均为虚构持有样例，不导入真实用户资料。

### 2.3 键盘、导航与外观

采用 A 的侧栏、列表/网格、摘要和完整档案结构。可交互控件有可访问名称、可见焦点和明确状态文字。表单 Tab 顺序按视觉阅读顺序；关闭后焦点返回触发入口；焦点不能落入弹窗背后的列表。

⌘N 新增、⌘F 当前页搜索、⌘E 编辑选中资产、⌘, 设置；全局命令面板为 P1。上述须在打包 App 中验收，网页原型中能按键不代表原生快捷键已验证。提供浅色、深色、跟随系统；保存选择并在重启后保持。

从详情返回保留搜索词、筛选、排序、视图、选中对象和滚动位置；对象不再匹配时给出说明与清除条件入口。不存在的滚动锚点回到最近仍存在的相邻项，不自动清空用户所有筛选。

## 3. 输入契约

完整字段含义见产品设计第 4–7、10 节。以下限定提交行为；标 S 的取舍见第 7 节。

| 对象 | 最小有效输入 | 空值、日期与关系处理 |
|---|---|---|
| 资产 | 去除首尾空白后非空的名称 | 价格/日期/分类/封面可空；未知日期不默认今天；购买日期不晚于今天；同名允许，保持不同 ID |
| 维护 | 关联资产、标题、类型；日期策略见 S02 | 金额可未知或零；类型未选建议为“其他”；已知日期不得与持有区间矛盾 |
| 保障 | 关联资产、保障类型 | 提供方与日期可空；两日期已知时结束不早于开始；未知不伪装为有效保障（S03） |
| 心愿 | 非空名称 | 预计价、目标日期、分类等可空；目标日期可以在未来；实际购入不沿用预计价冒充实付 |
| 退役/重新启用 | 可执行的源状态、操作日期 | 不晚于今天；不早于已知购买或前一有效生命周期动作；更正历史策略见 S01 |
| 售出 | 可售出的资产、实际售价、售出日期 | 售价必填且非负；日期不晚于今天，不早于已知购入及前置动作；未知购入价不阻止售出 |
| 图片 | 用户明确选择且应用可读取的文件 | 必须成功托管，或由用户明确移除后继续；不静默跳过；格式/大小边界由技术验证补齐 |
| 分类/渠道 | 非空名称 | 改名保持引用 ID；被引用分类删除前迁移或改为未分类；不得产生悬空引用 |

金额小数位、文本长度、文件上限、同名分类/渠道如何规范化由技术设计给出统一可验证限制；应用前后端使用同一约束。原型中的 80 字名称上限、金额正则等不是已冻结产品规则。

## 4. 核心流程验收

以下每条 AC 为未来实现的验收定义，不是当前已通过的测试。计算基准直接引用产品设计第 15.3 节，避免维护两份公式。

### F01 · 新增资产

入口：首次使用引导、资产页新增、⌘N。首次打开不要求账号、分类初始化或网络。

| 编号 | 前提与动作 | 可观察的预期结果 |
|---|---|---|
| AC01 | 仅输入名称，金额/日期留空并保存 | 一个 Active 资产；详情显示未知值；无虚构购买日期；有独立建档信息；退出重开仍在 |
| AC02 | 名称只有空白，或购入日期为未来 | 就地提示并阻止保存，保留输入；未来购买引导使用心愿 |
| AC03 | 选择封面并保存，随后移动用户原图片 | 应用内仍能显示托管图片；图片写入失败时不显示已完整保存 |
| AC04 | 双击保存；或提交成功但回执丢失后重试 | 一次业务操作只建一件资产，重试返回相同结果；无多份有效事件 |
| AC05 | 有输入时关闭，分别选择继续编辑/放弃 | 前者保留输入与选图，后者不留半条资产和业务事件 |

成功后进入该资产详情，并提供返回列表入口。**原型差异**：当前 HTML 新增回到列表及摘要；正式行为遵循本条和产品设计 F01，后续统一原型。

### F02 · 查找、详情与更正

入口：资产列表/网格、总览与时间轴的关联对象。默认按资产名称、品牌、型号、分类、备注、序列号搜索；与状态、分类、保障筛选取交集，排除软删除项。未分类是可见的默认归属，不强迫创建分类。

| 编号 | 前提与动作 | 可观察的预期结果 |
|---|---|---|
| AC06 | 单击物品，进入完整详情，再返回 | 同一对象；搜索、筛选、排序、选中与滚动上下文保持；列表/网格切换不丢失条件 |
| AC07 | 补填未知价格/日期后保存 | 同一资产 ID；原建档时间保持；成本、购买事件与汇总更新一次 |
| AC08 | 更正后对象不匹配原筛选 | 当前详情仍能看见成功结果；返回列表说明不再匹配，允许清除条件 |
| AC09 | 无结果、已删除链接、不存在链接、读取失败 | 四种状态有各自文案和入口；读取失败不显示“从第一件开始” |
| AC10 | 编辑购入日期使其晚于已有维护、退役或售出日期 | 阻止矛盾更正并列出冲突记录；不自动移动后续事件（S01/S02） |

列表至少支持产品设计列与对应排序；未知价格/日期排在已知值之后（升降序均如此，S04），并列采用稳定次序，切换视图不随机跳动。

### F03 · 维护与保障

维护、保障为不同操作；保障不会自动退役或启用物品。详情、时间轴、汇总读取相同有效业务事实。

| 编号 | 前提与动作 | 可观察的预期结果 |
|---|---|---|
| AC11 | 购入 ¥1,000，新增维护 ¥200，再改为 ¥150 | 总投入依次 ¥1,200、¥1,150；只存在同一有效维护记录及对应事件，升级不重复加钱 |
| AC12 | 一条维护金额留空，随后补为 0 | 留空时成本不完整；补零后恢复可计算，不将未知当免费 |
| AC13 | 删除误记维护，取消一次、确认一次，再从最近删除恢复 | 取消不变；确认软删除后维护与有效事件同步隐藏、成本重算；恢复同一记录后重新计入，见 S05 |
| AC14 | 两份保障重叠，一份未来生效，一份今日到期 | 分别展示；摘要不误报未来保障当前有效；有效截止日包含当天（S03） |
| AC15 | 更正保障结束日期，连续重启应用 | 原到期信息同步更正，无重复到期事件；生命周期不变，不依赖常驻进程 |

售出后允许补录持有期内的历史维护（S02）；不得因当前 Sold 就一律拒绝补全真实历史。晚于售出日的费用是否属于其他业务不在本轮自动扩展。

### F04 · 心愿与转换

新建 Ongoing；放弃进入 Abandoned 并保留历史；转换进入 Achieved。预计金额只用于心愿预计总额，不进入资产购入汇总。首版不默认增加放弃后重开、合并到现有资产等未约定动作。

| 编号 | 前提与动作 | 可观察的预期结果 |
|---|---|---|
| AC16 | 新建预计价 ¥1,500 的心愿，再放弃 | 资产数量和购入金额不变；进行中心愿预计总额中排除该项；原历史保留 |
| AC17 | 预计 ¥1,500，确认实付 ¥1,200 后转换 | 只创建一件资产；实付为 ¥1,200，原预计价仍为 ¥1,500；双方可追溯 |
| AC18 | 取消转换、转换中故障、连续触发转换 | 取消无变化；故障不留半转换；重复请求指向同一资产；成功前不显示已实现 |
| AC19 | 转换后软删除关联资产，再次打开心愿 | 仍为已实现，引导最近删除恢复；不生成第二件资产；恢复后引用仍有效 |

转换沿用名称、分类、封面；实际价格和日期可按 D05 留空，明确将导致哪些成本指标无法计算。购买与心愿实现可组合展示，不累计两次购买。

### F05 · 退役与重新启用

| 编号 | 前提与动作 | 可观察的预期结果 |
|---|---|---|
| AC20 | Active → Retired → Active | 每次记录有效动作；购买日期和维护费用不变；退役时仍计持有，重新启用不重置天数 |
| AC21 | 操作日期早于前一状态动作，或对 Sold 直接启用 | 阻止并说明适用动作；不静默改写历史或模拟真实购回（S01） |

Retired → Active 沿用核心流程；状态日期更正按已收敛的 S01 处理，不把重新启用等同于撤销真实历史。

### F06 · 售出、更正与撤销

| 编号 | 前提与动作 | 可观察的预期结果 |
|---|---|---|
| AC22 | 购入 ¥1,000，维护 ¥200，持有 10 天后以 ¥300 售出 | 当前持有排除它；净成本 ¥900、净日均 ¥90；次日持有天数仍是 10 |
| AC23 | 上例更正售价为 ¥1,400 | 同一出售事实，净成本 −¥200、净日均 −¥20；不截断为零 |
| AC24 | 从 Retired 误记售出后撤销 | 回到 Retired，清除有效结算并同步有效事件，天数重新到今天；保留内部纠错关联 |
| AC25 | 购入价未知，输入已知售价并售出 | 售出成立、持有数量变化；成本不完整，不显示精确净成本和净日均 |
| AC26 | 真实售出后重新买回同型号物品 | 新建另一 ID；旧 Sold 档案和处置事实不被覆盖 |

售出修改日期还需检查已知维护和前置状态日期；未知日期的记录不得被擅自填入一个看似合法的日期。清空已确认售出日期不是普通更正，需走撤销动作。

### F07 · 删除与恢复

| 编号 | 前提与动作 | 可观察的预期结果 |
|---|---|---|
| AC27 | 删除含维护、保障、图片、心愿关联的资产 | 进入最近删除；退出普通列表、资产事件和统计；文件不被永久清除、心愿关系不丢失 |
| AC28 | 恢复上例 | 同一 ID、原状态、原资料和关系恢复；不重复维护或事件；其他共享图片引用仍可读 |
| AC29 | 恢复 Sold，或遇到恢复失败 | Sold 不变为 Active；失败仍留在最近删除，可重试；首版无自动永久清空 |

统一最近删除入口在设置中可达，侧栏快捷入口可保留；支持全部/资产/维护/保障筛选。新增以下验收，不用独立的详情回收入口代替用户选择的统一管理：

| 编号 | 前提与动作 | 可观察的预期结果 |
|---|---|---|
| AC41 | 单独删除维护或保障，然后从统一最近删除恢复 | 同一记录 ID，费用/保障/有效时间轴同步；原附件可读，状态不变 |
| AC42 | 先删维护，再删父资产，再恢复父资产 | 父资产与此前有效关联记录恢复；此前独立删除的维护仍在最近删除，不被意外复活 |
| AC43 | 父资产仍删除时尝试单独恢复子记录 | 明示先恢复所属资产并提供定位入口；不悄悄连带恢复父资产 |
| AC44 | 删除父资产并查看最近删除，或重复恢复请求 | 父删除不为所有关联记录制造独立删除项；重复恢复幂等，无重复费用/事件或文件 |

删除关联心愿历史的显示应提示资产已删除，不默认把心愿退回进行中。维护/保障单条删除统一出现在最近删除（S05）；父资产已删除时先恢复父资产，不以资产恢复隐式复活早先被独立删除的记录。

### F08 · CSV、完整备份与恢复

| 编号 | 前提与动作 | 可观察的预期结果 |
|---|---|---|
| AC30 | CSV 导出与完整备份分别执行 | CSV 明示为资产表；完整备份包含关联记录、托管原图、最近删除及校验清单；目标位置可找到且成功前完成验证 |
| AC31 | 备份后在空数据目录恢复 | ID、状态、金额、心愿关系、维护保障和图片一致；最近删除仍可用；缩略图可重建 |
| AC32 | 损坏、不支持版本、缺附件或非法路径的备份 | 写入当前资料前拒绝，报告原因；当前数据不改变 |
| AC33 | 确认替换后遇到磁盘不足、拒绝访问或进程中断 | 原资料或恢复前保护副本保持可用；不能处于只能部分读取的半恢复状态；下一次启动可恢复到确定版本 |
| AC34 | 备份期间有编辑请求，或取消文件选择 | 同一备份中的数据库与文件为一致状态；取消选择不开始任务；明确等待/拒绝编辑策略由技术方案落实 |

首版完整替换恢复，不做合并恢复。恢复前保护当前数据失败则不得继续覆盖。完整性失败不提供“忽略错误继续覆盖”的普通快捷按钮。

CSV 已确认默认导出所有未删除资产（包括 Sold），明确范围；含稳定 ID、名称、分类、品牌、型号、购入价、币种、购入日期、渠道、状态、售出日期/售价、备注，空值留空而不是写零（S04）。含逗号、换行、引号和公式样式文字时，应安全、可还原地导出，具体兼容策略在技术设计中确定。

## 5. P0 配套页面与覆盖

| 编号 | 范围 | 可观察验收条件 | 原型现状 |
|---|---|---|---|
| AC35 | 总览与统计 | 当前持有含退役、不含售出；历史购入含售出；价格未知显示未计入数；日期未知从日期趋势中排除并说明；持有毛日均与售出净日均分开展示 | 原型仅有持有摘要，完整统计待制作 |
| AC36 | 持有周期与购买趋势 | 月/季/年/全部范围明确，期间按购入日期；持有区间、平均/中位/最长排除未知日期并标记；年/月边界定义见 S04 | 待制作 |
| AC37 | 分类/渠道 | 创建、改名后原 ID 引用有效；删除分类前迁移/未分类；心愿与资产均无悬空引用；分类支持排序和图标 | 待制作 |
| AC38 | 时间轴 | 按真实业务日期排列，建档与购入分开；只看有效事件；过滤购买/维护/生命周期/心愿；未知日期单列待补充（S02） | 只有单件摘要示意 |

## 6. 状态转换约束

| 动作 | 来源 | 结果 | 必须一起更新 |
|---|---|---|---|
| 新增 | 无 | Active | 资产、建档信息、已知日期购买事件、托管图片 |
| 退役 | Active | Retired | 状态历史、活跃数量；持有数量保持 |
| 重新启用（S01） | Retired | Active | 状态历史、活跃数量；购买与费用保持 |
| 售出 | Active / Retired | Sold | 售出前状态、有效结算、有效事件、持有统计 |
| 更正售出 | Sold | Sold | 同一出售事实的结算及有效日期 |
| 撤销误记售出 | Sold | 售出前状态 | 移除有效结算与售出事实、重新计算持有、保留内部纠错记录 |
| 删除 / 恢复 | 任意资产状态 | 删除标记变化 | 原生命周期保持；关联可见性与统计一起变化 |
| 心愿转换 | Ongoing | Achieved + 一个 Active 资产 | 双向关联、业务事件、文件引用 |
| 放弃心愿 | Ongoing | Abandoned | 原预计资料保留、退出进行中预计总额 |

并发或重试不能绕过来源状态校验。交易与文件如何协同是技术设计问题，但对用户必须只暴露一致的成功结果，或明确可恢复的失败结果。

## 7. 已收敛细节与边界样例

决策来源：用户本轮同意维护未知日期规则，选择资产/维护/保障“统一放进最近删除”，并同意状态日期、保障到期、未知排序和 CSV 范围建议。业务决定已登记产品设计 D10–D12。以下附加的工程可观察细节是这些规则的细化，不宣称用户逐字审批。

| 编号 | 收敛结果 | 细化边界 |
|---|---|---|
| S01 | 状态动作按时间顺序，冲突不自动改历史；保留重新启用流程 | 更正退役/启用日期只改变该动作日期，需在相邻有效动作区间内且不晚于今天；同日动作保留顺序。更正早期动作不得改变后续状态序列或隐式撤销售出。错误动作的完整撤销交互不混入普通日期更正 |
| S02 | 维护日期允许未知，费用仍参与成本；售出后可补录持有期间的历史维护 | 已知日期不晚于今天，且在已知购入/售出边界内；未知日期单列“日期待补充”，不混入虚构时间分组；补填不产生第二条维护 |
| S03 | 保障截止日包含当天、30 天内提示到期 | 多份分别展示；若存在超过 30 天的有效保障，摘要可显示保障中并另列近到期提示；只有未来保障为尚未生效；日期不完整显示待补全，不推断当前有效 |
| S04 | 未知值排序末尾，CSV 默认全部未删除资产 | 同值按稳定 ID；期间两端包含当天；持有周期以购入日起自然月/年纪念日分组，无对应日取月底；分组左闭右开，平均/中位基于天数。这些为详细设计规则，可在技术审阅中调整而不改变已确认口径 |
| S05 | 资产、维护、保障统一最近删除并提供恢复 | 保留独立删除标记；父资产删除只隐藏原本有效的子记录。父恢复不清除先前独立删除标记；父已删除时先恢复父。首版不自动永久清空 |

边界例都是验收定义，尚非应用测试结果。观察日未特别说明时为 2026-09-10：

| 例 | 输入/操作 | 预期 |
|---|---|---|
| E01 | 9 月 1 日购入 ¥1,000，维护日期未知、费用 ¥200 | 总投入 ¥1,200，持有 10 天，日均 ¥120；维护列在日期待补充，不按建档日伪造发生日期 |
| E02 | E01 再加一条费用未知的维护 | 成本不完整；删除未知费用记录后可恢复完整计算；恢复该记录又变为不完整 |
| E03 | 9 月 5 日已售出，9 月 10 日补录发生在 9 月 3 日的维护 | 允许；重算截至 9 月 5 日的成本；不能把实际补录日当维护日；9 月 6 日的已知维护日期则冲突 |
| E04 | 保障今日到期/10 月 10 日到期/10 月 11 日到期，且均已生效 | 分别剩余 0/30/31 天；前两条近到期，最后一条保障中；次日再刷新 |
| E05 | 一份未来生效，一份已到期，一份日期不完整 | 无可证实有效保障；分别保留尚未生效、到期、待补全信息，不显示已经覆盖 |
| E06 | 购入日 2024-02-29；观察日 2025-02-28 | 达到自然年纪念日，进入 1–2 年组；实际含首尾持有天数仍独立计算，不用 12×30 代替 |
| E07 | 购入日 2025-08-31；观察日 2026-02-28 | 满 6 个自然月，进入 6–12 个月组；月底规则不重写购入日期 |
| E08 | 价格为未知、0、100 的资产分别升降序 | 两种排序中未知都在末尾；0 是已知值参与排序 |
| E09 | 购入 ¥1,000，维护 A ¥200、维护 B ¥100；先删 A，再删并恢复资产 | 恢复后总投入 ¥1,100；再独立恢复 A 才变 ¥1,300，不重复新增事件 |
| E10 | 同日退役后启用，再将退役日期改到启用次日 | 阻止并展示冲突；同日原动作顺序保留，不自动交换动作 |

剩余技术事项：兼容系统、图片能力/上限、数据库与文件一致性、崩溃恢复、迁移、备份版本、字段长度/数值上限和性能基准，见 [技术设计提案](decisions/001-local-desktop.md)。它们仍需验证，业务确认不等于工程实测通过。

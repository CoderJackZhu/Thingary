## 3. T12 行为与非目标

- 侧栏启用独立「心愿清单」页，沿用 A「静序」布局与原 Demo 图标风格。支持新增和浏览 Ongoing 心愿、从 Ongoing 放弃为 Abandoned 并保留历史；进入进行中/已实现/已放弃筛选、Grid/List 切换及最近加入、优先级、预计价、目标日期排序。已实现分组在 T12 可为空；不能造假转换事实。列表、详情、加载/空白/错误/重试和浅深色均要完整。
- 名称必填；分类、预计价格、优先级、目标日期、链接、封面、备注可空。P0 固定 CNY；预计价用可空整数分存储，明确 ¥0 与未知不同，非负并作范围/溢出校验。目标日期允许未来，不默认今天；加入时间用真实建档时间，不代替目标日期。链接只作为外部链接字段，不因输入 URL 自动抓取网络数据。
- 优先级如需具体选项，使用高/中/低及未设置这组最小选项，并在报告注明这是 T12 的界面实现选择；自定义优先级和自定义排序属 P1。排序明确空值位置及稳定次序，筛选与搜索在同一权威查询中取交集。进行中预计总额仅累加**价格已知**的 Ongoing 心愿，展示未知数量；Abandoned 与 Achieved 不参与，且不改变资产数量、购入总额、维护费用或售出成本。
- 心愿只引用已有**分类 ID**。分类改名、图标/排序、删除迁移或转未分类时，所有 Ongoing/Abandoned 心愿的引用也必须保持或迁移，包含搜索/筛选/备份恢复；不留悬空引用。产品字段没有心愿购买渠道：渠道只在 T13 实际购入确认时适用，T12 不给心愿虚构渠道。

## 4. 持久化与恢复契约

- 在当前 schema 10 上顺序迁移，先用 `VACUUM INTO` 为隔离虚构库做一致性保护快照；禁止重置库、重导 Demo 或改写旧迁移。新增心愿表及封面关系时，旧 schema 1–10 恢复/迁移、备份 manifest/文件校验、失败回滚与旧库数据保留均需测试。
- 复用串行写 worker、generation、revision、request ID/内容指纹/回执和 `saved_request` 核对。同一请求同输入只产生一次心愿或状态变更；不同输入或旧 revision/generation 返回明确冲突。写入已提交但响应丢失时按原 request ID 核对，不能重新生成请求猜成功。分类引用迁移与回执同事务；存储忙/写锁失败后保持草稿和选图，可重试。
- 表单用现有原生 `<dialog>`、焦点/ESC/关闭保护和持久化草稿协议；恢复前校验 generation 与版本。取消不写业务记录。放弃操作保留原记录 ID、预计资料、封面与审计时间；重复放弃不能产生第二条历史。保存后从后端重读权威数据。
- 只使用已有隔离 App 标识 `local.possio.t06b.preview` 和虚构库。普通 `local.possio.preview` 库、真实档案、数据库/备份/凭据不入 Git。浏览器预览仅内存，不能证明原生持久性；原生工具不可用时诚实列为未验，不直接改库冒充 GUI。GUI 文件选择/删除若工具要求即时确认，按当时规则处理。

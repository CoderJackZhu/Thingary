## 4. 实施前已核对的约束

以下是既有规格的执行检查，不新增业务范围。

- **费用与完整性**：没有维护＝维护合计 0；金额明确 0＝已知免费；存在未知金额＝完整总投入、净成本和日均不可知。可以显示已知部分及未知笔数，但不得假装完整。日期未知而金额已知仍参与总投入；升级也是一条维护，不另加 `upgrade_cost`，不再累加时间轴金额。
- **单一计算口径**：总投入＝购入价＋有效维护费用；Sold 净成本再减售价，天数固定到售出日；Retired 仍到今天。整数分、溢出检查、自然日含首尾、负值及精确比值舍入沿用现有规则。已有 `src/sales.ts::settlement` 和 `src/asset.ts::costs` 只覆盖前期范围，不能仅在维护列表显示新金额、让详情/摘要/售出预览继续按旧式算。按 ADR 把已保存数据的权威成本与完整性集中在 Rust 领域/查询结果；表单预览如需另算，复用明确契约并用同一独立样例核对，禁止散落复制第三套公式。不借此重构整个工程。
- **日期双向约束**：维护日期可空，不默认今天、不用 created_at 冒充发生日；已知日期必须≤今天、≥已知购入日、≤有效售出日。维护不是状态动作，不要求晚于最近一次退役/启用；Sold 可以补录历史，未知日期依 S02 保留待补充。反过来，更正购入日、首次售出或更正售出日，也须检查已有有效维护日期并指出冲突，不悄悄搬动维护或重置状态。
- **身份与并发**：新增稳定维护 ID；更正保持 ID/created_at，不增第二笔费用。所有变更复用串行 Worker、generation、request_id/指纹/回执及版本校验；维护变更必须使依赖旧成本/日期的资产草稿失效，或以等效版本约束阻止旧草稿覆盖。重复请求不重演，响应丢失先核对，不能重新生成请求猜测成功。回执涉及新实体时审清 `saved_request` 的旧资产返回假设，不破坏资产/售出回执。

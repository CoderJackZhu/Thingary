# U19 · 售出保值率（统计页）开发方案与设计

日期：2026-10-01。状态：**方案草案，待用户审阅；未实现、未做视觉或原生验收。** 来源：用户对比「有数」的洞悉功能后，选择只做保值率（平均保值率、总盈亏、排行），目标进展总览与文字摘要不做。产品设计 6.1 节已把「售出保值率」列为 P1（售价 ÷ 购入价；购入价为零或未知时不计算），本方案是它的落地。

本文件同时承载业务规则、界面、技术与任务拆分，因为范围只有统计页一张卡。用户批准后，规则与验收迁入[产品设计](../PRODUCT_DESIGN.md)新决策条（预定 D29），进度登记到[实施计划](../IMPLEMENTATION_PLAN.md)；迁入前以本文件为准，迁入后本文件只保留界面与技术部分。

## 1. 范围

**做：** 统计页新增「售出保值率」卡：平均保值率、总盈亏、总回收率、按保值率排序的明细、未参与清单。顺带修正同页「回收分析」卡的回收率口径（第 3 节）。

**不做：** 新页面或侧栏入口；数据库迁移；按期间筛选；二手估值或对未售出物品估算保值；维护费计入保值率；目标进展总览；文字摘要；任何 AI。

## 2. 业务规则

| 项 | 规则 |
|---|---|
| 纳入对象 | 未删除、生命周期为已售出、存在未撤销售出记录、未设置「不计入统计」的物品。退役、使用中不参与 |
| 单件保值率 | 售出价 ÷ 购入价。只用购入价，不含维护费（维护后的真实成本见日均排行的净日均） |
| 单件差额 | 售出价 − 购入价，可为负 |
| 可计算条件 | 购入价已知且大于 0。售出价必填，为 ¥0 时保值率 0% |
| 不可计算 | 购入价未知 →「购入金额未知」；购入价为 ¥0 →「购入价为 ¥0，不计算」。列入折叠清单，不参与任何汇总 |
| 平均保值率 | 可计算物品的简单平均，每件同权 |
| 总回收率 | 可计算物品的总售出价 ÷ 总购入价（金额加权），作为平均保值率的补充，两个数都显示并写明口径 |
| 总盈亏 | 可计算物品的售出价合计 − 购入价合计，同一批物品，标明件数 |
| 保值率可超过 100% | 售价高于购入价正常显示，不封顶 |
| 排序 | 按未舍入的精确比值，默认从高到低，可切换；同值按 ID 稳定排序 |
| 范围 | 全部历史，不随页面其他筛选变化；「不计入统计」只看 `exclude.statistics`，不看 `exclude.daily` 与 `exclude.total` |
| 精度 | 金额整数分，IPC 用字符串；保值率为百分比的百分之一（`rate_hundredths`），四舍五入远离零；平均值先对精确比值求平均再舍入 |

`exclude.daily` 只影响日均排行，保值率与日均无关，因此不受它影响。

## 3. 现有「回收分析」卡的口径缺陷（需同批修正）

统计页现有「回收分析」卡的购入成本回收率，分子是期间内**所有**已售出物品的售价合计，分母却只含购入价已知的物品。购入价未知的物品卖出价进了分子、不在分母，卡片脚注声称这些物品「未纳入回收率」，与计算不符；购入价为 ¥0 的物品同理。位置：`src-tauri/src/insights.rs` 的 `stats_snapshot`（`sold_purchase` 与 `proceeds` 累加）。

虚构例：A 购入 10,000 售 6,500，B 购入 2,000 售 2,400，C 购入 800 售 0，D 购入未知售 1,000，E 购入 0 售 50。现卡显示 (6,500＋2,400＋0＋1,000＋50) ÷ (10,000＋2,000＋800＋0) = 9,950 ÷ 12,800 = **77.73%**；按本方案可计算集合 A、B、C 应为 8,900 ÷ 12,800 = **69.53%**。

处理：`stats_snapshot` 的 `sale_proceeds_cents` 只累加购入价已知且大于 0 的已售出物品，字段名与结构不变，脚注改为「购入价未知或为 ¥0 的 n 件未纳入」。新旧两卡在「全部」期间对同一批数据必须给出相同回收率，作为一条验收。该卡按购入日期期间筛选、新卡为全部历史，口径差异在卡片说明里写明，不合并。

## 4. 界面

位置：统计页现有「日均成本排行」卡之后，独立一张卡，不新增侧栏入口，不改页面分区；复用 U16 的 tokens、`ui-card`、`ui-metrics`、`ui-table`、`segmented` 与既有 SVG，不引入新依赖。

文字线框（布局契约，不作为已验证视觉稿）：

```text
售出保值率                                          ⓘ
[平均保值率 61.67%] [总回收率 69.53%] [总盈亏 −¥3,900]
3 件参与 · 总购入 ¥12,800 · 总售出 ¥8,900
[从高到低 | 从低到高]
#  物品    购入价     售出价    差额       保值率
1  耳机    ¥2,000    ¥2,400   +¥400     120.00%
2  相机    ¥10,000   ¥6,500   −¥3,500    65.00%
3  键盘    ¥800      ¥0       −¥800       0.00%
▸ 2 件未参与：手机 购入金额未知 · 赠品 购入价为 ¥0，不计算
```

- 指标行三格，说明文字在数值下方。ⓘ 写明：只用购入价与售出价，不含维护费；平均为每件同权、总回收率按金额加权；购入价未知或为 ¥0 的物品不参与。
- 差额沿用 `changeText`，负数使用同一负号与颜色语义，不只靠颜色（带 +/− 符号）。保值率沿用 `rateText` 的负号，但本卡保值率不为负，显示为无符号百分比，需要时在实现中另写 `percentText`，不改 `rateText` 既有行为。
- 物品名是可聚焦按钮，打开原档案，沿用日均排行的 `onOpenAsset`；长名称截断并保留完整可访问文本。
- 不加图表：保值率明细已是排行，表格足够；若后续需要，只加数字加小横条，不加饼图。
- 状态：加载中；读取失败（带重新读取）；没有已售出物品（「还没有售出记录」）；有已售出但全部不可计算（指标显示「—」，下方只有未参与清单，不出现空表格、不出现 0% 或除零）；正常；只有一件可计算（平均与总回收率相同，照常显示）。
- 读取失败只影响本卡，不阻塞页面其他卡。切换排序方向不重新请求。

## 5. 技术方案

**后端**（`src-tauri/src/insights.rs`，不新增文件、不迁移表）：新增 `Store::resale_rate(today)`，单条 SQL 取已售出物品与有效售出记录，避免逐件读取：

```text
assets a JOIN sales s ON s.asset_id=a.id AND s.revoked_at IS NULL
WHERE a.deleted_at IS NULL AND a.lifecycle_state='sold'
  AND NOT EXISTS(… json_extract(p.payload,'$.exclude.statistics')=1)
```

返回结构 `ResaleRate { generation, today, included_count, total_purchase_cents, total_sale_cents, total_gain_cents, average_rate_hundredths: Option<i64>, weighted_rate_hundredths: Option<i64>, rows: Vec<ResaleRow>, excluded: Vec<Excluded> }`；`ResaleRow { id, name, purchase_cents, sale_cents, gain_cents, rate_hundredths, sold_date }`。金额累加用 `i128` 再转字符串；排序用交叉相乘比较精确比值，与现有 `by_ratio` 同法；复用 `Excluded` 结构。`included_count == 0` 时两个比率为 `None`，不输出 0。

**命令**：`commands.rs` 新增 `resale_rate`，与 `holding` 同形（`w.call` 加本地日期）；`lib.rs` 注册。

**前端**（`src/Stats.tsx`）：新增 `ResaleCard`，由 `StatsPage` 在 `HoldingCards` 之后渲染；独立 `useEffect` 取数，沿用 `live` 标志防竞态和 `retry` 模式。类型就近声明，格式化复用 `money`、`changeText`。浏览器预览：`visual-preview.ts` 增加 `resale_rate` 分支，数据取自预览记录的 `sale.fields.price_cents` 与资产购入价，规则与 Rust 一致，供视觉取证。

**不改：** schema、备份格式、`holding` 命令与日均排行、物品详情、导航、权限与 capability 配置（新命令按现有命令同样注册即可，实现时核对 Tauri 命令权限是否需要显式登记）。

## 7. 验收与样例

统一虚构样例（今天 2026-09-10，金额单位元）：

| 物品 | 购入 | 售出 | 备注 | 期望 |
|---|---|---|---|---|
| A 相机 | 10,000 | 6,500 | | 纳入，65.00%，差额 −3,500 |
| B 耳机 | 2,000 | 2,400 | | 纳入，120.00%，差额 +400 |
| C 键盘 | 800 | 0 | | 纳入，0.00%，差额 −800 |
| D 手机 | 未知 | 1,000 | | 不参与，购入金额未知 |
| E 赠品 | 0 | 50 | | 不参与，购入价为 ¥0 |
| F | 1,000 | 900 | 不计入统计 | 不出现在任何位置 |
| G | 1,000 | 800 | 已删除 | 不出现 |
| H | 1,000 | 700 | 售出后已撤销 | 回到使用中，不出现 |
| I | 1,000 | — | 退役 | 不出现 |

基准：参与 3 件；平均保值率 (65＋120＋0) ÷ 3 = **61.67%**；总购入 12,800，总售出 8,900，总盈亏 **−3,900**，总回收率 8,900 ÷ 12,800 = **69.53%**；排序高到低 B、A、C，低到高 C、A、B。

| 编号 | 验收条件 |
|---|---|
| AC01 | 上述样例的汇总、排序与未参与清单与基准完全一致，F、G、H、I 不出现 |
| AC02 | 购入价未知与购入价为 ¥0 的物品只出现在未参与清单并注明原因，不进入任何汇总，无除零与 NaN |
| AC03 | 售出价为 ¥0 的物品保值率为 0.00%，计入参与件数与平均 |
| AC04 | 保值率超过 100% 照常显示，不封顶，差额带 + 号 |
| AC05 | 无已售出物品：空状态，指标不显示 0%；全部不可计算：指标「—」加未参与清单 |
| AC06 | 比率相同的两件按 ID 稳定排序；两个仅差一分的比值按精确值排序，不按舍入后的显示值 |
| AC07 | 更正售价、撤销售出、删除物品、设置或取消「不计入统计」后重新读取，卡片随之变化；`exclude.daily` 不影响本卡 |
| AC08 | 加载失败显示错误与重新读取，不影响页面其他卡；排序切换不重新请求；点击物品名打开原档案且不产生写入 |
| AC09 | 浅色与深色、1280×800 与窄窗下不重叠、不横向溢出；长名称截断；负差额不只靠颜色表达 |
| AC10 | 「回收分析」卡在期间「全部」下对样例显示 69.53%（旧口径为 77.73%），与新卡总回收率一致；脚注数量与未参与件数一致 |

## 8. 风险与待核对

- 「平均保值率」同时存在简单平均与金额加权两种读法，本方案两个都显示并写明口径；若用户只想要一个，保留平均保值率，总回收率移入 ⓘ。
- 已售出的虚拟资产（C 系列）是否可售出、是否应纳入：实现时核对 `sales.rs` 与虚拟资产规则，若虚拟资产不能售出则无影响，否则按物品同样处理并在验证报告记录。
- 「回收分析」口径修正会让现有显示的回收率下降（样例 77.73% → 69.53%），属于纠错，需在更新日志写明，不静默变动。
- 命令权限登记方式未在本次核对中确认（第 5 节末），列入 U19b 开工检查。

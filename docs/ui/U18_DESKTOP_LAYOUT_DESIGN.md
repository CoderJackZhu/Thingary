# U18 · 桌面布局修复与导航整理

产品范围与验收唯一见 [D24 / U18-AC01–12](../PRODUCT_DESIGN.md#u18-product)，任务状态唯一见[实施计划](../IMPLEMENTATION_PLAN.md#u18)。本文只维护界面结构、交互细节、异常行为与视觉取证要求，不另建业务规格。沿用 [U16](U16_DESIGN_SPEC.md) 的字体、间距、金额格式和三主题令牌；[U17](U17_TAG_INVESTMENT_DESIGN.md) 的入口、聚合口径与返回上下文继续有效。

## 1. 反馈、判断与调查边界

| 用户反馈 | 设计处理 | 实施前必须核对 |
|---|---|---|
| 心愿全部不在最左，详情的数字和快捷按钮竖长条 | 调整顺序；为窄详情采用独立布局规则 | 详情真实可用宽度、共享指标/按钮样式和换行约束 |
| 周期计划付款记录竖排，被下面区块覆盖 | 内容自然撑高，窄区使用完整记录行 | 溢出/高度/定位约束、详情与全页表格复用关系 |
| 分类右侧看不全、鼠标难以访问 | 完整快捷项＋更多分类菜单 | 各状态页是否共享筛选器、分类全集与可用状态 |
| 统计范围不明，低频入口占据侧栏 | 名称与归属调整，低频入口收进设置 | 导航注册、菜单、面包屑、返回栈和模块开关 |

以上是用户报告与设计应对，不是已确认的 CSS 根因。本轮不访问代码或运行界面，不指定未经核对的函数名、断点和修复行号。后续先用图工具定位并复现，再决定最小修改点；不以放宽窗口最小值、全局缩小字号或隐藏操作代替修复。

## 2. 心愿清单与详情

筛选顺序为「全部｜进行中｜已实现｜已放弃」，默认与记忆沿用现状。顺序和默认是两回事。

右侧详情以纵向信息组为基础：身份与封面 → 价格/攒钱信息 → 进度与快捷动作 → 日期等补充信息 → 当前状态可用操作。现有字段和操作不得因本次整理丢失，不凭草图添加新业务字段。

- 价格是完整的金额单元，例如 `¥2,850`，不得拆成 `¥2,` 与 `850`。标签可以独占一行；多列放不下就降为单列。还差等数值遵循原语义，不另造计算。
- 在约 300px 的检视器中，优先让「心愿价格」占一行；「已攒／还差」只有在实际文本完整容纳时并排，否则上下排列。不得机械套用主页面的四列指标。
- 快捷攒钱按钮保留已有金额与次序，每个按钮不可拆字；整组可以两行排列。输入与提交按钮也应完整，不能被相邻指标挤压。
- 长名称、日期说明、错误提示可以自然换行；加载、禁用和失败态不改变区块的基本宽度。金额不使用省略号、仅悬停可见或缩成小字来规避问题。
- 当详情与列表无法同时满足可读宽度时，沿用现有窄窗详情呈现方式，保证独立返回入口；具体切换宽度由实际容器测量确定，在实施记录中写明。
- 详情只有清楚的纵向阅读路径，底部操作不得覆盖末行。保存中防重复提交、失败反馈及未知回执核对保留。样例中禁止心愿实现的规则不变；转换回归使用独立虚构个人库。

## 3. 周期费用详情与付款记录

计划信息、计划操作、付款记录按正常文档流排列，各区块由内容撑高。滚动应能到达最后一条记录和其后操作，禁止通过固定高度裁掉记录或让浮动操作覆盖内容。

宽内容区可以保留现有表格；详情窄区使用紧凑记录行：首行安排日期和完整金额，次行安排状态/说明，操作在可容纳位置横排。字段以实际记录为准，不添加新支付状态。日期与金额不能逐字挤压；备注可换行。

- 空记录显示空态和现有可用动作；一条记录不应撑出大段空白，多条记录不与下一块交叠。
- 「计划／付款记录」两个页面视图均回归，包括从时间轴跳入付款记录、返回、确认后刷新以及局部失败重试。
- 若当前已有分页/加载更多，保持其语义；不能把修复变成一次加载全部历史记录。
- 不改到期计算、付款状态、汇总和关联权益，不因展开详情而确认付款。

## 4. 物品分类栏：鼠标优先

### 4.1 正常与溢出结构

```text
空间充足：全部分类  未分类  数码电子  衣饰配件  影音摄影  家电家居
发生溢出：全部分类  未分类  数码电子  [当前隐藏分类]  更多分类 ▾
极窄空间：[分类：影音摄影 ▾]
```

示例只说明排列机制，不修改现有分类名称、数量或顺序。「当前隐藏分类」实际显示被选中的名称，仅在原快捷序列未能显示它时占据一个位置。

1. 根据分类栏实际可用宽度排放完整按钮；先为「更多分类」预留空间，不能先放满再遮住最后一个。
2. 全部能容纳时不显示多余的更多按钮；溢出时固定在行末。无左右箭头，不依赖水平滚轮或触控板。
3. 「全部分类」「未分类」优先可见；选中尾部分类时，在更多按钮前保留其位置，必要时移出末尾普通快捷项。其他项保持既有相对顺序，不修改持久化排序，也不复制同一个分类按钮。
4. 连这些项也无法完整容纳时，整栏切换为单个分类选择按钮。超长分类名让按钮自适应换行，完整名称仍可读；菜单内名称也允许换行，不制造水平滚动。
5. 尺寸变化只重排呈现，筛选值、列表结果与当前分类 ID 不变。切换回来恢复按既定顺序计算的快捷项，不记录所谓常用分类。

### 4.2 菜单内容与状态

菜单展示**全部可筛选分类**，而非仅显示溢出的尾部；沿用现有列表的可选集合及顺序，不因为某分类当前结果为 0 就把它藏起来。

- 顶部固定分类搜索框；不新加计数、分组或管理操作。搜索按名称匹配、忽略首尾空白及英文大小写，无结果显示「没有匹配的分类」。
- 「全部分类」「未分类」作为两个固定快捷选项保留；搜索只筛选具体分类。前者清除分类限制，后者只看无分类物品。
- 菜单打开显示当前项勾选；点选后更新分类筛选、关闭菜单并回到触发按钮，列表分页重置沿用既有筛选行为，关键词、标签、排序和视图不被清空。
- 菜单内分类过多时纵向滚动，搜索框与两个固定选项保持可达；高度不超过窗口剩余空间，必要时向上展开。不能被列表/详情的裁切区域截断。
- 分类搜索与物品搜索独立；关闭后再次打开清空菜单搜索，当前分类保留。
- 分类读取失败不呈现为「没有分类」，显示错误与重试；切资料库先关闭菜单、丢弃搜索与旧库选项，再遵循原筛选重置规则。失效分类 ID 不按同名项替换，沿用现有失效筛选处理并保证可回到全部。

### 4.3 键盘与返回

触发按钮可 Tab 聚焦，Enter/Space 打开；菜单支持方向键导航、Enter 选择、Esc 关闭并还原焦点，点击外部关闭。搜索输入不吞掉正常文字输入。可访问名称含「分类」与当前选择，不只读出三角图标。

从列表进入物品详情、从标签进入 U17 分析再返回，保留原有分类 ID 与上下文；按返回时实际宽度重新排版，确保当前分类可见。分类菜单展开时，Esc 只关菜单，不直接退出详情或返回上一页面。

## 5. 导航、设置与外观

### 5.1 侧栏局部调整

```text
总览
物品
  原有全部资产与状态入口（次序和计数保留）
  心愿清单
  物品统计
财富
  既有入口（按现有模块开关）
────────
时间轴
设置
[太阳] [月亮] [半明半暗圆]
既有本地状态提示
```

不再显示「回顾」标题；U17 标签投入仍由列表标签筛选进入，不新增侧栏入口。物品统计无新增件数徽标。时间轴不变成设置的子页面。

短窗时侧栏主体可纵向滚动，底部区域预留实际高度，不能覆盖末个入口或本地提示。模块开关延续现有机制：若已有开关控制物品/统计，则迁移后仍遵守；不据此新造「物品模块开关」。时间轴保留现有领域开关行为，不借此删改历史事件规则。

### 5.2 设置中的低频入口与返回

- 「设置 › 外观」增加「素材库」入口行；「设置 › 资料与备份」增加「最近删除」入口行。复用现有分组，不新增一级设置分类。
- 点击进入原有完整页面；面包屑为「设置 › 素材库」或「设置 › 最近删除」，侧栏保持设置高亮。
- 鼠标返回按钮与面包屑可回到对应设置分组；恢复该组滚动位置及入口焦点。Esc 优先关闭菜单/确认框，再按页面返回规则处理。
- 删除后的「前往最近删除」、来源提示等已有快捷入口继续可用；从这些入口进入时，返回仍回实际来源，面包屑可另行回设置。不要为了入口迁移而破坏返回上下文。
- 素材选择器仍是表单内的选择器，不被替换为设置页面；最近删除的确认、恢复、清空及样例隔离规则不变。
- 页面标题、面包屑、导航选中、顶栏搜索与原生菜单上下文同步；仅当文字实际指向该页面时将「统计」改为「物品统计」，不全局替换业务术语。统计开关说明按实际适用范围核对，尤其不误称 U17 不受排除规则影响。

### 5.3 三态外观按钮

设置行下单独一行三个等宽图标按钮，顺序浅色、深色、跟随系统。复用现有 SVG 风格和控制圆角/边框/选中色；系统图标可用现有图标体系绘制半明半暗圆，不寻找旧样式作为实现依赖。

每个按钮有悬停说明、可访问名称、选中状态与键盘焦点；同一时刻仅一个偏好被选中。点击已选按钮保持该模式，不循环切换。系统模式的太阳/月亮外观变化不移动选中项。

B/C/D 仍在设置中选择，三态按钮只控制明暗；设置若保留模式选择，与侧栏同源双向更新。按现有持久化机制保存，不新建第二份偏好；原生重开和系统外观变化须实测。

## 6. 虚构场景与证据

### 6.1 场景准备

- 心愿：价格 2,850、已攒 850、还差 2,000；另加长名称、零/未知、大金额 `¥12,345,678.90`、目标日期缺失以及已实现/已放弃。金额仅在既有合法范围内构造，不为测试放宽校验。
- 周期费用：0、1、30 条付款；长名称、备注、确认与失败状态，以及详情下方仍有操作的场景。
- 分类：无自定义项、现有默认项、30 个虚构分类，包含长中文/英文名、无物品分类；测试首项、中间项和末项。样例仅用于测试，不改默认分类体系。
- 页面状态：正常、空白、读取中、读取失败、提交失败；样例与隔离个人库往返，U17 分析→档案→分析→列表。

### 6.2 尺寸、主题与证据组织

在 1280×820、1080×760、800×600 对照心愿详情、周期详情、溢出分类/展开菜单、侧栏和设置；B/C/D 各有浅/深。800×600 是沿用既有验收尺寸，实际最小可用窗口需在开工核对；不得宣称未运行的尺寸通过。

后续证据统一放在 `docs/ui/desktop-layout/`，按页面/状态/窗口/主题/明暗记录同尺寸前后截图和索引。文件名可采用 `wish-detail-800x600-B-light-before.png` / `...-after.png`。本轮不创建空证据目录或伪造截图。

系统模式另外记录偏好保持、系统明暗切换与重开结果。浏览器只证明布局交互，原生菜单、持久化与系统跟随须用隔离 App；正式库不得打开或写入。已实现/未实现、复现/未复现和通过/未测试分开记录。

# U16 · 与设计稿对齐：差距分析与计划（草案，待用户确认）

日期：2026-09-29 · 依据：Open Design 项目「家底 · 界面风格方向」规范 v2（`index.html`）与 2.0.0 实际界面，在 1280×820、同一虚构样例下逐页并排截图对照。

## 1. 结论

2.0.0（U15）只完成了**结构基础**：颜色变量集中、5 级字号、一行页头、若干页面的局部重排（筛选一行、单列表单、详情三个操作、设置五类、侧栏三组）。设计稿里真正决定观感的三件事**基本没有落地**：

1. **统一的容器形态**：设计稿每个区块都是同一种“卡片”，主题一换，卡片的边框、圆角、阴影、分隔方式一起变；应用里每页各用各的类（`overview-card`、`detail-section`、`review-card`、`stats-kpis`、`wealth` 的 `article`……），主题只能换颜色，换不了形态。
2. **主题的“形态”差异**：设计稿里 B/C/D 不只是配色不同，而是卡片形态、字体、侧栏样式都不同；应用里三套主题只换了颜色，因此 B 与 C 看起来几乎一样，D 也只是底色变灰。
3. **页面版式**：总览、详情等页的信息组织仍是旧版式加减法，与设计稿的构图差别很大（见第 3 节）。

之前把 U15 报为“全部完成”是按清单核对、没有与设计稿并排对照的结果，结论不成立；本文件取代那一结论。

## 2. 为什么会这样（根因）

- 旧界面约 117KB 分散样式，各页容器类不同；U15 在旧类上加覆盖规则，没有先建立**共用组件层**（卡片、指标行、行列表、区块标题、分段、胶囊、弹出菜单）。没有共用层，主题就无从改变形态。
- 主题变量只定义了颜色，没有定义**形态变量**（卡片底、边框、圆角、阴影、分隔线、数字字体、主数字字重、侧栏图标样式、主卡底色）。
- 阶段出口写的是“构建通过 + 浏览器核对”，没有写“与设计稿第 N 屏并排一致”，导致验收只看有没有改、不看像不像。

## 3. 逐页差距（B 清新原生，浅色）

| 页面 | 设计稿 | 2.0.0 现状 | 差距 |
|---|---|---|---|
| 框架·侧栏 | 品牌方块「底」；状态项右侧计数（8/6/2/1/1）；选中为浅灰胶囊＋蓝色图标 | 旧品牌图形；无计数；选中为浅蓝底蓝字 | 中 |
| 框架·金额 | 汇总数字取整（¥350,000） | 全部带 .00（¥350,000.00） | 大（观感噪音最大的一处） |

## 4. 三套主题要不要再拉开（B 与 C）

**建议：要。** 三套主题各自定义四个维度，只有“颜色”一项不足以让人感觉换了主题：

| 维度 | B 清新原生（默认） | C 纸本档案 | D 柔和卡片 |
|---|---|---|---|
| 容器 | 白底卡片，1px 细边，圆角 10，无阴影 | **没有卡片**：区块用 1.5px 墨色顶线分隔，内容贴边，靠留白分组；表格用细横线，像账簿 | 浅灰画布上的白卡片，圆角 16，柔和阴影；指标行拆成独立小卡 |
| 字体与数字 | 系统字体；数字中等字重 | 标题宋体、页标题 28；数字用衬线旧式数字、细字重 | 系统字体；主数字加粗放大（34） |
| 颜色 | 系统蓝为唯一强调色 | 暖纸底、赭红强调、墨色主按钮 | 靛紫强调、主卡淡色渐变 |
| 侧栏 | 浅灰半透明感，单色线性图标，选中浅灰胶囊 | 米色底、宋体品牌与分组名，选中为左侧赭红竖线＋加粗（不用胶囊） | 与画布同色，**彩色图标方块**，选中为白色浮起胶囊 |

深色版各自保留同样的形态，只换明暗。若之后觉得 C 维护成本高，可以只保留 B 与 D；但既然已承诺三套，建议按上表把 C 做出辨识度，否则 C 没有存在意义。

## 5. 需要用户确认的问题

1. **B 与 C 是否按第 4 节拉开**（建议：是）。
2. **金额显示**：整数金额是否去掉「.00」（如 ¥350,000），有角分时照常显示两位（建议：全局如此；只改显示，不改存储与计算）。
3. **总览的大趋势图**：是否改为嵌在净资产主卡里的小图，完整曲线只在「账户与盘点」页（建议：是）。
4. **侧栏计数**：物品各状态项右侧显示件数（建议：是；需确认现有查询能否直接给出计数，若要新增后端查询会单独说明）。
5. **总览页标题**用「家底」，侧栏入口仍叫「总览」（建议：是）。
6. **物品详情**去掉「返回列表」独立一行（面包屑与 Esc 已可返回），「关于这件物品」并入购买与投入卡片底部（建议：是）。

## 6. 实施计划（U16，每阶段出口 = 与设计稿对应屏并排一致）

| 阶段 | 内容 | 出口 |
|---|---|---|
| U16a 共用组件层 | 建立卡片、区块标题、指标行、行列表、胶囊、分段、弹出菜单的共用类；主题增加形态变量（容器、分隔、圆角、阴影、数字字体与字重、侧栏图标样式、主卡底色）；金额显示规则 | 规范页（设计稿「规范」屏）在 B/C/D × 浅深 6 种组合下与应用内同名组件一致 |
| U16b 框架 | 侧栏（品牌、计数、选中态、三主题侧栏形态）、顶栏、页头 | 设计稿任一屏的侧栏与顶栏在 6 种组合下一致 |
| U16c 总览 | 按设计稿重排：两张主卡（内嵌趋势与分类色条）、4 项辅助指标、待关注＋近期记录 | 设计稿「总览」屏 6 种组合一致 |
| U16d 物品 | 全部物品收尾、物品详情卡片化、心愿网格与检视器 | 设计稿「全部物品」「物品详情」「心愿」屏一致 |
| U16e 财富与回顾 | 账户、支出、周期、虚拟资产（检视器）、时间轴（类型色块与金额列）、统计、最近删除 | 设计稿对应各屏一致 |
| U16f 收尾 | 设置分类图标、全页 800×600、对比度、隔离原生验收（含 VoiceOver 抽查） | 并排截图集入库；原生验收记录 |

**验收方法（每阶段）**：设计稿与应用在同尺寸、同主题、同模式下各截一张，放进 `docs/ui/u16/<阶段>/`，逐项写明仍有的差异；差异为零或经用户同意保留，才算完成。设计稿里的临时插图不计入差异（应用使用现有插图库）。

## 7. 不做的事

- 不删功能、不改数据语义与 schema；设计稿中不存在的现有功能（如统计的回收分析、支出的日期待补提示）保留，按同一组件样式重排。
- 不引入新依赖；图表继续用现有 SVG。

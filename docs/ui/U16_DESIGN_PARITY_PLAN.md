# U16 · 与设计稿对齐：差距分析与计划

日期：2026-09-30 · 状态：**已复核收口，进入 2.1.0 自用发布**。用户本次授权继续 Claude 未完成的任务并先推送。

- 视觉参照：设计稿 v3（Open Design「家底 · 界面风格方向」`index.html`；仓库副本 [`docs/ui/u16/mockup-v3.html`](u16/mockup-v3.html)，用浏览器直接打开，顶部可切主题、模式与页面）。
- 开发依据：[U16 设计规范](U16_DESIGN_SPEC.md)（令牌、格式、组件、框架、逐页规范、主题检查表、不做清单）。
- 两者冲突以规范为准，并同步修正设计稿副本与 Open Design 项目。

## 1. 结论

2.0.0（U15）只完成了**结构基础**：颜色变量集中、5 级字号、一行页头、若干页面的局部重排（筛选一行、单列表单、详情三个操作、设置五类、侧栏三组）。决定观感的三件事基本没有落地：

1. **统一的容器形态**：设计稿每个区块都是同一种卡片，主题一换，卡片的边框、圆角、阴影、分隔一起变；应用里每页各用各的类（`overview-card`、`detail-section`、`review-card`、`stats-kpis`、`wealth` 的 `article`……），主题只能换颜色。
2. **主题的形态差异**：设计稿里 B/C/D 的卡片形态、字体、侧栏都不同；应用里三套只换颜色，B 与 C 几乎一样，D 也只是底色变灰。
3. **页面构图**：总览、详情、心愿、时间轴等仍是旧版式加减法。

之前把 U15 报为“全部完成”是按清单核对、没有与设计稿并排对照的结果，结论不成立。

## 2. 根因

- 旧界面约 117KB 分散样式，各页容器类不同；U15 在旧类上加覆盖规则，没有先建立**共用组件层**，所以主题无从改变形态。
- 主题只定义了颜色令牌，没有**形态令牌**。
- 阶段出口写的是“构建通过＋浏览器核对”，没有写“与设计稿第 N 屏并排一致”。

## 5. 分阶段计划

每阶段结束：`npm run build`、`npm run test:ui`、`npm run check`（涉及 Rust 时加 `npm test`）通过，**并**完成第 6 节的对照截图；截图差异为零或经用户同意保留才算完成。开发阶段单独提交；2026-09-30 用户已授权复核通过后合并 main、安装和归档。

### U16a · 共用组件层与令牌
- `src/theme.css`：按规范 2.1 增加形态令牌（三主题 × 浅深）；D 侧栏彩色方块颜色表。
- 新建 `src/ui.css`（在 `desktop-polish.css` 之后、`theme.css` 之前引入）：`ui-card`、`ui-section-head`、`ui-metrics`、`ui-hero`、`ui-rows`、`ui-table`、`ui-inspector`、`ui-filterbar`、`ui-popover`、按钮、状态与标签、`ui-empty`／骨架／失败（规范第 4 节）。组件只读令牌，不写死颜色与形态。
- 新建 `src/Sparkline.tsx`：规范 4.5 的小折线（悬停、键盘、`aria-live`），供总览使用；`WealthPage` 的完整曲线复用同一浮层逻辑。
- `FormControls.tsx` 的 `Info`：改为即时浮层（悬停与聚焦），不再依赖 `title`。
- 格式：`asset.ts` 的 `money()` 按规范第 3 节取整，新增 `unitMoney()`；`maintenance.ts` 复用；逐处把日均、每次改用 `unitMoney()`。
- 测试：更新引用「.00」的测试；新增 `money`／`unitMoney` 用例；对比度测试加入侧栏选中文字、链接在 `--selected` 上。
- 出口：设计稿「规范」屏与应用内同名组件（在浏览器预览中临时挂一个 `?state=components` 组件页，或逐页挑选实例）6 种组合一致。

### U16b · 框架

## 6. 对照截图（验收方法）

- 工具：设计稿副本 `docs/ui/u16/mockup-v3.html` 与浏览器预览 `visual-preview.html`，同为 1280×820；设计稿隐藏顶部工具条后，应用框架与设计稿框架像素尺寸一致。
- 范围：
  - 全部 15 屏 × B 浅色、B 深色；
  - 总览、全部资产、物品详情、时间轴、设置 5 屏 × C 浅、C 深、D 浅、D 深。
  - 合计 50 组。
- 存放：`docs/ui/u16/<阶段>/<屏>-<主题>-<模式>-{mockup,app}.png`。
- 每组写一行差异说明（放在该阶段的验证记录里）；允许的差异只有：真实插图替代示意插图、真实数据文本长度、规范第 9 节列出的“不做”内容。

## 7. 不做的事

- 不删功能、不改数据语义与 schema；设计稿中不存在的现有功能按同一组件样式保留。
- 不引入新依赖；图表继续用现有 SVG。
- 设计稿中数据给不出或超出已确认规则的内容，见规范第 9 节。

## 8. 接续须知（本地会话 → 云端会话）

- **分支**：`claude/u16-parity`（从 main 开出）。每完成一个可验证的小步就提交并推送；额度耗尽前务必提交推送。进度以实施计划 U16 表与本节“当前进度”为准。
- **Open Design**：只在本机可连（本机守护进程）。云端不需要它——设计稿 v3 完整副本在 `docs/ui/u16/mockup-v3.html`，规范与计划均在仓库。
- **云端能做**：前端代码、`npm run build`、`npm run test:ui`；有无头浏览器时可按第 6 节截图对照（设计稿副本用 `python3 -m http.server` 打开，隐藏顶部工具条）。
- **云端不能做**：Rust 编译与测试（链接 macOS 框架，只能在 Mac 上 `npm run check`／`npm test`）、原生 App 验收、安装。因此唯一的后端改动（`asset_counts`）在本地先完成；其余阶段只动前端。回到本机后补跑 `npm run check`、`npm test` 与原生验收。
- **发布边界**：不打开正式库；最初只授权开发分支，2026-09-30 用户追加授权复核通过后合并 main、安装与归档。截图只截窗口或页面，不截整屏。
